## 用户报告的 2 个 bug 修复（13:28，commit 8203f58）
### Bug 1：开局种植没有音效
- **先排除逻辑层**：注入 FakeAudioContext 验证 —— 种植确实创建并 start 了振荡器，说明代码路径没问题
- **根因在浏览器音频层**：AudioContext 刚创建时音频线程未就绪，**会话首个音效被整段吞掉**（之后的音效正常）
- **修复三件套**：①`primeAudio(c)` 上下文创建即播 1 帧静音 buffer 预热管线 ②`tone/noise` 的 t0 加 **8ms 前瞻**（避免排到"刚好此刻"被丢帧）③`armAudioUnlock()` 任意首次 pointerdown/keydown 兜底 resume（带 removeEventListener 存在性守卫，兼容 sandbox）

### Bug 2：大波预警横幅倒计时结束后残留约 2s
- **根因（我自己引入的）**：上次加清场门槛时，把「横幅显示」和「等待刷怪时机」混在同一个 `warn.active` 里 —— 清场慢时横幅被迫延长
- **修复**：拆出 `warn.pending`。`active` 只管横幅（倒计时归零**立即隐藏**）；`pending` 负责等清场（或 25s 兜底）后刷怪。三个分支改成 `if(pending) / else if(active) / else if(canAdvance)` 互斥
- 顺带：预警时长 3s→**2s**（用户要求），toast 同步用 `WARN_TOTAL`
- **教训：显示状态与业务等待状态必须分开建模**，否则任何"等待条件"都会变成 UI 残留
