## v2.4.1 消缺：商店三页签全空白（2026-10-01 晚，用户真机反馈，已修复提交 `74cc31f`）

### 根因（真机 agent-browser 复现坐实）
- `SHOP_GEOM.CARD` 定义键 `y:150`，消费侧（drawShopUpgrades/Consumables/Slots + onClickShop 四处）读 `G.CARD.y0` → undefined → NaN → fillRect/strokeRect 静默不画 → 商品区全空；onClickShop inY 恒 false 商品点击全废
- 修复：定义侧改 `y0`（与 x0 命名对齐），一刀

### 为什么无头门控漏放（重要教训）
- ctx 桩 Proxy 吞掉全部绘制调用，NaN 参数无断言可见
- REG-SHOP-01 §7 走函数直调（buyUpgrade 等）没走真渲染路径——逻辑层绿 ≠ 绘制层好
- **与「交付前自己走一遍真实点击链路」纪律同源：Canvas 游戏必须有真帧渲染断言**

### 防回归（已落地）
- harness ctx 桩新增 `__drawLog`（fillRect/strokeRect/fillText 参数日志，上限 5000）
- REG-SHOP-01 §9：CARD 键位完整性静态断言 + 三页签 `__renderRaw` 真帧渲染「数值参数全有限」+ 卡底 fillRect(240×170) ≥9 次计数
- 判别力自证：旧源复跑 §9 静态断言精确红（先红后绿闭环）
- ⚠️ drawLog 格式是 `[method,x,y,w,h]`——宽在 index 3、高在 index 4（首版断言按 c[4]/c[5] 过滤全空，虚惊）

### 真机验证方法沉淀（agent-browser）
- 每条 bash 命令独立守护进程可能丢页面（eval 报 null canvas / about:blank）→ **open + eval 必须同一命令链内 && 连发**
- 点击后同步 getImageData 读到的是旧帧（RAF 下一帧才画）→ 必须 `requestAnimationFrame(()=>requestAnimationFrame(...))` 双帧等待后再采样
- eval 内可用 Promise 包采样逻辑一次返回；agent-browser eval 支持 Promise 自动 await
