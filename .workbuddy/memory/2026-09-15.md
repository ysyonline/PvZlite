## PvZ Lite（植物大战僵尸）单文件游戏
- 文件：`plants-vs-zombies.html`（纯 HTML+Canvas，无依赖，双击可跑）
- 架构：9x5 网格，**6 种植物**（向日葵/豌豆/地瓜/坚果/双发/西瓜），4 种僵尸（普通/路障/快速/铁桶），3 档难度，**关卡制（第一关 + 第二关，通关第 N 关解锁 N+1）**
- 关键设计：
  - 实体四类 `plants/zombies/projectiles/effects`，统一在 `update(dt)` 中推进
  - **游戏时钟 `gt` 在 RAF 主循环 `loop()` 里累加，不在 `update()` 里** —— 做无头测试时必须自己补 `gt+=dt`，否则波次永不触发
  - 阳光是**可点击收集的实体**（effect.kind==='sun'），带 `targetY` 落地停住 8 秒
  - 僵尸生成走 `spawnQueue` 队列 + `processSpawnQueue` 逐个放出，不是整波瞬刷
  - 关卡配置 `LEVELS[n]`：`name/startSun/armTime/lawn/dusk/totalWaves/waves[{spawns:[[type,cnt]],interval}]`
    - L1 白天草坪：5 波 13 只，只有 normal+cone
    - L2 黄昏草坪：6 波 28 只，解锁 **fast**，多一层暖色 `dusk` 滤镜
  - 地瓜（=原版土豆雷）：`armT` 倒计时武装 → 武装后僵尸进格即 `explodeMine()`，500 伤害秒杀 + 自毁
  - 通关条件：`wave>=totalWaves && !waveActive && 队列空 && 场上无僵尸` → `state='end'; won=true`
  - **铲子**：卡片栏最左侧独立槽（`SHOVEL_X/SHOVEL_W`），卡片整体右移到 `CARD_X0`；`selected={shovel:true}`，点格子铲除并自退模式；X 键切换
  - **音效**：WebAudio 实时合成，无外部文件。`tone()` 单音 / `noise()` 噪声 / `gate(key,sec)` 节流防止密集事件糊成一团。AudioContext 在 `startGame()`（用户点击）时创建，符合自动播放策略
  - **大波预警**：波次配置加 `big:true` 即为大波；`checkWave` 检测到下一波是 big 且未预警过（`warn.last !== next`）时，先播 4 秒警报（`SFX.siren()`）再生成，期间不推进 `wave`。状态机 `warn={active,t,last}`
    - L1 第5波 big；L2 第4、6波 big
    - 预警横幅：全屏红色压暗 + 渐变横幅 + 闪烁大红字 + 英文副标题 + 倒计时进度条

### 稳定性加固（针对「玩的时候偶现退出当前」）
排查出 4 个真实隐患，全部修复：
1. **主循环无异常保护（最可能的元凶）**：`loop()` 里 `render()`/`update()` 任意一帧抛异常 → 末尾的 `requestAnimationFrame(loop)` 不再执行 → **游戏永久卡死**，表现就是"突然退出/画面不动"。修法：整帧 try/catch 吞掉异常 + 底部红条提示 + `console.error` 留痕，主循环继续跑。
2. **快捷键绑在 canvas 上**：点过 HTML 按钮后焦点跑到按钮，canvas 收不到 keydown → 快捷键全部失灵。修法：改绑 `window`，并对数字键/空格等 `preventDefault()`（顺带阻止 Space 触发聚焦按钮的默认点击）。
3. **HTML 按钮点击后保留焦点**：之后按 Space/Enter 会二次触发该按钮（若上一次点的是「重来」就会莫名回菜单）。修法：`bindBtn()` 统一包装，点击后 `el.blur()`；按钮补 `type="button"`。
4. **R 键/重来一键丢进度**：无任何确认。修法：新增 `requestExit(byWhat)` 二次确认（3 秒内再按一次才生效，`gt<1.5` 的刚开局不拦），配屏幕提示条 `toast()`。

新增基础设施：
- `setState(s, why)` —— 所有状态切换的唯一入口，控制台打印 `state a → b (原因) gt=x wave=y`，下次再偶现可直接看日志定位
- `toast(msg, sec)` / `drawToast()` —— 屏幕中上方临时提示条
- `drawFrameErr()` —— 帧异常红条

### 修过的 bug（有复用价值）
1. **植物扣血重复**：`updatePlant` 和 `updateZombies` 各写一份 → 合并到 `updateZombies`
2. **子弹缺 row**：溅射/命中判定靠 y 硬凑行号 → 发射时带上 `row`
3. **`plants.splice` 在 `for...of` 中** 导致迭代器错乱 → 改 `_dying` 标记 + 统一清理
4. **粒子被更新两次**（`update` 和 `updateParticles` 都跑）→ 合并
5. **阳光一路掉出屏幕** → 加 `targetY`，落到草坪指定 y 停住，停留 8s 后消失
6. **僵尸过快** → 速度全面下调对齐原版：普通 16 / 路障 15 / 快速 45 / 铁桶 12（px/s）
7. **僵尸节奏过密** → 逐个生成（首波 7s/只，每波 -0.6s，下限 1.5s），第 5 波起才允许并发 2-3 只，波间空档 14s
8. **卡片冷却永不递减（严重）**：`cardCD[type]=c.cd` 后**没有任何地方递减**，导致种过一次卡片永久变灰、无法再种。修法：在 `update()` 里加 `for(const c of CARDS) cardCD[c.type]=Math.max(0,cardCD[c.type]-dt)`
   - 注意区分：`p.cd` 是植物自身攻击冷却，`cardCD[type]` 是卡片栏冷却，两者独立
9. 向日葵种下瞬间吐阳光 → 初始 `sunT` 设为 7，等 7 秒再产第一颗
10. **改动 UI 布局必须同步改点击热区**：卡片栏右移后 `onClick` 里的 `cx=6+i*CARD_W` 要改成 `CARD_X0+i*CARD_W`，菜单按钮 y 坐标也要跟着 `drawMenu` 一起改，否则点不中

### 无头测试方法（已验证可复用，26 断言全绿）
用 Node + `vm` 跑单文件 Canvas 游戏逻辑，无需浏览器：
```js
// 1) 抽 <script> 内容
const m=html.match(/<script>([\s\S]*?)<\/script>/); fs.writeFileSync('_check.js',m[1]);
// 2) 造 stub：ctx 用 Proxy 吞掉所有绘制调用，create* 返回 {addColorStop:noop}
const ctxStub=new Proxy({},{get:(t,k)=>k in t?t[k]:function(){return String(k).startsWith('create')?{addColorStop:()=>{}}:undefined},set:(t,k,v)=>{t[k]=v;return true}});
const listeners={};
const canvasStub={width,height,getContext:()=>ctxStub,addEventListener:(k,f)=>listeners[k]=f,focus(){},getBoundingClientRect:()=>({left:0,top:0,width,height})};
// 3) sandbox 要显式挂上外部变量（btns/listeners/noop 等），否则追加代码里引用不到
sandbox.globalThis=sandbox; sandbox.listeners=listeners; sandbox.btns=btns;
// 4) 追加探针到脚本尾部（顶层 let/const 不挂 global，必须在同一作用域追加）
code += `globalThis.__probe=()=>({state,wave,sun,...});
         globalThis.__api={startGame,tick(dt){gt+=dt;update(dt)},click(x,y){listeners.click({clientX:x,clientY:y})},...};`;
vm.runInContext(code,sandbox);
```
要点/坑：
- **必须自己补 `gt+=dt`**（游戏时钟在主循环里），否则波次永不触发，测试假通过/假失败
- `window` 在 sandbox 里未定义 → `ac()` 内 `new (window.AudioContext||…)` 抛 ReferenceError 但被 try/catch 吞掉 → 音频静默降级，正好可用；想测静音逻辑就挂个空的 `window:{}`
- 想统计真实刷怪数：**包装函数声明**（函数声明绑定可变）`const _o=processSpawnQueue; processSpawnQueue=function(dt){const b=spawnQueue.length;_o(dt);globalThis.__spawned+=b-spawnQueue.length}`
- 模拟点击/按键直接调 `listeners.click/keydown({...})`，比构造 DOM 事件省事
- 别用「每帧采样 queue 内容」来统计僵尸数——同一只僵尸每帧都被数到，数字虚高几十倍
- **测主循环要小心**：脚本末尾已有一次 `requestAnimationFrame(loop)`，把 rafQueue 清空会让后续 `step()` 无帧可跑、全部假失败；正确做法是先 `step()` 消费掉已注册的那帧
- **测异常隔离**：往 `zombies` 里 push `null` 即可让 `update()` 天然抛 TypeError，比侵入式打桩简单
