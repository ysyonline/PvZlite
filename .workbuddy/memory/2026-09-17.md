### §C 关键设计决策：不用 setInterval，改帧驱动
- 暂停时 `update` 不执行 → 警报**天然同步暂停**（规格要求的"暂停要停 loop"零额外代码）
- 横幅结束当帧 `SirenLoop.stop()` → 与 `SFX.bigWaveImpact` 收束衔接，无定时器拖尾
- 2s 窗口 ≈ 4 轮（原一次性三连 1.32s 后留 0.68s 空白）
- 200ms 淡出改为「每轮自带指数衰减 + 收束音衔接」，不单独做总线增益斜坡（避免波及其它 event 音效）
- 附带收益：vm 沙箱的 `window.setInterval` 是空 stub，用定时器实现的逻辑**无头测不了**；帧驱动可测

### ★ 排障：git push 挂死 → 根因是 `helper-selector`
**症状**：`git push` 零输出挂到超时；`git credential fill` 也挂；但 `git ls-remote` 正常（2.8s）。

**排查路径**（这个分步隔离法值得复用）：
1. `git ls-remote origin` → 通 ⇒ 网络/URL 都没问题，问题在**写鉴权**环节
2. `git -c credential.helper= credential fill` → 0.5s 秒回错 ⇒ git 本体正常
3. `git -c credential.helper='!"…/git-credential-manager.exe"' credential fill` → **14.8s 拿到凭据** ⇒ **GCM 本身好的**

⇒ 定位到**系统级配置 `credential.helper = helper-selector`**（PortableGit 自带 `git-credential-helper-selector.exe`）。无交互终端时它会去弹**图形选择框**，永远等不到用户点击 → 永久挂起。它是列表里第一个 helper，所以先于 GCM 执行并卡死。

**解法**：命令行覆盖 helper 列表（`credential.helper=` 空值会**清空**列表）：
```bash
git -c credential.helper= \
    -c credential.helper='!"C:/Users/user3667/.workbuddy/binaries/PortableGit/versions/1.2.0/mingw64/bin/git-credential-manager.exe"' \
    push -u origin main
```
**没有动全局/系统配置**（那是用户的既有设置，只做单次覆盖）。

**顺带清掉的干扰项**：`PortableGit/versions/1.2.0/etc/gitconfig.lock`（0 字节陈旧锁，13:25 由首次取凭据时留下，无进程持有）。已删除——**但它不是根因**，删完照样挂。

**其他确认**：GitHub 凭据此前已存在（GCM 里 `username=ysyonline`），无需重新授权；直连与 7890 代理**两条通道都通**，本次推送没配任何代理。

- **「并行编辑同一文件」是本会话最大坑**：6 组并行 Edit 静默丢了 6 处改动，每个调用却都报 "Successfully edited"。**grep 核对落点只信 grep，不信成功提示**
- **`git add` 带不存在的 pathspec 会整体失败**，且 `2>/dev/null` 会吞掉报错 → 提交信息与内容不符。**提交后必看 `git show --stat`**
- **凭据 helper 挂死要看"哪个 helper 在跑"**：分步隔离（`ls-remote` → 无 helper → 只挂 GCM）三步就能定位，别一上来怀疑网络
- **搜索结果/摘要里的数字不可信**：源码行数、用例数、关卡数值一律自己复算（本次 3 处摘要数字与源码不符）
- **成员/工具自述 ≠ 事实**：本会话两次靠"独立回读"抓到问题（远端 ref 回读、`git show --stat`）
- **调度专家团成员必须先 `TeamCreate`**，否则 Agent 报 `No active team found`
