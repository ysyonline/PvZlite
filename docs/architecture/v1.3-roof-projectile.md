## §1 现状精确梳理（抛物线要动的那块现状）

### 1.1 `updateProjectiles`（L1010–L1036）逐行现状

```js
function updateProjectiles(dt){
  for(let i=projectiles.length-1;i>=0;i--){        // 倒序遍历，允许 splice 语义
    const pr=projectiles[i];
    pr.x+=pr.vx*dt;                                 // ① 唯一位移：水平匀速直线
    if(pr.x>canvas.width+40){pr.dead=true;continue} // ② 越右界 → dead
    for(const z of zombies){                        // ③ 命中遍历：同排逐僵尸
      if(z.dead||z.row!==pr.row)continue;
      const zy=GRID_Y+z.row*CELL_H+CELL_H/2;        // ④ 目标行 y 基线（per-row 常数，随行号唯一）
      if(Math.abs(zy-pr.y)<32&&Math.abs(z.x-pr.x)<42){ // ⑤ 双窗口命中：V 纵向 ±32 / H 横向 ±42
        z.hp-=pr.dmg; SFX.hit();
        if(pr.splash>0){ /* melon 溅射 */ }
        else{ spawnBurst(pr.x,zy,'#aef06a',6); }
        if(z.hp<=0&&!z.dead)killZombie(z);
        pr.dead=true;break;
      }
    }
  }
  projectiles=projectiles.filter(p=>!p.dead);      // ⑥ 过滤清理
}
```

**关键现状语义**：

- **位移只有水平**：`pr.y` 从对象创建那一刻起**从不改变**（直线弹）。命中纵向窗口 `|zy-pr.y|<32` 在发射时即已满足（发射 `y=pos.y-8`，`zy ~ pos.y`），故直线弹的命中判定**实际仅由横向窗口** `|z.x-pr.x|<42` 主导。
- **`zy` 来源**：`zy=GRID_Y+z.row*CELL_H+CELL_H/2`——纯由 `pr.row` 决定的行中心 y，**per-row 固定常数**，与僵尸实际 x 无关。这是抛物的**天然盟友**：抛物线只要在行基线附近下落，就能复用 ④⑤ 的既有两个窗口逻辑，**无须新引入行判定**。
- **两字段语义**：`vx`（水平速度 px/s）、`dmg`、`row`（行归属）、`type`（pea/melon）、`splash`（>0 为溅射半径）、`dead`。**无 `vy`/`g` 字段**——直线弹对象字面量（L941–L946）从不传这两个键。
- **发射点 y 偏移（类型差异）**：

| 类型 | 行号 | 发射对象字段 | 发射 y |
|---|---|---|---|
| pea（单发） | L946 | `{x,y:pos.y-8,vx:340,dmg,row,type:'pea',splash:0,dead}` | `pos.y-8` |
| double（双发） | L941/L942 | `type:'pea'` ×2，y 分别 `-14`/`-4` | `pos.y-14`/`pos.y-4` |
| melon | L944 | `{x,y:pos.y-16,vx:220,dmg,row,type:'melon',splash:55,dead}` | `pos.y-16` |

**结论**：直线弹全部**水平匀速**（vx 恒定）、**垂向静止**（y 恒定），命中窗口天然横向主导。抛物线要做的，只是给 y 加一个随时间变化（带重力）的量，**其余命中/溅射/清理逻辑全部复用**。

> **现状 bug 免责**：L1013 `pr.x+=pr.vx*dt` 是无条件水平位移 + L1014 越右界。若按 GDD §3.4 给 cabbage 也走同一条 L1013 路径，那么 cabbage 也水平匀速前移——**符合**；但需在 L1013 之后、L1015 命中遍历之前插入 cabbage 的重力更新（§2.1）。L1014 的越界判定对 cabbage **部分成立**（抛过头没目标会到 canvas 右界外 → dead，可复用），但 GDD §3.4 还要求「y 过深下落→dead」的越界，需补一行（§2.1）。

### 1.2 导弹对象在 `updatePlant` 攻击分支（L936–L950）现状

`p.type==='pea'||p.type==='double'||p.type==='melon'` 共享同一分支（L936），内部按类型给 `cd` / `dmg` / 发射对象。**cabbage 要在 L936 的 else-if 链上新增一个独立分支**（§4.1），不复用该分支——因为 cabbage 的发射点（`pos.y`，非 `pos.y-8`）与对象字段（含 vy/g）与直线弹不同，硬塞进同一分支会污染类型差异判断（文策渊 §3.2 已定 dmg=30 / cd=2.0 / vx=260 / 纯单目标无溅射）。

## §2 抛物最小改动方案（核心）

### 2.1 弹道对象字段 + `updateProjectiles` 的精确改法

**新增弹道对象（在 `updatePlant` 新增 cabbage 分支里 push，§4.1）**——相对直线弹**新增 `vy`、`g`、`type:'cabbage'`**，不碰任何现有字段：

```js
// 发射（updatePlant 内 cabbage 分支）——抛向同行最远/首个有僵尸的 x（hasZombieAhead 只给 bool，需另取目标 x，见 §2.3）
const target = firstZombieX(p);                 // 同行首个 z.x > pos.x-10 的僵尸 x（新增小函数）
const d = Math.max(50, target - (pos.x));       // 到目标距离（下限 50 防除零/极近）
const t = d / CABBAGE_VX;                       // CABBAGE_VX=260
// ★ 预测提前量修正（§2.3 核心）：用僵尸飞行后的预测位置重算,保证命中移动目标
const leadX = target - zombieLeadSpd(p.row) * t;  // 减掉弹道时间内该行僵尸移动量
const d2 = Math.max(50, leadX - pos.x);           // 修正后距离
const t2 = d2 / CABBAGE_VX;
const vy0 = (zy - pos.y - 0.5*CABBAGE_G*t2*t2) / t2;   // CABBAGE_G=500；zy = 本行基线（同发射 y，故≈0 差）
projectiles.push({ x:pos.x+30, y:pos.y, vx:CABBAGE_VX, vy:vy0, g:CABBAGE_G, dmg:30, row:p.row, type:'cabbage', splash:0, dead:false });
```

**`updateProjectiles` 的精确改动（只在 L1013 之后、L1015 命中遍历前插 2–3 行 + L1014 越界处 1 行）**：

```js
function updateProjectiles(dt){
  for(let i=projectiles.length-1;i>=0;i--){
    const pr=projectiles[i];
    pr.x+=pr.vx*dt;
    // ---- v1.3 新增：仅 cabbage 生效的重力分支（直线弹永不进入，vy/g 未定义）----
    if(pr.type==='cabbage'){ pr.vy+=pr.g*dt; pr.y+=pr.vy*dt; }   // ⚠️ 必须 boolean 前置于位移，勿无条件
    if(pr.x>canvas.width+40 || (pr.type==='cabbage'&&pr.y>canvas.height+40)){pr.dead=true;continue}  // 越界：右界(既有)+下坠(新增)
    for(const z of zombies){
      if(z.dead||z.row!==pr.row)continue;
      const zy=GRID_Y+z.row*CELL_H+CELL_H/2;   // 复用既有
      // ---- 命中窗口：cabbage 走既有五代双窗口（§1.1 已证 zy 随行定、天然可用），仅需横向窗口在"下落段"成立 ----
      if(Math.abs(zy-pr.y)<32&&Math.abs(z.x-pr.x)<42){
        z.hp-=pr.dmg; SFX.hit();
        if(pr.splash>0){ /* melon 溅射（cabbage splash=0 不会进）*/ }
        else{ spawnBurst(pr.x,zy,'#aef06a',6); }
        if(z.hp<=0&&!z.dead)killZombie(z);
        pr.dead=true;break;
      }
    }
  }
  projectiles=projectiles.filter(p=>!p.dead);
}
```

**改动量**：核心弹道体 **+3 行**（重力分支 1 + 越界条件 1 + 注释）将命中遍历**零改动**复用。

### 2.2 「直线弹路径零改动」如何保证——精确判断条件

| # | 断言 | 为什么成立 |
|---|---|---|
| A | 位移 `pr.x+=pr.vx*dt` 对直线弹逐帧值**不变** | 直线弹对象字面量（L941–L946）**不传 vy/g**；新增分支 `if(pr.type==='cabbage')` 对 pea/double/melon 恒为 false，y 依旧从不在 update 中变化 |
| B | 命中双窗口对直线弹逐帧**不变** | ⑤ 横竖两句完全未改 |
| C | 越界对直线弹**不变** | L1014 原条件 `pr.x>canvas.width+40` 保留；新增 `||(type cabbage && y>...)` 对直线弹为 false（cabbage 分支短路，且直线弹无 type cabbage），整体表达式对直线弹等价于原式 |
| D | 清理 `filter(!dead)` **不变** | 未触碰 |
| E | 对象字段无侵入 | 直线弹对象没加任何键 → `probe().projectilesArr` 快照（`{type,x,y,row,vx,dmg,splash,dead}`）对直线弹零差异 |

**唯一不可破坏的硬约束**：重力分支**绝不可写成无条件** `pr.y+=pr.vy*dt`（会把 undefined 变 NaN，让直线弹 y 全崩）。**必须** `if(pr.type==='cabbage')` 前置。这是保老 REG 的第一生命线，实现时在 PR 评审点死盯这一行。

### 2.3 命中判定算法 + 「按距离解算 vy0」的预测修正（★ CONCERN 必须回传）

文策渊 §3.4 原式：`vy0 = (zy - spawnY - 0.5*g*t²)/t`，`t=d/vx`，`d = |target.x - spawnX|`（**target.x 取发射瞬间的当前 x**）。数学上：弹丸经对称弧在 `x=target.x` 处回到 `y=zy`——**对"静止目标"精确命中**。

**为什么对移动僵尸必 miss（量化复算）**：

`CELL_W=90`，投手抛到第 8 列 ≈ `d=8×90=720`，`t=720/260≈2.77s`。弹道飞行期间僵尸左移量：

| 僵尸类型 | spd (px/s) | 飞行 2.77s 左移 | 命中窗横向 ±42 |
|---|---|---|---|
| normal | 16 | **44.3 px** | ❌ 超出（壳落在僵尸右侧 44px，miss） |
| fast | 45 | **124.6 px** | ❌ 严重超出 |
| cone | 15 | 41.6 px | 临界（贴线） |

即：**按固 pos.x 解算，抛物线只会命中"飞行中静止"的僵尸**（啃食中的 target 确实静止，`updateZombies` L1059 在 eating 时 `z.x-=0`）。对移动僵尸，炮火全部落空在其身后，**投手几乎无用**——直接违背支柱 1「抛物是答案，不是玩具」（文策渊 E6 虽接受"移动没命中→落点处 dead"，但那会让投手形同虚设，本文判定为规格需修正）。

**推荐修正（小 delta，不推翻结构）**：把 `d` 从「当前 x」改为「**预测提前量**」——`target` 取僵尸飞抵时间内的预测位置。解算闭环（一次迭代够）：

```
t0 = d0/vx                    // 初值：d0=|target.x - spawn.x|
lead = target.x - spd_row * t0   // 该行僵尸速度 spd_row（同一行所有非 eating 僵尸同速；eating=0 自动命中）
d  = max(50, lead - spawn.x)     // 修正距离
t  = d/vx
vy0 = (zy - spawn.y - 0.5*g*t*t)/t
```

- `spd_row` = 该行首个目标僵尸的 `z.spd`（若目标僵尸 `eating` 则 spd 视为 0，本就静止，直接命中）。
- **代价**：多读一次同名行僵尸的 spd + 一次乘法。对 5 行 × 数弹规模**纯运算开销可忽略**（每发射一次算一次，非每帧）。
- **不回传不采纳的话，行 dmg 数字（30/2.0s）是废的**——因为打不中移动目标，dps 名义 15 实际趋近 0。此点已列入 §6 回传策划项。

> 注：文策渊 §3.4 也提到"命中窗口 Δ 可放宽到 ~50"。但放宽横向窗口不能救——横向 miss 是 44–125px，放 50 只够 normal 临界、fast 仍 miss，且放太大会让直线弹语义被污染（若改共用窗口）。**故修预测提前量是根治，放宽窗口只是兜底**。

**越界与 E6（GDD §6.2 E6）**：`pr.y>canvas.height+40` 让未命中的壳在画布下方消散还原弹道；`pr.x>canvas.width+40`（既有）兜住抛向已无目标方向的过深弧线。两条件对 cabbage 均成立即 dead，不下穿误伤他行（命中遍历已按 `pr.row` 过滤，天然隔离）。

### 2.4 发射如何知道目标几格远（row + x 即可，无须格子数）

投手发射**不需要知道目标在第几格**，它需要**目标的行 + 当前 x 坐标**：

- **row**（决定目标行 y 基线 `zy`）——投手自身 `p.row` 即目标同行（`hasZombieAhead` 保证同行有敌），零额外获取。
- **目标 x**——新增小函数 `firstZombieX(p)`（≈ `hasZombieAhead` 的变体，返回首个 `z.row===p.row && z.x>pos.x-10` 的 `z.x`）。发射时算 `d = |z.x - spawn.x|`。
- **不需要「格子数」**：距离 = 由 `current x → grid x` 的像素差直接推，不经过 `posToGrid`。文策渊"row 决定目标行 y + 距离由 current x→grid x 差推"的假设**成立且天然满足**。
