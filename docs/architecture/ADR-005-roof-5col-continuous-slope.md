## 上下文（Context）

### 现状（v1.2.1 / v1.3-M3 已落地部分）

1. **坐标映射是二维平面**：`gridToPos(col,row)` / `posToGrid(x,y)`（L232–233）为**纯仿射、无列/行偏移**的矩形网格映射。它是**全代码仅有的两处**把 `(col,row)↔(x,y)` 互换的函数，`posToGrid` 仅供点击/预览使用。
2. **L5 屋顶「斜」是纯纹理**：v1.3-M3 用 `ROOF_SLOPE=0.18` 的**旋转带 + 剪切竖缝**在**绘制层**伪造倾斜（L1430–1478），**几何层未动** ⇒ 格子仍是轴对齐矩形、僵尸仍按平面行走 ⇒ 「看起来还是平」/台阶感/顶面读感不足。
3. **M3 施工规格立了一条红线**：`production/v13-m3-visual-impl-spec.md` §2.1①「**gridToPos 平面假设不动**」，§11-C12「屋顶 C 档真透视 = **否决**」——理由是 GDD 拍板项④ / `roof-process §2.4` 认为「破坏 `gridToPos` 平面假设 → 波及全链路 → 估 400+ 行」。
4. **用户诉求升级**：用户在 B（阶梯）/C（平滑）效果草图间评审后，明确诉求**连续坡面的观感（C 档）**，并进一步钉定 **斜坡扩到左 5 列（col0–4）+ 抬升总量 H=60px**。

### 问题

「真实斜屋面」与「`gridToPos` 平面假设」二者不可兼得：**要么** 保留平面假设（只能做纹理级倾斜，达不到观感天花板，见 M3 现状）；**要么** 破除平面假设（几何层真斜切）。需要一次 **显式架构决策**记录这次取向翻转，并**重新给出实测成本/风险**，替代此前「400+ 行」的历史估算。

### 约束与实测事实（本 ADR 的依据）

- **引擎/技术栈不变**：原生 Canvas 2D + WebAudio 单文件零构建（ADR-001/003）。
- **`level.roof` gate 是既有隔离惯例**（L716/717、L1370、L1431、L1501、L1520）⇒ 破平面假设可**收口在 roof 分支内**，L1–L4 结构性免疫。
- **实测成本**：C2 核心 **≈ +40~65 行**（见施工规格 §5），**远低于 400+**（约 1/6~1/10）。历史「400+」成立于「真透视 C 档整包（逐行偏移 + 真弹道高度物理 + 全链路重写 + 大量 REG 断言平移）」，**不成立于本 C2 切片**。
- **实测回归**：`probe()` 快照**不含任何 y**（`tests/harness/index.js`）⇒ **无用例能断言实体 y**；`gridToPos↔posToGrid` **闭式互逆** ⇒ `REG-ROOF-01 clickGrid(2,2)` 仍精确落格；L1–L4 恒 0 ⇒ 逐字节等价。**回归零漂移**（详见评估 §C.5 / 施工规格 §4）。
- **唯一 BLOCKING 风险**：`gridToPos` 抬升后，**弹道命中基线（L1073）不随之抬升** ⇒ L5 平台列直线弹纵向偏差 ≥68px > 命中窗 32px ⇒ **全体 miss**（60px ≫ 32px）且**无测试捕获**（须显式修 L1073/L991/L1024，施工规格 §2.C/§3）。

## 决策（Decision）

**采纳 C2（几何连续平滑坡面）**：在 `level.roof` 门控下，**破除 `gridToPos` 的平面假设**，令其 y 成为 **x 的连续函数**，由此得到真·斜屋面的几何（平行四边形格）+ 连续实体行走 + 落格自洽。

### 关键决策点

1. **映射层（唯一核心）**：`gridToPos` 的 y 改为 `GRID_Y+row*CELL_H+CELL_H/2 − liftX(x)`；`posToGrid` 以 `col=⌊(x−GRID_X)/CELL_W⌋` 先定列、再 `row=⌊(y−GRID_Y+liftX(x))/CELL_H⌋` 闭式反解。**两函数共用同一 `liftX`**（互逆的充要条件）。
2. **抬升函数**：`liftX(x)=ROOF_LIFT_H·clamp((x−GRID_X)/(ROOF_COLS·CELL_W),0,1)`，`ROOF_COLS=5`、`ROOF_LIFT_H=60`；`liftX` 内 `if(!level.roof)return 0` ——**单点 gate**。
3. **实体 y 连续**：`drawZombie`（L1816）等实体 y 一律 `− liftX(z.x)`（连续，非阶梯）——这是 C2 与 C1′（阶梯）的唯一实质差别（≈2 行）。
4. **弹道基线同步抬升（强制）**：命中基线（L1073）+ cabbage 瞄准（L991）+ 地瓜判据（L1024）一律 `− liftX(...)`；发射 y 因 `gridToPos` 自动抬升而**不改**。**列为 BLOCKING，未闭环不得验收。**
5. **`ROOF_SLOPE=0.18` 弃用**：M3 的「旋转带」口径与 C2 的「逐 x 抬升」口径不同，屋顶皮肤（带/缝/城垛）**重写为 shear 口径**（`平面 y − liftX(x)`）。
6. **隔离与回退**：全部改动落在 `level.roof` 分支或 `liftX` gate 内；回退 = 反向 5 处独立块（施工规格 §6）。

### 不做（明确边界）

- **不做「真弹道高度物理」**（即不要求「直线弹在坡上按真实高度差打不中」的完整物理）——只做「基线随地面平移」。直线弹发射后仍水平匀速（`pr.y` 恒定）。
- **不做实物斜切**（植物/僵尸贴图随斜面旋转）——只做**位置**跟随，不做**朝向**跟随。
- **不动布局常量**（`GRID_X/GRID_Y/CELL_*`），不动 L1–L4 任何路径。

## 备选方案（Alternatives）

### A. 维持 M3 纯纹理倾斜（不破平面假设）

- 优点：零映射改动、零弹道风险、回归绝对零。
- **否决理由**：已实测「看起来还是平 / 台阶感」——用户诉求是**连续坡面观感**，纹理方案**达不到观感天花板**，且已被用户在两轮效果评审中淘汰。

### B. B 档（逐列常量 Y 偏移，格子仍矩形/阶梯）

- 优点：比 C2 略省（评估 §3.2 核心 +26~46），无斜切反解。
- **否决理由**：**格子只能矩形**（逐列常量无法产出平行四边形）、僵尸**跳档**（每列 12~20px 电梯感）——**正是用户要 C2 消掉的东西**；且美术 §四 明确推荐 C2。

### C1. 纯装饰斜切（`gridToPos` 不动，仅绘制平行四边形）

- 优点：最便宜。
- **否决理由**：**「看到的斜格 ≠ 点中的格」**——破坏落格直觉（本作几何色块画风的命门），且不解决僵尸跳档。**不达 C 的验收目标。**

### C1′. 映射斜切 + 实体阶梯

- 优点：落格自洽。
- **否决理由**：保留「电梯感」（每列跳档），与用户诉求相悖，且**相对 C2 只省 ≈2 行** ⇒ 无理由停在阶梯版。

### D. 逐行偏移 / 真透视整包（历史「400+ 行」语境）

- 优点：最接近物理真实。
- **否决理由**：逐行 Y 偏移 + 真弹道高度物理 + 全链路重写 + 近半 REG 断言平移 ⇒ 成本/风险陡增，收益（在本 2.5D 色块画风下）不足以覆盖。**本 ADR 明确不做**（见「不做」边界）。

## 后果（Consequences）

### 正面

1. **真·斜屋面**：平行四边形格 + 砖缝严丝合缝 + 连续行走 ⇒ 达到 C 档观感天花板（最接近 PvZ 截图）。
2. **落格自洽**：闭式互逆 ⇒ 斜坡上点选的格 = 画出的格（美术命门达成）。
3. **成本可控**：核心 +40~65 行，**推翻「400+」的历史估算口径**（该口径属「真透视整包」，非本切片）。
4. **回归零漂移**：`level.roof` gate + probe 不吐 y + 闭式互逆 ⇒ 既有 27/60/56 门控预期全绿。
5. **演进清晰**：`liftX` 单点开关；未来若要「真弹道高度物理」只扩 `liftX`→命中语义，不重构映射层。

### 负面 / 风险

1. **BLOCKING：弹道基线必须同步抬升**（L1073 等）。漏改 ⇒ L5 直线弹全废，**且现有门控不报**（无坡上命中用例）。→ 对策：施工规格 §3 清单 + 建议新增轻量断言 + 真机复核。
2. **静默玩法变化**：修后「坡上直线弹」语义与今日不同（上坡可中、越顶/越坡可能漏）——**零回归 ≠ 玩法零变化**，须真机 + Playtest 覆盖。→ 对策：施工规格 §7-1 提供 α/β 两口径供拍板。
3. **顶部空间收窄**：平台顶 y=20、城垛顶 y=6（H=60），逼近画布上沿；**H 硬上限 ≈66**（城垛顶触顶）。→ 对策：H=60 保留 6px 余量；不再上调。
4. **皮肤重写面**：M3 的 `ROOF_SLOPE` 旋转带整体作废，带/缝/城垛需按 shear 重写（约 +9~17 行核心）。→ 对策：施工规格 §2.E 给出逐块口径。
5. **L5 既有手感平移 60px**：平台整体上抬 60px，L5 既有手感（种植/命中的像素位置）整体平移，需真机复验。→ 对策：roof-gated，不影响老关；L5 属开发中关卡（未发布）。

### 与既有 ADR/GDD 的关系

- **与 ADR-001（单文件零构建）**：**不冲突**——本决策只用现有 Canvas 2D 原语，零新依赖、零构建。
- **与 ADR-003（Canvas 2D）**：**不冲突**——平行四边形仍用 `beginPath/moveTo/lineTo/fill` 既有原语。
- **与 GDD 拍板项 ④ / `roof-process §2.4`**：**修订**——原「否决真透视」的理由（400+ 行 / 破坏平面假设波及全链路）**经实测不成立**；本 ADR 以实测成本/回归证据**有条件翻转**该否决（条件：roof-gate + 弹道基线同步抬升 + 不做真弹道物理）。

## 触发复审的信号（Future Revisit Triggers）

出现以下任一情况，重评审本 ADR：

1. **弹道基线抬升（BLOCKING）无法在 roof-gate 内干净落地**（如需要引入新命中算法/改窗口常量）→ 说明「破平面假设」的连带面被低估，回退 B 档评估。
2. **要「真弹道高度物理」**（直线弹按坡高真实打不中）→ 命中语义升级，成本量级抬升，须重估。
3. **斜坡列数/抬升量再变**（如 5 列→全 9 列，或 H>66）→ 顶部空间/观感约束重算。
4. **引擎或渲染后端切换**（Canvas 2D → WebGL 等）→ 映射层与皮肤重做，本 ADR 作废。
5. **L5 真机手感复验判定「平台整体上抬 60px」不可接受** → 需重新设计抬升基准（如底锚 vs 顶锚）。
