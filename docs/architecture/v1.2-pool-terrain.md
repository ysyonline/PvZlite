## §2 睡莲格语义甲/乙案可实现性背书（GDD 拍板项②技术输入）

### 2.1 两案实现形态对照

| 维度 | 甲案：垫为实体 | 乙案：`hasPad` 布尔 |
|---|---|---|
| 数据形态 | `plants.push({type:'lilypad',dur:300,maxDur:300,...})`，与普通植物同构 | 新顶层集合 `waterPads`（如 `Set` 存 `'col,row'`），与 plants 平级的**第二种格子状态载体** |
| 既有管道复用 | updatePlant 无匹配分支 = 天然 no-op（L889–L925 结构验证）；`_dying` 清理循环零改动；probe.plantsArr 免费获得垫快照 | 校验/渲染/重置/探针全部要显式接新集合：startGame 加清理、PROBE_SUFFIX 加 `__waterPads` 桥、probe 需扩字段 |
| 渲染 z-order | **白送**：drawGameWorld L1318 按数组序绘制 = 后种的上覆植物天然盖在垫上，零改动即 M3"不互相遮挡" | 需在植物层前插垫的静态绘制块 |

| 平衡 | 保住 GDD"水税可能重复缴"的真实压力，与支柱 1/§5.3 水税专项（6–8 垫含 1–2 重铺余量）自洽 | 水行后期一次性投资即永久防线，"贵格火力管理"考点（W6–W8 桶落水行）张力减弱；GDD 已评估数值影响可忽略，**但体验张力差异仍在** |

### 2.2 决定性技术证据：啃食目标选择的现状语义

updateZombies L1005–L1010 现状：

```js
let target=null;
for(const p of plants){                    // ← 数组序正序遍历
  if(p.row!==z.row)continue;
  const pos=gridToPos(p.col,p.row);
  if(z.x-pos.x<CELL_W*0.4&&z.x-pos.x>0){target=p;break}
}
```

僵尸啃"嘴前 36px 内**数组序第一个**植物"。甲案下垫先种（index 小）→ 上覆植物后种（index 大）→ 正序遍历**先命中垫**——与 GDD 甲案"自上而下：先啃上覆植物"**顺序相反**。修正（1 行 + 1 注释）：

```js
for(let i=plants.length-1;i>=0;i--){       // 倒序：同格多实体（垫+上覆）先啃后种的（甲案自上而下语义）
```

**回归安全性证明**：相邻格中心距 = CELL_W = 90 > 36 门槛，僵尸嘴前窗口内至多命中一个格子；陆地格恒为单实体，倒序与正序在该格内结果相同。即此改动**只改变"同格多实体"这一新引入的情形**，对 L1–L3 全部行为严格等价，由现有 REG-PLANT-01~04 / REG-ZOM-01~03 全绿兜底。

### 2.3 推荐

**推荐甲案。** 归纳：

1. **哲学契合**（ADR-001/002 精神）：甲案"新内容 = 数据 + 既有管道读它"，乙案发明 plants 之外的第三种状态载体，每个触点（校验/渲染/重置/探针）都要显式接新集合——违背"读常量做分支"的最小改动精神。
2. **渲染 z-order 白送**，乙案要手写分层。
3. **甲案的唯一硬成本**（§2.2 的 1 行）已被证明对存量行为零影响。
4. 平衡与体验：甲案保住"垫会被啃穿"的压力语义，乙案焊死未来演进路。
5. 乙案唯一优势（啃食零改动）被 §2.2 证明代价仅 1 行，优势不复存在。

垫耐久建议值：`dur:300`（与地瓜同级最短档；啃食 65/s → 空垫 ≈4.6s 啃穿，垫+豌豆 ≈16s——垫的脆弱有存在感但不拖累 25 费重铺节奏）。**规格不锁值，不入契约断言**（GDD §8.3 口径）。

### 2.4 E4 铲子交互：规格矛盾与技术侧修正建议

GDD E4 字面："垫上有植物 → 禁止 + toast（'先移除上方植物'）"。但按字面规格，玩家**没有任何途径移除上方植物**（点垫格被整体拒绝）——toast 指引一条死路，且水格火力永远无法替换（垫上植物只能陪葬到垫被啃穿）。

**技术侧建议修正 E4 为**：铲子作用于该格**最上层实体**——垫+植物 → 移除植物、保留垫；仅空垫 → 移除垫（无返还，全作惯例）；陆地格照常。这保留 E4"垫不被误铲"的保护意图，同时给玩家完整操作空间。实现代价两案相同（铲子循环 L635–645 改为"取格内数组序最后实体"，+4~8 行）。**此为规格 deviation，需文策渊确认后回写 GDD §6.2 E4**（见 §6）。

## §3 E1/E2 拒绝路径现状时序确认（onClick L649–L664）

现状代码逐行：

```js
if(selected){
  const c=CARDS[selected.i];
  // L652 ①占用校验（先）——拒绝：deny+toast+return，保留选中
  if(plants.some(p=>p.col===g.x&&p.row===g.y)){SFX.deny();toast('这格已经有植物了',1.4);return}
  // L653 ②阳光/CD 校验 + 扣款（后）——通过才 sun-= / cardCD=
  if(sun>=c.cost&&!(cardCD[c.type]>0)){
    sun-=c.cost;cardCD[c.type]=c.cd;
    plants.push({...});SFX.plant();
  }else{SFX.deny()}
  selected=null;return;
}
```

**结论：现状是"先校验、后扣款"**——所有拒绝路径（占用 L652、阳光/CD 不足 L661–663）均发生在 `sun-=c.cost` 之前，天然零副作用。E1/E2 的水格/陆格校验插入点 = **L652 之后、L653 之前**：

```js
// L652½（新增 2 行）：水轴校验——拒绝模式完全复刻 L652（deny+toast+return，保留选中）
if(WATER_ROWS.includes(g.y)&&!plants.some(p=>p.col===g.x&&p.row===g.y&&p.type==='lilypad')&&c.type!=='lilypad'){SFX.deny();toast('水格需要先铺睡莲',1.4);return}
if(!WATER_ROWS.includes(g.y)&&c.type==='lilypad'){SFX.deny();toast('睡莲只能种在水里',1.4);return}
```

零副作用成立性：两行 return 前不触碰 `sun` / `cardCD` / `selected`——与 L652 占用拒绝行为模式逐位一致（注释"保留选中，方便改点空格"的既有设计意图原样继承）。**无需改动任何既有行，纯插入。**
