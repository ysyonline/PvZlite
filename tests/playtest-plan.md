# Playtest 计划 · PvZ Lite

> **目标**：把"感觉还行"变成"有证据的验收标准"。三轮 Playtest 分别验证核心循环、上手体验、压力边界。
>
> **参与方式**：本项目为个人项目、无外部玩家。所有 Playtest 采用 **自评（作者本人） + 亲友代测（≥1 人，最好 2 人）**。亲友代测时必须提前关闭控制台、禁止告知任何实现细节（关卡配置 / 数值），只做"正常玩"。
>
> **通过判定**：每一轮独立给出 PASS / CONCERNS / FAIL。任何一轮 FAIL 即阻塞发布，需要主理人确认是否延后。

---

## 通用规则（三轮共用）

### 前置条件（每轮开始前必做）

1. **打开文件**：双击 `D:\code\zw\plants-vs-zombies.html`（或拖入 Chrome / Edge）。禁止使用浏览器开发者工具查看代码。
2. **localStorage 处理**：本项目已有解锁进度存档（键 `pvz_unlocked`，2026-09-16 加入）。**想体验零解锁流程** → DevTools → Application → Storage → Clear site data 清一次；**想直接测第二关** → 不清，或在地址栏追加 `?level=2` 免解锁直进。
3. **浏览器环境**：Chrome / Edge 最新版，窗口 ≥ 1200×800（画布固定 1000×680，需要完整显示）。
4. **关闭干扰**：通知静音、屏蔽自动播放拦截（浏览器应因首次点击「开始游戏」而允许 WebAudio）。
5. **记录工具**：手边准备一个 Markdown 笔记文件（每轮一个，命名 `tests/playtests/round-N-notes.md`）+ 秒表 + 可选录屏（OBS / ShareX）。

### 观察维度（每轮共用 6 条）

| # | 观察维度 | 记录方式 |
|---|---|---|
| O1 | **卡死 / 帧异常**：屏幕是否冻结？底部红条「⚠ 捕获到帧异常」是否出现？ | 出现一次即记录，附 `setState` 日志和截图 |
| O2 | **误操作**：想点 A 结果点中 B（卡片栏 / 铲子 / 阳光 / 种植预览） | 记录操作意图 vs 实际结果 |
| O3 | **反馈不足**：想做的操作没有反馈（音效 / 视觉 / 提示） | 记录场景 + 期望的反馈 |
| O4 | **数值平衡**：某波感觉过于轻松 / 过于困难 | 记录波次 + 感受 |
| O5 | **教学缺失**：不看说明能否理解机制？ | 记录卡壳点 |
| O6 | **快捷键冲突**：浏览器快捷键（Ctrl+R / F5 / Tab）是否干扰？ | 记录按键 + 冲突表现 |

### 通用记录模板

```markdown
## Round N · <主题> · <日期> · <参与者>

| 任务 ID | 任务描述 | 成功 | 耗时 | 困惑点 | 情绪反应 | 观察记录（O1-O6） | 备注 |
|---|---|---|---|---|---|---|---|
| T1 | ... | ✅ / ❌ / ⚠ | mm:ss | ... | 😌/😐/😟/😵 | O2: ... | ... |
```

情绪反应约定：😌舒服 / 😐一般 / 😟焦虑 / 😵受挫。

### 通过标准（三条硬门槛，每轮共用）

任一命中即 **FAIL**：
- **F1**：出现 O1（卡死或帧异常），且未能在同一份代码下 3 次复现通过；
- **F2**：核心任务全部失败（如"通关第 1 关"），且失败原因不是玩家操作失误；
- **F3**：出现 S0 级 Bug（参考 `bug-taxonomy.md`）——阻断级 Bug 一票否决。

三条全部命中「无」但存在 O2-O6 累计 ≥ 3 条 → **CONCERNS**（可发布但需列入下一 sprint）。
否则 → **PASS**。

## Round 1 · 可玩性验证（Core Loop Fun）

### 目的
验证核心循环「收集阳光 → 种卡 → 打僵尸 → 过波」是否具备基础"好玩感"，识别反馈/数值层面的明显缺陷。

### 参与者画像
- **主测**：作者自评（1 人）——熟悉机制，用于确认"没做错的"。
- **副测**：1 位**玩过原版 PvZ 或塔防类游戏**的亲友——用于校准"是否符合品类期待"。
- **时长**：每轮每人 20-30 分钟。

### 任务列表

| ID | 任务 | 期望结果 | 观察重点 |
|---|---|---|---|
| T1 | 第 1 关·普通难度，从零开始正常玩到通关 | 3-6 分钟内通关 | 节奏是否拖沓、第 5 波大波预警是否给足准备时间 |
| T2 | 第 1 关·普通难度，**只用豌豆（第 2 卡）** 通关 | 能过 2-3 波即算成功，无法通关也可接受 | 单一输出是否有存在感 |
| T3 | 第 1 关·普通难度，**只用向日葵 + 铲子**，观察纯经济循环 | 观察是否能"越种越富" | 阳光掉落到哪、是否会被误吞；铲子是否误用 |
| T4 | 第 2 关·普通难度正常通关 | 通关成功 | 快速僵尸出现时的应对节奏 |
| T5 | 第 2 关·普通难度，**故意不点阳光**观察失败反馈 | 失败画面是否清楚、是否有"再来一次"的直觉路径 | O2 误操作、O3 反馈不足 |
| T6 | 通关第 1 关后返回菜单，确认「第 2 关」解锁 | 第 2 关按钮变为可点击（非 🔒） | 解锁反馈是否明显 |
| T7 | 使用「下一关」按钮从结算页直进第 2 关 | 直接进入，无需返回菜单 | 按钮位置与文本是否清晰 |
| T8 | 使用快捷键全流程：`1-6` 选卡、`X` 铲子、`F` 加速、`M` 静音、`空格` 暂停、`R` 重来 | 全流程快捷键可用 | O6 快捷键冲突；R 键二次确认是否合理 |

### 通过标准
- **PASS**：T1 / T4 / T6 全 ✅；无 F1/F2/F3；O1-O6 累计 ≤ 2 条；主测+副测"愿意再玩一局"的意愿 ≥ 1 人。
- **CONCERNS**：T2/T3/T5/T8 有 ⚠ 但未 FAIL。
- **FAIL**：命中任一硬门槛。

## Round 2 · 教学与上手（Onboarding）

### 目的
验证**新手 3 分钟内能否不看任何说明通关第 1 关**——即"教学是否靠设计而非文档"。同时验证菜单信息层级、失败后的重试路径。

### 参与者画像
- **主测**：1-2 位**没玩过 PvZ 也基本没玩过塔防**的亲友（大学生 / 老人优先）。
- **不告知**：不给任何说明、不提示任何机制、不解释任何 UI。
- **观察方式**：作者旁站，只记录不指导。允许玩家**大声自言自语**（"说想法"法 / think-aloud），可录音。
- **时长**：每人最多 10 分钟——超过 3 分钟未通关即为失败样本。

### 任务列表

| ID | 任务 | 期望结果 | 观察重点 |
|---|---|---|---|
| T1 | 双击打开 HTML，观察 5 秒内是否理解"这是什么" | 能说出"塔防类"或类似 | 首屏视觉冲击、标题识别度 |
| T2 | 不问作者，独立点开「开始游戏」 | 进入第 1 关 | 按钮层级是否明显 |
| T3 | 不问作者，独立完成首次种植 | 5 秒内种下 1 棵向日葵 | 卡片视觉、点击热区、阳光数字理解 |
| T4 | 不问作者，独立收集阳光 | 30 秒内点收至少 1 颗 | 阳光掉落轨迹、点击热区 |
| T5 | 不问作者，用 100 阳光种下豌豆 | 观察是否理解"种豌豆就能攻击" | O5 教学缺失、植物图标识别 |
| T6 | 3 分钟内尝试通关第 1 关（普通难度） | 通关或至少打到第 3 波 | 难度曲线、卡壳点 |
| T7 | 失败后观察是否知道如何重来 | 主动按 R 或点「重来」 | 失败提示清晰度 |
| T8 | 询问玩家："你怎么知道要按 1-6 选卡？" | 观察玩家如何理解快捷键 | 底部提示条 / 菜单提示行有效性 |

### 通过标准
- **PASS**：T3 / T4 / T5 全部 ✅；至少 1 位新手在 3 分钟内打到第 3 波或以上；玩家能自述 ≥ 2 条游戏机制。
- **CONCERNS**：T1/T2 顺利但 T6 有 1 人在 3 分钟内没打到第 3 波；教学有卡壳但可绕过。
- **FAIL**：任一新手 T3 或 T4 失败（连"种卡"和"收阳光"都做不到）；或 T6 全部新手 ≤ 第 2 波。

### 备注
若 T2 失败（按钮找不到）：很可能是「开始游戏」按钮视觉权重不足，需 art-director 复核。
若 T5 失败（不理解豌豆作用）：需在卡片栏加 1 行小字说明或首次种下时触发 toast。

## Round 3 · 压力与边界（Stress & Edge）

### 目的
在**地狱难度 + 4× 加速 + 大波叠加**的极限条件下，找出：
1. 主循环卡顿或帧异常（对应已知陷阱「RAF 位置」）
2. 波次/预告/刷怪的边界（对应 `warn` / `spawnQueue` / `checkWave` 分支）
3. 音效节流是否糊成一团
4. 结算页解锁逻辑在极端路径下的正确性

### 参与者画像
- **主测**：作者自评（1 人）——熟悉机制。
- **副测**：1 位**硬核玩家**（打过困难 / 地狱塔防或速通类）——用于找出玩家视角的"作弊路径"。
- **时长**：每轮每人 15-20 分钟。

### 任务列表

| ID | 任务 | 期望结果 | 观察重点 |
|---|---|---|---|
| T1 | 第 1 关·地狱难度·4× 加速，尝试通关 | 通关；观察帧率是否流畅 | O1 卡死、性能 |
| T2 | 第 1 关·地狱难度·1× 速度·大波预警（第 5 波）时暂停并观察 UI | 暂停状态下大波预警横幅仍在；恢复后正常进入 | 暂停 × 预警的组合是否冲突 |
| T3 | 第 2 关·地狱难度·4× 加速，**同时按 M 静音、F 加速、R 重来** 高频切换 | 无帧异常；每次切换状态正确 | 快捷键抢占、按钮 blur 是否生效 |
| T4 | 连续 5 波全用**向日葵 + 坚果**堆防御，不种植任何攻击植物 | 观察失败路径与反馈 | 是否会被"看起来能过"误导 |
| T5 | 让 4 只普通僵尸同时进屋（用铲子清空防线，让它们直冲） | 触发 `setState('end','僵尸进屋')` | 一次只进 1 只还是全部同时进 |
| T6 | 快速连点卡片栏（同卡连点 20 次）+ 快速连点铲子 | 卡片冷却正确、铲子不叠态 | 卡片 `cardCD` vs 植物 `p.cd` 混淆 |
| T7 | 在阳光下落瞬间点击阳光 + 同时按下 F | 阳光被正确收集、速度切换不冲突 | 输入事件竞争 |
| T8 | 通关第 2 关后返回菜单，观察是否显示「已通关全部关卡」 | 显示庆祝语 | 边界分支：`won && !LEVELS[levelNo+1]` |

### 通过标准
- **PASS**：T1 / T3 / T5 / T6 / T8 全 ✅；无帧异常；控制台无 `[PvZ] 帧异常` 报错。
- **CONCERNS**：T2 或 T4 有异常但不阻断。
- **FAIL**：任一测试出现 O1（卡死 / 帧异常），或 T5 出现"僵尸进屋却没结束游戏"这类逻辑错误。

### 压力测试附注（工程同学可参考）
- 若 T1 帧率明显掉，工程同学可查 `update()` 内是否引入了 O(n²)（例如 `hasZombieAhead` 每帧 × 每植物）。
- 若 T3 帧异常，检查 `requestExit` 二次确认状态是否与 `setState` 冲突。
- 若 T5 出现多僵尸同时进屋只触发 1 次 `setState`，属于正确行为（幂等）；若完全不触发，为 Bug。
