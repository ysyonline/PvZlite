## 三、v1.1 背景速览（为什么有 T9-T14）

- **S3 第三关「月夜草坪」**（`LEVELS[3]`，源码已核）：7 波 33 只（normal 15 / cone 8 / fast 8 / **bucket 2**），大波 = W3 / W5 / W7，`startSun=100`，`night` 冷蓝滤镜。**铁桶仅出现在 W6（1 只）与 W7（1 只）**，hp 560（约 3 只 normal）；末波 W7 = normal×3 + cone×2 + fast×2 + bucket×1 共 8 只，interval 6s + 队列剩余 >6 只时每只 +0.5s 喘息（引擎自动摊薄）。
- **难度与速度系统**：僵尸 hp/spd = 基础 STATS × `DIFFS` 倍率，地狱难度为最高倍率；`F` 键切换 1×/2×/4× 游戏速度。速度只缩放游戏时钟，**音频调度同样随游戏时间走**——4× 下警报轮次间隔（0.62s 游戏时）实际体感约 0.16s 一轮。
- **与 KNOWN-ISSUES #8 的关系**：本轮 T9/T10 的帧率观察是**定性**的（流畅/掉帧/冻结）；量化 profile（DevTools Performance 60 帧）由性能基准任务（V11-11）单独执行。两件事同期进行时数据可互相引用，但本轮判定不依赖量化数字。

## 四、v1.1 扩充任务详解（T9-T14，全部主测执行）

### T9 · 第三关 · 地狱难度 · 4× 加速全程通关
- **怎么验**：`?level=3` + 地狱难度 + `F` 切到 4×，尝试全程通关。
- **期望**：通关全程无卡死、无底部红条「⚠ 捕获到帧异常」；地狱倍率下 W5/W7 大波虽有压力但**逻辑行为正确**（预警 → 刷怪 → 清场门槛 → 结算）。
- **观察重点**：O1（帧异常零容忍，出现即记录 + 截图 + 记录波次）；W7 场上同时存在 normal+cone+fast+bucket 四种实体时的渲染与碰撞。
- **异常**：画面冻结 / 红条 / 波次卡住不推进 / 僵尸穿行叠影异常。

### T10 · 4× 加速下第三关末波边界（帧率 + 手感 + 声音层叠）【本轮 v1.1 核心任务】
- **怎么验**：L3 · 普通难度 · 4× 加速，打到 W7（big wave + bucket 在场）；在 W7 预警 2 秒窗口与刷怪期间密集操作（快速点卡 + 铲子 + 收阳光）。
- **期望**：
  - **帧率**：W7 全场 8 只 + 抛物线（西瓜）+ 粒子同屏时无肉眼可见掉帧；`interval` 下限保护（`max(2.5, interval)`）与队列喘息正常生效，刷怪节奏均匀；
  - **手感**：种植 / 铲除 / 收阳光的点击响应在 4× 下仍跟手，无"点了中国没反应"的输入丢失；
  - **声音**：警报 loop 在 4× 下轮次间隔体感变密但**不破音、不糊成一团**（单轮 0.62s 游戏时 × MAXROUND=8 防御上限兜底）；横幅结束当帧警报停止、紧接低沉冲击音（`bigWaveImpact`），衔接干净无拖尾。
- **观察重点**：O1；O3（声音语义在高速下是否仍可辨识）；预警 × 高速 × 密集操作三重叠加是否互相打架。
- **异常**：末波掉帧明显 / 警报拖尾进战斗 / 冲击音丢失 / 点击丢输入 / 红条。

### T11 · 铁桶僵尸（bucket）压力场景可读性
- **怎么验**：W6（bucket 首秀，非大波）与 W7（大波内）各观察一只铁桶从登场到死亡的全过程。
- **期望**：
  - **可读性**（GDD level-3 §2 口径）：能看出"豌豆打桶很慢"——铁桶血条消耗明显比普通僵尸慢；
  - **死亡反馈**：金属碎裂"叮当"音（`SFX.death('bucket')`）与**桶形零件**（`shape:'bucket'`）飞出同帧发生，视觉听觉同步；
  - 分值反馈：击杀 +150（高于 cone 100 / fast 80 / normal 50）。
- **异常**：铁桶死亡无金属音 / 没有桶形零件 / 音画不同步 / W6 首秀即被大波淹没导致玩家看不清机制（记录实际波次场面）。
- **关联**：O3 / O4。

### T12 · 第三关 W7 大波预警 × 暂停组合
- **怎么验**：L3 打到 W7 预警横幅出现时按 `空格` 暂停，观察 3 秒后恢复。
- **期望**：暂停状态下横幅与倒计时静止但可见；警报声行为符合"暂停即停 / 恢复续播或随窗口剩余时间收束"任一合理表现（记录实际行为即可，不做硬性期望）；恢复后正常进入 W7，无状态错乱。
- **说明**：本任务是 R1-T2（L1 第 5 波版）在 v1.1 新关卡下的延伸——夜间滤镜 + 预警横幅 + 暂停三者的组合是 L3 特有画面条件。
- **异常**：暂停后横幅消失不恢复 / 恢复后预警跳过直接刷怪 / 警报声在暂停中无限循环不停。
- **关联**：O1。

### T13 · 第三关通关的终局边界 + 持久化
- **怎么验**：正常通关 L3（普通难度即可）→ 观察结算页 → 返回菜单 → `F5` 刷新 → 再看菜单。
- **期望**：通关 L3 后应触发"**已通关全部关卡**"庆祝分支（`won && !LEVELS[levelNo+1]`，L3 是最后一关）；结算页最高分已更新；刷新后菜单三关全解锁、最高分保留。
- **异常**：通关 L3 仍提示"下一关" / 庆祝语不出现 / 刷新后解锁回退。
- **关联**：O5（终局反馈是否给玩家"毕业感"）。

### T14 · 第三关大规模失守的失败反馈 + 结算落盘时机
- **怎么验**：L3 打到 W6/W7 时主动用铲子清空防线，放 ≥4 只僵尸（含铁桶更佳）同时进屋。
- **期望**：
  - 触发 `setState('end','僵尸进屋')`，游戏结束判定**幂等**（多只同时进屋只结束一次，属正确行为；完全不结束才是 Bug）；
  - 失败音分层：`SFX.lose` + 失败强化音 `loseClimax`（带 2s 节流）层叠不刺耳；
  - 结算页分数与最高分正确（`updateBest` 在进入 end 态时触发——**失败局的高分同样应计入**）。
- **异常**：僵尸进屋游戏不结束 / 失败音爆音或无声 / 高分未落盘。
- **关联**：O3。

- **任务**：第 2 关 · 普通难度，**故意不点任何阳光**，让防线自然被磨穿直至失败。

- **观察重点**：O2（失败瞬间有没有误操作空间）；O3（失败反馈是否充分：画面 + 失败音 + 强化音层叠）；失败文案可读性。

## 八、判定标准（继承计划书，设计未改）

**硬门槛（任一命中 = FAIL）**
- **F1**：出现 O1（卡死或帧异常），且未能在同一份代码下 3 次复现通过；
- **F2**：核心任务全部失败，且失败原因不是玩家操作失误；
- **F3**：出现 S0 级 Bug（参考 `tests/bug-taxonomy.md`）——阻断级一票否决。

**PASS**：T1 / T3 / T5 / T6 / T8 全 ✅；无帧异常；控制台无 `[PvZ] 帧异常` 报错。
**CONCERNS**：T2 或 T4 有异常但不阻断。
**FAIL**：任一测试出现 O1（卡死 / 帧异常），或 T5 出现"僵尸进屋却没结束游戏"这类逻辑错误。

> **v1.1 任务与补测项的处理口径（继承 Round 1 执行包对 V 系列的做法）**：T9-T14 与 R1-T2/R1-T3/R1-T5 **不改变上述判定公式**；其结果单独评审。发现"异常"描述按缺陷记录并定级（S0-S3）——命中 S0 即触发 F3 一票否决；S1 及以下进缺陷清单与下一 sprint。补测项结果由主理人**回填 `round-1-report.md`**（把"— 未单独回报"改为实测结果），用于闭合 KNOWN-ISSUES #5。
>
> **T8 期望值迁移说明（重要）**：计划书成文时游戏只有两关，故原 T8 期望"通关第 2 关显示已通关全部关卡"。v1.1 新增第三关后，该分支的正确行为变为：**通关 L2 → 菜单解锁 L3（无庆祝语）；通关 L3 → 才显示"已通关全部关卡"**（`won && !LEVELS[levelNo+1]` 分支天然支持，T13 专项验证）。本轮按 v1.1 语义判定 T8，计划书原文不回改。
