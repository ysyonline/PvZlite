## 三、B / C 差异说明（≤1 屏）

| 维度 | **B 档 · 阶梯** | **C 档 · 平滑** |
|---|---|---|
| **轮廓读感** | 左段呈 **3 级台阶**（3 个水平条带 + 竖面）；与「理想连续坡线」之间露出可见的**台阶空隙**。远景/小窗下会读成「三级楼梯」而非「屋顶斜面」 | 左段是**一条连续斜边**，与理想坡线**完全重合**；一眼即「屋顶斜坡」 |
| **僵尸上坡观感** | 僵尸 y 随列**跳档**：每跨一列出现一次**瞬时高度突变**（20px 的「电梯」感），连续行走时略突兀 | 僵尸 y 随 x **连续变化**，沿坡平滑上下，最接近 PvZ 原版的「走在斜屋面上」 |
| **格子与砖缝对齐** | 砖缝严格落在**矩形格**边界，横缝随台阶折线 —— **对齐无问题** | 格子本身即**平行四边形**，砖缝仍严丝合缝落在格边界；横缝沿坡为连续斜线 —— **同样对齐** |
| **与 PvZ 原版接近度** | 低（台阶感明显偏离） | **高**（平滑坡面 + 斜瓦行，最接近用户给的 PvZ 截图） |
| **工程代价** | 小（在 `gridToPos` 上加逐列 Y 偏移 / 或仅在绘制层逐列上移） | 大（斜坡段格子从矩形改为平行四边形，需工程侧评估；见并行产物） |
| **可读性风险** | 无（格子仍是轴对齐矩形） | 低（格子虽斜切，但砖缝与格仍对齐、落格中心仍可辨识） |

**一句话**：两档都能把「平的」变成「斜的」；**B 用台阶近似坡度，C 用平行四边形得到真坡度**。差别集中在**轮廓与行走是否连续**，以及在斜面上「砖缝↔格子」能否继续严丝合缝——这一点 **B 和 C 都做到了**。

## 四、美术总监推荐：**C 档**

理由：
1. **用户诉求的本质是「连续坡面的观感」**，不是「轮廓上有个台阶」。B 的台阶在大屏/远景下会暴露为 3 段水平条带，越看越像楼梯，**没解决问题的“根”**。
2. **C 不牺牲任何已有优势**：砖缝与格子**仍完全对齐**（本作「几何色块」画风下，对齐是落格直觉的命门）；僵尸行走连续、观感最接近 PvZ 截图。
3. 台阶感一旦被用户看出来，多半会再返工一次；C 一次性到位，返工风险最低。

**若工程成本不可接受**：B 是「几何正确、观感次优」的**保底档**，可在 B 之上局部微调（缩小每档 px、或斜坡只占 2 档）以弱化台阶感 —— 但**观感天花板仍低于 C**。请在 B / C 之间拍板。
