## 2. 抬升函数与高度（施工唯一真源）

```
liftX(x) = H · clamp( (x − GRID_X) / (5 · CELL_W), 0, 1 )
         = H · clamp( (x − 55) / 450, 0, 1 )
H = 60 px                      // ★ 定稿值（主理人裁决：保持 60；工程硬上限 H≤66）
GRID_X=55, CELL_W=90, COLS=9, ROWS=5, GRID_Y=80, CELL_H=104
```

- 列边界（x = 55 / 145 / 235 / 325 / 415 / 505）累计抬升 = **0 / 12 / 24 / 36 / 48 / 60 px** → **每列 +12px**（比 3 列版的 +20px 更缓）。
- 抬升后顶边：`col0 y=80 → col4 y=20`；`col5–8 y=20`（平齐）。
- 任意行的基线：`y_row(x) = GRID_Y + row·CELL_H + … − liftX(x)`（row 内连续，随 x 变化）。

## 6. ★ 美术判断：5 列 + H=60 够不够「一眼斜屋顶」？（工程侧参考）

> **定稿裁决（v1.3-M4 收口）**：**H = 60 定稿**（尊重用户已拍的「默认」+ 工程留余量，工程判硬上限 **H≤66**）。下方的「偏缓」担忧**不再以调 H 解决**，改用 **§6.1 补偿三件套**（已纳入工程绘制层清单）。

**结论：能读，但属「偏缓」档，处于「能读但不抢眼」的临界 —— 故必须上补偿。**

| 量 | 值 | 说明 |
|---|---|---|
| 本轮 5 列 H60 | `atan(60/450) =` **≈7.6°** | 比 3 列版打了约六折 |
| 上轮 3 列 H60 | `atan(60/270) =` **≈12.5°** | 舒适、明确 |
| 本作现有纹理斜面 `ROOF_SLOPE=0.18` | **≈10.2°** | 可作为「够斜」的经验锚点 |

- **够不够**：在**全尺寸静态帧**下能读出斜度（见 `slope-c2-5col.png`），**但**在小窗/移动端缩显或动态背景中，读感会掉到「疑似平」的边际。用户最初的投诉正是「看着平」→ **不贴临界走**。
- **H 的上限（存档，本版不采用）**：受「天空带可见 ~80px − 城垛 12px − 干净天空 ≥6px」约束，实测 **H≤66 为硬上限**（H=66→8.4°，平台城垛贴画布顶）；若把城垛降到 10–12px 理论上可到 72（9.1°），但**本轮已裁决不改 H**。
- **补偿路线**：见 §6.1（定稿采用）。

### 6.1 补偿三件套（定稿配置 · H=60 定稿下的配套补偿，用于抵消 7.6° 的偏缓读数）

> 主理人裁决：**H 保持 60**；「偏缓」读数**改用下列三项绘制层补偿解决**（纯绘制、不涉任何逻辑），美术侧为权威口径，工程侧已同意纳入绘制层清单。

| # | 补偿项 | 施工口径 | 作用 |
|---|---|---|---|
| ① | **斜坡段每行内增补一条半缝** | 斜坡段（col 0–4）在「每行 1 条横缝」基础上，**行内再补 1 条**（斜缝条数 ×2） | 用纹理密度直接换斜率读感，成本最低、最有效 |
| ② | **加强沿坡明暗** | 对角 linearGradient 幅度略加大（左上更亮 / 右下更暗，停靠点由 `0.10 / 0.20` 提至约 `0.13 / 0.24`） | 用受光方向暗示坡度 |
| ③ | **屋脊压条斜段加粗** | 沿顶边轮廓描边，**斜坡段 8→10px**、平台段维持 8px | 拉粗「坡线」的视觉权重 |

- **城垛不加密**：其密度与平台一致性更重要；坡线读感靠 ①②③ 即可，加密城垛反破坏屋脊节奏。
- 三项均为**纯绘制改动、零逻辑耦合**，H 不变、`liftX` 不变；若后续 H 上调（≤66），①②③ 仍适用（可保留或随之下调强度）。

### 6.2 城垛高度口径统一（收口澄清）

| 项 | 值 | 说明 |
|---|---|---|
| 效果草图画的高度 | **14px** | `slope-c2-5col-preview.html` 里的 `MH=14`，**仅示意**、非施工值 |
| **源码实际值** | **`MERLON_H = 12`** | `plants-vs-zombies.html` **L1471**（工程侧口径） |
| 对观感判断的影响 | **不影响** | 12 vs 14 的 2px 差异在 45px 宽、可辨于天空的剪影上**肉眼不可辨**；城垛的坡度读感来自**底边贴轮廓线**（`y=GY−liftX(x)`）而非高度，故 §6/§6.1 的判断与结论**全部成立** |
| 连带利好 | 顶部余量 +2px | H=60 时顶部余量由草图的 6px 修正为 **8px**（更稳，利于 HUD 护罩与城垛不贴顶） |

> 实现以 **`MERLON_H=12`** 为准；本文其余处若出现「14」均按本条解读为「示意」。

## 7. 待工程确认 / 风险（画像仅供工程评估，裁定权在工程侧）

| # | 项 | 说明 |
|---|---|---|
| R1 | **顶部 HUD 与抬升后的屋面重叠** | 平台被抬到 y=20 后，右上 HUD 文字区（`drawStatus` y≈4–48）与屋面/城垛在 x≥505 处空间重叠 → 需保证屋面绘制**早于** HUD，并保留/加强 HUD 护罩，避免浅蓝天上黄字读不清 |
| R2 | **檐板补厚实现** | 檐板是「顶边轮廓向下补到 y=600」的实心面，草稿里容易；落到工程需注意与右侧檐沟/左侧房子的遮挡顺序 |
| R3 | **平行四边形描边畸变** | 手工端点剪切（在格位置算 `liftX`）无描边畸变；若改用 `ctx.transform` 整体斜切，斜线描边宽度会轻微不均（本作 2px/低 alpha 下不可见，但仍建议手工剪切） |
| R4 | **补偿三件套的落地** | 见 §6.1；均纯绘制，需在绘制层清单内实现（斜坡段加半缝 / 渐变加强 / 压条加粗） |
| R5 | **城垛高度** | 以 `MERLON_H=12` 为准（§6.2） |
