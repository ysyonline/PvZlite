## §1 现状评估

### 1.1 现有植物体系的功能空缺

现有 12 种植物按职能分类：

| 职能 | 植物 | 数量 |
|---|---|---|
| 经济 | sunflower | 1 |
| 直线输出 | pea / double / snowpea | 3 |
| 抛物输出 | cabbage / corn / melon / icemelon | 4 |
| 防御 | nut | 1 |
| 地形载体 | lilypad / planter | 2 |
| **一次性秒杀** | **mine（地瓜）** | **1** |

**核心空缺**：一次性秒杀型植物严重不足。现有唯一秒杀卡 `mine` 的局限：

1. **命中范围仅同排 ±54px**（地雷**杀伤半径** `CELL_W*0.6` = 54px，约半格多）——范围极小；且其**触发判据**更窄，仅 `CELL_W*0.55` ≈ 49.5px（两语义区分见 §2.3）；
2. **被动触发**——必须等僵尸正好踩到埋点；
3. **定位廉价**（25 阳）——作为唯一秒杀卡，无法承接「对群爆发」「跨行救场」的需求。

三个新植物恰好补齐三个维度：

| 空缺维度 | 补位植物 | 说明 |
|---|---|---|
| **单排清场** | 航椒炸弹 | 同排全部僵尸一次性清空 |
| **面清场（跨行）** | 樱桃炸弹 | 3×3 格区域无差别秒杀 |
| **定向主动秒杀** | 窝瓜 | 从后方跳向前方任意列的最近僵尸 |

### 1.2 与原版 PvZ 的差异对照

| 原版植物 | PvZ Lite 对应 | 关键差异 |
|---|---|---|
| 土豆雷（Potato Mine） | 地瓜 `mine` | 已实现；±54px 同排、armT=8s、无差别秒杀（v2.1.1 消缺） |
| 辣椒（Jalapeno） | **航椒炸弹 `pepper`（新）** | 原版辣椒=种下即全排火焰清场；本作航椒=埋雷式踩中触发（见 §2.2） |
| 樱桃炸弹（Cherry Bomb） | **樱桃炸弹 `cherry`（新）** | 原版 3×3 格即种即爆；本作=埋雷式 + 3×3 格秒杀 |
| 窝瓜（Squash） | **窝瓜 `squash`（新）** | 原版跳 1-2 次；本作简化为一跳一只（见 §4.3） |

> **「即种即生效」设计哲学**：原版 PvZ 的辣椒/樱桃是「即种即爆」的应急卡。本作将一次性爆发植物统一为即种即生效（armT=0），核心理由：
> 1. **用户明确裁决**（2026-09-25）——三新植物不需要武装等待期，种下即处于可触发状态；
> 2. **与地雷的差异化**——地雷有 8s 武装窗口（廉价但有延迟），三新植物无武装窗口（更贵但即时），消费场景自然分层；
> 3. **策略互补**——紧急救场用窝瓜/樱桃（即种即生效）、预谋防守用地雷（便宜但有 8s 延迟），两者互不替代。

### 2.1 基本属性

| 属性 | 值 | 推导 |
|---|---|---|
| **名称 / 代号** | 航椒炸弹（Hangjiao Bomb）/ `type:'pepper'` | 辣椒主题，与地瓜形成「瓜椒双雷」风味 |
| **cost** | **125 阳光** | 地雷 25 + 单排全清溢价；介于地雷（25）与樱桃（150）之间；对齐原版辣椒 125 |
| **种植 CD** | **25s** | 比地雷（20s）更长——全排秒杀必须更稀缺 |

| **armT** | **0（即种即生效，用户裁决）** | 种植即处于可触发状态，无武装等待期；仅保留种植动画 + 爆炸动画 |
| **触发机制** | 同排任意僵尸进入检测范围 → 引爆 | 与地雷同**触发判据**：`\|z.x - pos.x\| < CELL_W*0.55`（≈**49.5px**，CELL_W=90） |
| **范围** | **同排全部僵尸（不限数量、不限列）** | 遍历 `zombies`，`z.row === p.row` 即命中 |
| **秒杀契约** | `killZombie(z)` — 无差别秒杀，无视防御/难度倍率 | 与地雷 v2.1.1 口径完全一致 |
| **一次性** | ✅ 引爆后消失（`p._dying = true`） | |

### 2.2 触发机制（已定案）

种植后即处于可触发状态。每帧检测：同排任意僵尸进入检测范围（`|z.x - pos.x| < CELL_W*0.55` ≈ **49.5px**）→ 引爆全排。与地雷触发判据完全相同，区别仅在于跳过 armT 倒计时——种下即可触爆。

> **裁决理由**：用户明确要求 armT=0。代码实现：种植帧起即走 `updatePlant` 的 pepper 分支（无 armT 倒计时），触发判据沿用 `mine` 的 `Math.abs(z.x-pos.x) < CELL_W*0.55`。

### 2.3 范围定义（精确）

- **引爆判据（＝触发判据）**：`z.row === p.row && Math.abs(z.x - pos.x) < CELL_W * 0.55`（≈ **49.5px**，CELL_W=90），与地雷引爆前的检测判据一致（同判据的三植物：mine / pepper / cherry）。

  > **⚠ 两个像素语义必须分开写（2026-09-25 校准）**
  > - **触发判据** `CELL_W*0.55` = **49.5px**——僵尸要走到多近，才会引爆地雷/航椒/樱桃；
  > - **地雷杀伤半径** `CELL_W*0.6` = **54px**——地雷引爆后实际秒杀的横向范围（`explodeMine` 的 `sameCell` 分支）。
  > 旧稿把两者混写成同一个「≈54px」。更正口径：**凡描述触发判据一律 49.5px；仅描述地雷「命中/杀伤范围」才用 54px**（如 §1.1、§4.2、§5.1 的地雷范围表述保留 54px，因其指的是杀伤半径，非触发判据）。

- **引爆后命中范围（＝杀伤范围）**：引爆后遍历 `zombies`，**仅 `z.row === p.row` 且 `!z.dead` 的全部僵尸**命中，**无数量上限、无列限制**。
- **跨行**：否。仅同排。
- **屋顶（roof）抬升**：命中判定按现有 `explodeMine` 口径处理 `zy` 抬升（`GRID_Y + row*CELL_H + CELL_H/2 - liftX(z.x)`），保证屋顶斜坡下同排语义正确。

### 2.4 秒杀契约

- 调用 `killZombie(z)`（L2214），走完整死亡管道：得分、阶位掉落（`spawnPointDrop`）、死亡爆币特效、尸体零件、分层死亡音效。
- **不参与耐久结算**（与 v2.1.1 地雷消缺口径一致）——铁桶（560hp）/高难度（hard ×1.35、expert ×1.80）下一碰即死。

### 2.5 与其他植物的交互边界

| 边界 | 说明 |
|---|---|
| 与地雷共存 | 两者可同时布置；航椒引爆不会触发相邻地雷（地雷仅在自身检测分支被触发） |
| 与樱桃共存 | 各自独立引爆，无连锁 |
| 武装期被啃 | `dur=300`，啃穿即 `_dying` 消失，不触发爆炸 |
| 铲除 | 走既有铲除返还（按 `Math.max(25, floor(cost/2/25)*25)` → 航椒返 50） |
| 水行/屋顶 | 无特殊地形限制，走 `canPlant` 默认路径（水行需先铺睡莲、屋顶需先放花盆——与普通植物一致） |

### 2.6 视觉效果建议

- **武装前**：红色小辣椒，体型比地瓜略小，呼吸灯微光。
- **武装后**：亮红色，表面火焰纹理动画。
- **爆炸时**：**全排火焰波**（从引爆点向两侧扩散的橙色渐变带 + 粒子喷涌，沿 `p.row` 方向横扫），配合冲击波环 + 震屏 + `SFX.boom()`。
- **Canvas 绘制**：纯色块圆弧手绘风——红色椭圆主体 + 绿色茎蒂 + 火焰色高光（对齐现有 drawPlantInner 风格）。

### 3.1 基本属性

| 属性 | 值 | 推导 |
|---|---|---|
| **名称 / 代号** | 樱桃炸弹（Cherry Bomb）/ `type:'cherry'` | 直译原版 |
| **cost** | **150 阳光** | 对齐原版樱桃 150；面清场定价高于单排清场（航椒 125） |
| **种植 CD** | **30s** | 全表最长 CD——面清场是终极爆发工具 |
| **dur（血量）** | **300** | 同地雷——可被啃 |
| **armT** | **0（即种即生效，用户裁决）** | 种植即处于可触发状态，无武装等待期；仅保留种植动画 + 爆炸动画 |
| **触发机制** | 同排进入**触发判据**范围（±49.5px，`CELL_W*0.55`）即有僵尸则引爆 | 与地雷同判据（像素语义见 §2.3 术语区分） |
| **范围** | **3×3 格（以植物所在格为中心）** | 已定案（Q-2 裁决） |
| **秒杀契约** | `killZombie(z)` — 无差别秒杀 | |
| **一次性** | ✅ 引爆后消失 | |

### 3.2 范围定义（精确）

**范围：3×3 格（以植物所在格为中心）——已定案**

```
        col-1    col     col+1
row-1   [  ]     [  ]     [  ]
row     [  ]     [🍒]     [  ]
row+1   [  ]     [  ]     [  ]
```

- **判定逻辑**：
  ```js
  const dc = Math.abs(colOf(z.x) - p.col);
  const dr = Math.abs(z.row - p.row);
  if (dc <= 1 && dr <= 1 && !z.dead) killZombie(z);
  ```
- **格坐标换算**：`colOf(z.x) = Math.floor((z.x - GRID_X) / CELL_W)`（复用既有 `posToGrid` 的 col 换算，`GRID_X=55`、`CELL_W=90`）。
- **棋盘边缘**：col=0/8 或 row=0/4 时范围自然截断，不做补偿。
- **跨行**：✅ **是**——这是本作第一个跨行秒杀，必须显式处理（现有溅射 L1584、地雷 L1988 均 `row!==` 过滤）。

**为什么不直接用像素半径**：
- 现有 `splash`/`splashRatio` 是「伤害百分比」而非「秒杀」，且不跨行；
- 樱桃是「范围秒杀」，语义更接近「格子区域」而非「像素带」；
- 3×3 格是原版樱桃经典范围，玩家直觉一致。

### 3.3 秒杀契约

- 调用 `killZombie(z)`，走完整死亡管道，与航椒/地雷一致。
- **不参与耐久结算**，无差别秒杀。

### 3.4 与其他植物的交互边界

| 边界 | 说明 |
|---|---|
| 跨行命中 | 3×3 格内所有僵尸（含相邻行）一律秒杀，无数量上限 |
| 武装期被啃 | 啃穿即消失，不爆炸 |
| 铲除 | 走既有返还（`floor(150/2/25)*25 = 75`） |
| 屋顶抬升 | 命中按「格坐标」判定（col/row），天然免疫屋顶斜坡抬升的像素偏差问题 |

### 3.5 视觉效果建议

- **武装前**：两颗小樱桃（深红双球 + 绿色茎连接），微晃。
- **武装后**：樱桃膨大、光泽增强、闪烁提示。
- **爆炸时**：以植物位置为中心，**深红色圆形冲击波**扩散（半径 0→135px，覆盖 3×3 格对角线）+ 大量红/橙/黄粒子四散 + 全屏红光（`triggerFlash('#f44', 0.12)`）+ 震屏（`triggerShake(6, 400)`）+ `SFX.boom()`。

  > **⚠ 为什么是 6 而不是 8（禁止改回 8）**
  > 源码 `triggerShake` 内存在**一次性闸门**：
  > `if(intensity===8 && !loseShakeUsed){loseShakeUsed=true} else {intensity=Math.min(intensity,6)}`
  > 即 **8px 是「失败进屋特写」的一次性保留名额**（`loseShakeUsed` 永久置位）。若樱桃请求 8，会**吃掉该名额**，导致首次爆炸 8px、之后所有樱桃与航椒（请求 7）被永久 clamp 到 6px，手感不一致——该问题已作为 **BUG-02** 修复。
  > **主理人裁决：樱桃定 6，8px 名额保留给失败进屋特写；§G「单次震屏 ≤6px」为全局手感红线。**
  > 文档与代码均以 **6** 为准；若见旧稿写 8，那是已废弃值，**不得据此把代码改回 8**（会直接导致 BUG-02 复发）。

### 4.2 与地雷的差异化定位（核心问题）

**凭什么玩家选窝瓜不选地雷？**

| 维度 | 地雷 `mine` | 窝瓜 `squash` | 判定 |
|---|---|---|---|
| cost | 25 | **50** | 窝瓜更贵 → 必须有更强能力 |
| armT | **8s（有武装等待）** | **0（即种即生效）** | 窝瓜无需等待——种下就跳 |
| 触发方式 | 被动（等僵尸踩） | **主动（跳向僵尸）** | 窝瓜不需僵尸走到格上 |
| 攻击方向 | 自身所在格 ±54px | **同排前方任意距离** | 窝瓜可碾压远处僵尸 |
| 范围 | 同排 ±54px（可能一炸多） | **单体** | 地雷可能多杀，窝瓜永远一只 |
| 位置要求 | 必须埋在僵尸路径上 | **种在后方安全位置即可** | 窝瓜可从 col 0 跳 col 8 |
| 风险窗口 | 武装前 8s | **无（即种即生效）** | 窝瓜无等待风险 |

**一句话差异化**：
> **地雷 = 廉价、被动、近距离、可能一炸多；窝瓜 = 中价、主动跳跃、全行射程、单体锁定。**

**使用场景对照**：
- 地雷适合：前期缺阳光时的廉价防御、预判路线布置、堆叠僵尸群一炸多；
- 窝瓜适合：远处铁桶/路障逼近、前排已失守需从后排出击、精准狙杀特定威胁。

### 4.3 攻击方向判定与行为细节

**方案：种植后立即检测前方最近僵尸，跳起碾压，消失。（已定案：1 次，等僵尸）**

行为流程：
1. 种植后（armT=0，即处于可触发状态），每帧检测同排前方僵尸：`z.row === p.row && z.x > pos.x`；
2. 若有多只，**选择 x 最小（最近）的那只**；
3. 启动跳跃动画（约 0.6s——从所在格跳起、抛物线落到目标位置）；
4. 落地时 `killZombie(target)` + `p._dying = true`；
5. **跳跃中不被啃——该行为仅在「绘制层」成立**：`p.jumping === true` 时改由 `drawSquashJump` 接管绘制，不进入 `drawPlantInner` 的常规绘制；**逻辑层的啃食判定并未排除 `p.jumping`**（即理论上仍可被啃）。实测 0.6s 跳跃窗口内最多损失 **39/400 耐久**（啃速 65/s × 0.6s），远不足以致死，**行为结果与「不被啃」一致、不影响结果**。
   > **实现提示**：因此**不需要**在逻辑层补一句 `if(p.jumping) continue` 之类的排除——那是无收益的额外改动，且与现有实现口径不一致。

**与原版差异（已定案 Q-3=1 次）**：
- 本作简化为**一跳一只后消失**，理由：①降低实现复杂度；②避免「窝瓜清全行」与航椒定位冲突；③单跳更易平衡。

### 4.4 无前方僵尸行为（已定案 Q-4=等僵尸）

**裁决结果：需要看到僵尸才触发。** 无前方僵尸 → 窝瓜进入「待机」状态（视觉微微抖动），一旦僵尸进入前方即跳。若始终无僵尸且被啃死 → 浪费 50 阳光。

### 4.5 实现要点（伪代码）

```js
// updatePlant 新增 'squash' 分支（armT=0，即种即生效，无倒计时）
if (!p.jumping) {
  // 找同排前方最近僵尸
  let target = null;
  for (const z of zombies) {
    if (z.dead || z.row !== p.row || z.x <= pos.x) continue;
    if (!target || z.x < target.x) target = z;
  }
  if (target) {
    p.jumping = true; p.jumpT = 0;
    p.jumpTarget = target;          // 存引用，需处理目标中途死亡
    p.jumpFromX = pos.x; p.jumpFromY = pos.y;
  }
} else {
  p.jumpT += dt;
  const progress = p.jumpT / 0.6;   // 0.6s 跳跃时长
  // 绘制侧据 progress 插值窝瓜抛物线位置
  if (progress >= 1) {
    if (!p.jumpTarget.dead) killZombie(p.jumpTarget);
    p._dying = true;
    // 落点尘土 + 震屏
  }
}
```

**关键注意**：
- 跳跃期间目标可能被其他植物打死 → 落地时 `if(!dead)` 守卫，窝瓜仍消失（简化处理）。
- `p.jumping / p.jumpT / p.jumpTarget / p.jumpFromX / p.jumpFromY` 为新字段，统一在 `spawnPlant` 工厂或首次使用时挂载（避免调用点内联补挂，遵循 P1-B 约定）。

### 4.6 视觉效果建议

- **外观**：大型窝瓜/西葫芦——深绿色椭圆体 + 黄色底面 + 一对怒目。
- **待机（武装后）**：微微上下弹跳，蓄势待发感。
- **跳跃动画**（三阶段）：压缩（0–0.15s 原地压扁蓄力）→ 起飞（0.15–0.4s 抛物线升空 + 尘土）→ 下落（0.4–0.6s 加速砸向目标）。
- **落地**：尘土 burst + 震屏 + 冲击波环（约 60px 半径）。
- **音效**：跳跃「嗖」声（可复用 `SFX.melonThrow`）、落地低沉「咚」声（建议新增 `SFX.squash`，见 §7.3）。

## §5 三植物横向对比

### 5.1 价格 / CD / 装填梯度

| 植物 | type | cost | 种植 CD | armT | 触发 | 范围 | 秒杀数 |
|---|---|---|---|---|---|---|---|
| 地雷（现有） | mine | 25 | 20s | **8s** | 被动踩中 | 同排 ±54px | 1~N（堆叠时 N>1） |
| **窝瓜** | squash | **50** | **15s** | **0** | 主动跳跃 | 同排前方任意 | 1 |
| **航椒** | pepper | **125** | **25s** | **0** | 被动踩中 | 同排全部 | N（不限） |
| **樱桃** | cherry | **150** | **30s** | **0** | 被动踩中 | 3×3 格 | M（9 格内） |

**梯度曲线**：
```
cost:   25 ─────── 50 ─────────────────── 125 ── 150
        mine     squash                  pepper  cherry
cd:     20s       15s                     25s     30s
armT:   8s        0                       0       0
        ↑唯一有武装  ↑三新植物即种即生效——更强/更贵的合理性来源
范围:   点        线（全行·单体）          线（全行·全目标）  面（3×3）
```

- **armT 梯度（关键差异）**：地雷 8s 是唯一有武装等待的——更便宜但需预判；三新植物 armT=0（即种即生效）——更贵但即时。
- 地雷 → 窝瓜：价格 ×2（25→50），获得主动跳跃 + 全行射程 + **无武装延迟**，但失去多目标可能。
- 窝瓜 → 航椒：价格 ×2.5（50→125），获得全排秒杀，但失去主动触发（等踩）。
- 航椒 → 樱桃：价格 +25（125→150），获得跨行 3×3 面清场。

## §7 风险与注意事项

### 7.1 平衡性风险

| 风险 | 等级 | 说明 | 缓解措施 |
|---|---|---|---|
| **航椒全排清场过强** | ⚠️ 中 | 125 阳即种即生效清一整排，5 行窄棋盘上可能让后期防线过度依赖航椒 | CD=25s 唯一硬限制；若过强优先上调 cost 125→150 或 CD 25s→30s |
| **樱桃 3×3 即种即生效覆盖过大** | ⚠️ 中 | 3×3 覆盖 9/45=20% 棋盘，即种即爆可能一次清场过多 | CD=30s 限制；若过强优先上调 cost 150→175 |
| **无武装时间削弱策略预判** | 🔵 低 | 即种即生效降低「提前布置」的策略深度，玩家更倾向应急堆砌 | 由 cost/CD 承担稀缺性（对比地雷 25阳/8s vs 航椒 125阳/0s），消费分层清晰 |
| **窝瓜与地雷内卷** | 🔵 低 | 定位明确差异化（被动 vs 主动、近距 vs 全行、有武装 vs 无武装），不易互相替代 | 若窝瓜使用率远高于地雷 → cost 50→75 |
| **四张一次性卡的槽位占用** | 🔵 低 | 卡槽最多 10 张，四张一次性卡可能占用过多 | 健康的构筑取舍，由玩家自行权衡 |

> **实测校准（2026-09-25 · `production/v22-balance-profile.md`，480 局）**：航椒与樱桃**均未见过强**（失守率差 0.00pp、时长压缩 0.4%，远低于阈值）⇒ **上表「过强」两条的缓解抓手（cost 125→150 / CD 25s→30s / cost 150→175）均未触发，维持 125/25s 与 150/30s 不变**。
> **附带观察（非缺陷，本轮不动）**：应急型打法下航椒/樱桃出现 0 次购买，提示 125/150 定价可能**偏冷**而非过强——属定价策略议题，**不在本次修订范围内**，需另行派单跟进，暂列「待后续观察」。
