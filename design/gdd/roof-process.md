## §0 一句话结论

**泳池用「行级常量 + 睡莲垫实体」把曾经的 C 档降维成了可行性 A/B 档；屋顶此刻做，同样可以靠「花盆依赖格 = 睡莲垫的实体占位复用」这条 80% 的现成降维路径吃到红利，但屋顶的**第二个**差异化支柱（抛物弹道）是泳池没碰过的**真·弹道语义改动**，它是屋顶档位跃迁的分界线——A 档（纯皮）约 30–60 行零风险可做，B 档（+一款投手/抛物线）约 150–220 行值得做，C 档（完整屋顶）约 400+ 行且投入产出比差，不建议。**

## §1 屋顶地形在《植物大战僵尸》原版的机制真相

### 1.1 核心地形差异：斜坡坡度 → 双语义

原版屋顶（PvZ 4-x / 5-x 段位）的差异核心是**场地带坡度**，它同时影响两件事：

| 机制 | 原版真相 | 影响面 |
|---|---|---|
| **坡度 → 直线弹道失效** | 豌豆/西瓜等直线子弹沿水平射出，在坡上因高度差打不中坡位的僵尸（尤其挥到的前提是**高度对齐**） | 这是屋顶**标配投手类植物**（卷心菜投手 Cabbage-pult、西瓜投手 Melon-pult、玉米投手 Corn-pult）的经济与操作理由——抛物弹道无视坡度，是屋顶的**主导解法** |
| **坡度 → 可部署行高度** | 原版屋顶行与行之间真实存在 Y 偏移（视觉上坡道逐行抬高，近端/近家门口低、远端/僵尸来向高） | 影响湛蓝（水生）类比、西瓜/卷心菜抛物线落点，以及**种植范围的直观物理位置** |
| **花盆（roof planter）依赖格** | 屋顶**铺砖面不可直接种**，需先在格子放一个「花盆」实体，再在其上种植物 | 这是「先垫后种」的**第二例**——与本项目泳池睡莲**同构**（睡莲 = 浮床上垫 → 种植物） |
| **投手类植物** | 卷心菜（50 费）、玉米（100 费）、西瓜投手（300 费）等，抛弧线命中，单目标或多目标 | 原版屋顶的**新内容载体 + 弹道新语义的化身** |
| **风/天气主题差异** | 原版屋顶分「白天屋顶」与「夜晚屋顶」（黄昏屋顶）两套，夜晚套用月光滤镜；整体是**空中场景**的氛围差异（无普通草坪的地面植被） | 主题层差异化 |

### 1.2 屋顶 = 泳池「空间轴」的姊妹，但调料完全不同

| | 泳池（本项目已做，方案 A） | 屋顶（本分析对象） |
|---|---|---|
| 空间轴表达 | **地形成本**：水格 = 25/格的睡莲税 | **部署依赖**：花盆格 = 先放盆再种（花盆若与睡莲同模式，则同样是"占位实体 + 25 左右税"） |
| 真正的新机制 | 无（睡莲是载体，无攻击；水面渲染是皮） | **弹道轴**：抛物 vs 直线（若走 B/C 档） |
| 新卡片 | 睡莲 ×1 | A 档零新卡 / B 档 +1 投手 / C 档 +2~3 投手 |
| 差异化核心 | **空间轴**（可部署面 −40% + 水税） | **弹道轴**（抛物线新打法）+ 坡视觉（美学） |

> 注意：L3 判 C 档时原话是「屋顶需要弹道语义…花盆依赖格，>150 行」。**泳池落地后，花盆依赖格这一半已被睡莲占位实体解了**；剩下需要单独评估的只有「弹道语义」这一半——这是本分析的核心焦点，见 §2.2。

## §2 对照本项目现状逐一映射（重点）

> 逐条给出「现能否做 / 缺什么 / 成本量级」。行号以 code-map（v1.2.1）为准。

### 2.1 种植校验：花盆依赖能否像睡莲一样用实体占位物降维？

**结论：能。这是本线最大的降维红利，几乎可 1:1 复用泳池已落地的睡莲路径。**

| 项 | 睡莲（泳池已做） | 花盆（屋顶待做） | 映射 |
|---|---|---|---|
| 数据形态 | `type:'lilypad'` 真实实体，同格与上覆植物分层（plants 数组） | `type:'planter'` 真实实体，同上 | **同构**：plant 数组加一个 type 分支 |
| 行依赖 | `WATER_ROWS=[1,3]`（L38 常量） | 屋顶**全 5 行**都需盆（或设 `ROOF_ROWS`），比泳池更简单——**不需要行级区分，全场地规则** | 反而更简单（无需区分哪些行是屋顶） |
| 种植校验 gate | L686–L689：`level.water && WATER_ROWS.includes(row) && type!=='lilypad' && !有lilypad → deny`；`level.water && !水行 && type==='lilypad' → deny` | 同为两分支：`level.roof && 无盆 && type!=='planter' → deny`；`有盆 && type==='planter' → deny` | **几乎逐行照抄**，只是把 water→roof、lilypad→planter |
| 铲子交互 | L686 铲垫语义：「铲子作用于最上层实体」（level-4 E4：铲上覆植物保留垫 / 空垫删除） | 完全同理 | 零新逻辑，吃既有实现 |
| 啃食语义 | 甲案：先啃上覆植物、空垫被啃 → 垫销毁（updateZombies 倒序遍历） | 可完全复用甲案 | 零新逻辑 |

**成本量级**：
- 新增 `ROOF_ROWS`（或直接 `roof:true` 全场地）常量：1 行
- `onClick`（L620–L705）种校验 3 处分支改/增：约 6–10 行（照抄泳池两分支 + 「有盆才能种」判定）
- `drawPlant` 系列（L1492–L1628）加花盆绘制分支：约 +15–25 行（绘制一个瓦盆/托盘轮廓，复用睡莲的底层铺垫绘制模式）
- `LEVELS[5]` 加键 + `roof:true`：数据，约 60–80 行（含波次表草稿）

> **这是 A 档的最小骨架，也是 B/C 档的底层地基**。花盆依赖格 ≈ 睡莲垫「换皮直用」，成本约 30–70 行（含新卡 planter 全链路）。

### 2.2 弹道系统：抛物弹到底要不要做？ vs 只做地形皮留直线

**这是屋顶线的分水岭，必须先拍板。**

| 现状（直线弹道） | 抛物要改什么 | 成本量级 |
|---|---|---|
| `updateProjectiles` L1010–L1036：`pr.x += pr.vx*dt`，y 恒定（仅发射 y 偏移），命中 = 同 row + y-window（`Math.abs(zy-pr.y)<32`）+ x-window | 给弹道对象加重力项：`pr.vy`（初速上抛）+ `pr.y += pr.vy*dt; pr.vy += g*dt`；命中判定从「y-window」改为「投影 x + 弧线在当前 x 的高度 vs 目标 y」，或简化成「弧线经过目标行高度窗口」 | `updateProjectiles` 改 8–15 行；`drawProjectile` 不变（仍画圆，只是 y 动，L1692–L1716 已支持任意 y 位置绘制） |
| 命中逻辑依赖 per-row 固定 `zy`（L1017） | 抛物投手需「落点 = 目标格 Y」，命中可在 x 进入范围时按目标行 y 判定（复用现有 window，把 y 判定放宽或对齐弧线最低点） | 8–12 行 |
| 弹道对象字段 `{vx, dmg, row, type, splash}` | 投手弹加 `{vy, g}` 字段 | 各发射点 +2~3 字段/次 |

**评估**：抛物本身**不触碰僵尸/种植/波次任何系统**，改动孤岛在 `updateProjectiles` + 发射点两处。技术上中等，不是"重写弹道引擎"，而是"给此类型弹加一个重力 y 分量"。

**两条路线对照**：

| 路线 | 做法 | 优点 | 代价 | 语义 |
|---|---|---|---|---|
| **R1 只做地形皮、弹道保持直线（低配）** | 屋顶斜坡视觉 + 花盆依赖格，但豌豆/西瓜仍直线水平飞（视觉上横穿坡上空，不真实但可玩） | 成本极低（A 档 30–60 行）；不动弹道；测试影响小 | **失去屋顶最大差异化支点**；"斜坡上飞直线子弹"视觉上会有穿帮感 | 弹道语义不变，坡度是纯装饰 |
| **R2 做抛物线（中配，推荐入门）** | 花盆 + 一款投手类植物落地抛物 + 现有直线弹（豌豆等）在屋顶场景可选择保留或仅对投手做弧线 | 拿到"抛物 vs 直线"的新打法，是屋顶真正的差异化；改动孤岛可控 | 需新增投手植物类型（见 §2.3）+ 弹道力改动 | **弹道轴正式成为屋顶第二支柱** |

> **策划判断**：屋顶若走 R1（纯皮），等于做了一个"只是换色斜视角的泳池"——水税换成盆税、水面换成坡，**玩法轴没有一寸前进**。这不是用户要的差异化。**至少要 R2（B 档）才值得立项。** 详见 §4。

### 2.3 投手类植物：新增植物类型牵涉多大？

**现状**：`CARDS`（L147–L157）全为直线攻击植物；`updatePlant`（L926–L968）攻击分支按 `type==='pea'|'double'|'melon'|'mine'` 走；绘制 `drawPlantInner`（L1492–L1628）按 type 分支。

若引入「投手」（如卷心菜投手 / 西瓜投手翻版）需新增的关键链：

| 链路 | 现状位置 | 新增类型改动 | 成本 |
|---|---|---|---|
| CARDS 数据 | L147–L157 | +1 卡（费用/CD/damage 字段）；卡片栏 7→8 | 数据 ~5 行 + 卡栏绘制布局微调（drawCardBar L1803–L1852，热键 onKey L737–L790 上界） |
| 攻击逻辑 | `updatePlant` L936–L950 | 加 `type==='pult'` 分支：CD、DPS、发射抛物弹（带 vy/g） | +12–18 行 |
| 弹道 | `updateProjectiles` L1010–L1036 + `drawProjectile` L1692–L1716 | 抛物弹类型分支（新增 type 如 `'cabbage'`）+ 重力更新 + 绘制（圆/小火箭） | +15–25 行 |
| 绘制 | `drawPlantInner` L1492–L1628 | 投手外观分支（炮筒/角）+ 抛出动画 | +20–35 行 |
| 音效 | `SFX` L440–L513 | 投手抛掷音（复用 melonThrow 或新键） | +1 键 ~3 行（走 `SFX.melonThrow` 路线则零新增） |

**评估**：新增一款投手全链路约 **70–110 行**（含抛物弹），是 B 档里最贵、但也是收益最高的一块。**不是"新系统"，是"已有弹道/绘制/音效多一个类型分支"**——架构上完全在现有"读 type 做分支"哲学内，不违背零依赖。

### 2.4 渲染：屋顶坡度视觉（透视/倾斜）改造成本

| 项 | 现状 | 坡度视觉成本 |
|---|---|---|
| `drawGameWorld` L1311–L1412 | 平面棋盘，逐行 `GRID_Y+row*CELL_H` 平铺；水面分支 L1320 | 若只做「**墙面砖纹 + 远景城垛剪影**」这类**非透视**皮肤：零几何改动，仅在棋盘底色/纹理上叠新图案，**+15–30 行绘制** |
| **真实透视/倾斜**（行逐行抬高、Y 偏移随 row 变化） | 所有绘制都假设平面 `gridToPos`（L207） | **一旦行间 Y 偏移非恒定，`gridToPos` 就要改成 per-row 偏移**。这颗雷波及：种植命中（posToGrid）、弹道 y-window 判定（L1017 zy 假设）、僵尸行进 y（updateZombies）、尸体/血条（drawZombie L1629–L1691）——**牵一发而动全身**，估 150–250 行且大量测试重写 |

**关键取舍**：
- **轻视觉（推荐）**：`gridToPos` 保持平面，只做「砖瓦棋盘配色 + 屋顶装饰（烟囱/瓦楞横线）+ 天空/背景换色」→ **A 档的零几何成本皮肤**。玩家看到的只是一个"长得像屋顶"的场地，但机制是平面泳池化的花盆规则。
- **重视觉（成本爆炸）**：真实 per-row 抬升 → 破坏整个 `gridToPos`/`posToGrid` 平面假设 = **C 档最大成本项，且纯粹为了"看起来像"。**

> 策划判断：**真实透视坡度 = 不值得。** 原版屋顶的坡度是硬核单位距离逻辑，但对 PvZ Lite 这款"几何装饰、几何色块"的画风，`gridToPos` 平面 + 好看的屋顶皮肤完全够用——玩家感知「这是在屋顶上玩」，而"坡度让子弹打歪"这种微观物理在这款休闲简化版里**根本不是用户要的**。

### 2.5 关卡结构：LEVELS 是否足够表达屋顶

| 项 | 现状 | 结论 |
|---|---|---|
| `LEVELS` 键 | L55–L121；泳池加了 `water:true`（L108）布尔开关 + `WATER_ROWS` | 屋顶加 `roof:true`（或复用一种 terrain 枚举）即可，**同构** |
| 高度差/坡度 | LEVELS 无此表达 | **不需要**（见 §2.4：放弃真实坡度/真实弹道高度，屋顶只作为"主题 + 花盆依赖格"表达） |
| 波次表 | 同构 | 照抄泳池/月夜模式 |

### 3.0 引擎触及面诚实审计（B 档·推荐档，含抛物投手）

对照 code-map 逐区块过一遍，屋顶（B 档）真实触及位置：

| 触及面 | 位置 | 性质 | 量级 |
|---|---|---|---|
| `ROOF_ROWS` / `roof:true` | 新常量 L38 附近 + `LEVELS[5]` 键 | 数据 + 1 常量 | 1 + 60–80（波次表） |
| `CARDS` + planter（花盆）+ 投手 | L147–L157 | 纯数据 | ~10 行 |
| 种植校验分支（有盆才能种 / 盆只种地上） | onClick L620–L705 | 逻辑分支（照抄泳池） | 6–10 行 |
| 花盆绘制（占位物） | drawPlantInner L1492–L1628 | 绘制分支 | +15–25 行 |
| 投手攻击分支 + 抛物弹发射 | updatePlant L936–L950 | 逻辑分支 | +12–18 行 |
| 抛物重力更新 | updateProjectiles L1010–L1036 | **真·弹道语义改动** | +8–15 行 |
| 抛物弹绘制 | drawProjectile L1692–L1716 | 绘制分支 | +10–15 行 |
| 屋顶皮肤（砖纹/城垛） | drawGameWorld L1311–L1412 | 绘制分支（轻视觉） | +15–30 行 |
| 卡栏 7→8 布局 / 热键上界 | drawCardBar L1803–L1852 / onKey L737–L790 | 上界微调 | ~5 行 |
| 移除水面逻辑（屋顶非水） | water 相关若复用需隔离 | 分支管理 | — |
| 音效 | 投手复用 melonThrow（零新键）或 +1 键 | — | 0–3 行 |
| **测试** | REG-END-02 平移；新 SMOKE-026「屋顶平衡契约」；投手/抛物断言 | 既定惯例 | 测试扩展 |

**B 档改动面粗估：150–220 行（不含测试）**，其中**抛物弹语义是唯一"动到引擎核心逻辑"的点**（updateProjectiles），其余全是「读 flag 做分支」的既有哲学。

### 3.1 三档对比总表

| 档位 | 内容 | 代码改动量级 | 测试影响 | 新鲜感收益 | 风险 |
|---|---|---|---|---|---|
| **A 轻量版 · 屋顶主题皮** | 屋顶皮肤（砖纹/城垛，平面、无真实坡度）+ 花盆依赖格（占位实体）+ 花盆卡，**弹道保持直线** | **30–60 行**：常量 + 种植校验分支 + planter 新卡全链路 + 皮肤绘制 | 现有 REG 大体兼容，仅 REG-END-02（上界）平移 + SMOKE-026 屋顶契约；**弹道/僵尸零触碰** | ★★☆：换皮感强，玩法轴 ≈ 泳池换主题 | 低：几乎零弹道风险；但收益也低 |
| **B 中量版 ·（推荐）** | A 全部 + **一款投手类植物 + 抛物弹道落地**（抛物线成为屋顶第二支柱） | **150–220 行**：A 的地基 + 投手全链路 + 抛物重力 | **动到 updateProjectiles** ——现有 PLANT/弹道相关 REG 中 3–5 条 y-window 断言假设需复核（L1017 `zy` 固定行 y，投手弧线会改这条路径；直线弹路径若保留则零影响） | ★★★★：弹道轴新打法 = 真差异化；花盆税 + 抛物投手双新 | 中：弹道改动孤岛化（只 updateProjectiles），可控；需一条抛物命中行为断言兜底 |
| **C 重量版 · 原版完整屋顶** | B 全部 + **真实坡度透视（per-row 抬升）+ 弹道对坡度的真实高度影响 + 多张投手卡（卷心菜/西瓜投手/玉米等）** | **400+ 行**：`gridToPos`/`posToGrid` 平面假设被破坏（L207 → per-row 偏移），牵动种植/弹道/僵尸/尸体/血条**全链路** | **近半 REG 断言的行进/高度假设失效**（L1017 zy、gridToPos、僵尸 y）——需大量重写，S 护栏拆白建 | ★★★★★ | **高**：与"单文件零依赖最小改动"哲学冲突；真实坡度微观物理不是本作定位；投入产出比最差 |

> **推荐：B 档（中量版）作为立项基线。** A 档只是"换皮泳池"（触发 §4 的差异化警告），C 档成本爆炸且收益错位。若用户只想低成本体验"屋顶氛围"，A 档也可先做一版探温，但作为正式关卡不建议停在 A。

## §4 关键建议：屋顶 vs 泳池的差异化（策划判断）

### 4.1 泳池已把「空间轴」吃完——屋顶不能再蹭

泳池 = **空间轴**（地形成本：水税 25/格 + 可部署面 −40%），这是本作第一个"借地形改变决策"的关卡。屋顶若只做「花盆依赖格 + 屋顶皮」，本质上是一次**换主题的水税复刻**：

| | 泳池 | 屋顶（若只做 A 档） | 玩家感知 |
|---|---|---|---|
| 新增部署成本 | 25 税/水格 | 盆税（约 25）/全格 | **一样的"多花钱先放载体再种"** |
| 差异化机制 | 水面不能直种 | 屋顶不能直种 | **几乎相同** |
| 新打法 | 无 | 无 | **感觉在做泳池第二遍** |

### 4.2 屋顶的正确差异化核心：弹道轴

屋顶真正的、泳池没有的东西是**抛物弹道**——它同时带来：
1. **新操作语义**：投手无视坡度/前排、抛射落点选位，改变了"直线对射"的心智；
2. **新解空间**：抛物线可越过高威胁前排直接砸后排/空地僵尸，与现有直线豌豆形成**互补战术层**（不取代，新增一维）；
3. **视觉新鲜**：抛弧线的弹道本身就是差异化的"看得见的机制"。

所以**屋顶应主打「弹道轴」，而非「地形税」**。花盆依赖格降级为"氛围 + 轻度成本"，真正的玩法增量 = 投手 + 抛物。

### 4.3 一句话定义屋顶

> 「同一张棋盘，直线对射之外，多一种**抛物线投手**的打法，外加屋顶砖瓦的皮和花盆依赖的仪式感。」

这保证了屋顶 ≠ 换皮泳池，也不触碰 C 档的真实坡度成本。

## §5 已知风险与取舍

| 风险 | 诊断 | 缓解 |
|---|---|---|
| **B 档动了 updateProjectiles**（抛物重力），现有 PLANT 组 3–5 条弹道断言（y-window 固定行 y）可能漂移 | 抛物只对新增投手弹类型生效；**现有 pea/melon 直线弹路径若保留原逻辑**，则老断言零影响；仅需一条「投手抛物命中行为法」新断言 | 弹道改动走「按 type 分支」，不重构直线路径 |
| **抛物命中手感**：弧线 vs y-window 判定不精确，可能出现"看得到但打不到" | 命中判定需与弧线视觉效果对齐 | 简化判定：x 进入目标列范围且弧线当前 y 落在目标行窗口内即 hit；Playtest 校准抛速/重力 |
| **卡片栏 7→8 布局**：8 张可能挤占、热键需扩展 | drawCardBar/onKey 上界微调 | 参考泳池 6→7 的既有做法，+5 行 |
| **屋顶皮肤观感**：平面皮肤可能被玩家识破"不是真斜坡" | 冲突感集中在直线弹横穿坡上空 | B 档已用"直线弹 + 投手兼有"消化——直线弹打低处、投手打高处，观感合理 |
| **追加水逻辑隔离**：屋顶关 `level.water` 应为 false，需确保 water 分支不误触发 | 屋顶若复用 flag 体系须明确 terrain 互斥 | 采用 terrain 枚举（`'lawn'|'pool'|'roof'`）或独立 `roof:true` 且保证 water 全关关闭 |
