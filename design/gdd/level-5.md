## §1 概述

### 1.1 本关定位

| | L3 月夜草坪 | L4 泳池 | **L5 屋顶（本关）** |
|---|---|---|---|
| 教学定位 | 毕业关：护甲威胁 | 进阶二幕：空间轴（水税）| **决战二幕：弹道轴（抛物 vs 直线）+ 全场地盆税** |

| 僵尸种类 | 4 种全员 | 复用 4 种全员 | **复用 4 种全员（零新增、零变体）** |
| 波次 / 总量 | 7 波 / 33 只 | 8 波 / 38 只 | **9 波 / 42 只** |

| 卡片集 | 6 张 | 7 张（+睡莲）| **9 张（+花盆 + 投手）** |

### 1.2 目标体验

一句话：**「直线对射的世界，多了一种抛过墙头砸下来的投手打法，而每一格都得先垫盆才能种」**。

- 玩家带 L4 的阵容记忆进入 L5，W1–W2 先体会「所有格子都要先放盆」的新规则——比泳池更普适的「先垫后种」（泳池只有 2 水行，屋顶**全 5 行**都要盆）；
- W3 第一次大波用 fast 教会玩家：**光靠直线豌豆在盆税棋盘上会被拖垮，抛物线投手是屋顶的解法**（抛物线可越过中前排快速砸到后排）；
- 中段通过 W4–W5 反复横跳，玩家自发收敛到「直线植物守前排 / 投手抛后排 / 向日葵与经济集中在已铺盆行」的分工；
- W9 双铁桶终波（单波 2480 hp，与 L4 持平）在盆税 + 抛物打法双重压力下收束全关。
- **屋顶轮廓（v1.3-M4）**：场地从**左往右先斜升（斜坡段 col0–4）、后水平（平台段 col5–8）**，对齐 PvZ 原版屋顶的连续坡面——「在斜屋顶上打」的参照系由**几何本身**给出（非纯皮肤），见 §3.6。

### 1.3 与 L1–L4 的关系

- **继承**：全部规则机制零改动；植物卡 6 张 + 睡莲全保留（新增第 7 花盆、第 8 投手）；START_SN / LEVELS 完全同构，仅新增 `roof:true` 地形开关 + 盆依赖。
- **递进**：L4 空间轴（水税/可部署面 −40%）→ **L5 弹道轴（抛物新打法）+ 全场地盆税**。僵尸威胁维度在 L3 已满配，L5 不加僵尸维度，难度增量由「全场地盆税 + 弹道新操作」支付。
- **解锁链**：L4 通关 → L5（`unlockedLevel` 自动支持）；`?level=5` 直进由既有上界校验自动扩展（上界 = LEVELS 键数 4→5）。

## §2 玩法目标与设计支柱

### 2.1 本关考验玩家什么新能力

| 新能力 | 触发场景 | 支撑机制（已存在 + 新卡）|
|---|---|---|
| **全场地盆税部署规划** | 随机行刷怪下，**每一格**种植前都需先放盆（含植物费用的叠加成本） | 花盆（25 费 / 建议 5s CD）：全格前置依赖；W3 前须完成首轮铺盆 |
| **抛物打法选位** | 直线豌豆在盆税棋盘上前排受限，投手可抛过后排 | 投手（150 费 / 2.0s CD）：抛物线命中，无视前排阻挡，后排补刀 |
| **直线/抛物分工** | 5 行 × 直线(前排)+抛物(后排)双解法 | 豌豆/双发/西瓜（直线）+ 投手（抛物）并存的互补战术层 |
| **9 波资源规划** | 总时长 ≈5 分钟，系列最长 | 葵 4–5 张 + 铺盆先后顺序的经济线（推导见 §5）|

### 2.2 设计支柱（4 条，本 GDD 数值决策的裁判标准）

1. **「抛物是答案，不是玩具」** —— 投手的抛物线是屋顶的**主导解法**，不是"多一张卡"的可选体验。任何"投手可有可无""直线也能无脑过"的评价都指向数值失衡。让 W3/W9 有必靠抛物才舒服处理的场景（后排/越前排）。
2. **「先垫盆，再谈输出」** —— 盆税是屋顶的**认知与预算门槛**，难度全部通过「先放 25 盆再种」的部署顺序 + 盆税占比表达，不改任何机制数值。全场地盆税比泳池水税更普适，是本关"看起来熟悉、体感全新"的来源。
3. **「直线守前、抛物压后」** —— 引导（不强制）的分工：前排用直线植物（成本低、直接对射），后排/越前排用投手（抛物线、灵活但贵）。双解法互补而非替代。
4. **「僵尸复用，机制唯一」** —— W1–W9 的僵尸构成大量复用 L4 同位波，认知预算全部花在「盆税 + 抛物」两个新规则上；新鲜感唯一来源 = 弹道轴 + 全场地盆税 + 双桶终波。若构成也翻新即 L3 支柱 3 警告过的认知过载。

### 2.3 玩家心理映射（SDT）

| 心理需求 | 本关供给 |
|---|---|
| 胜任感 | W9 双桶压轴击杀 +「我能在全格需盆的棋盘上用抛物线打出 L4 的操作」|
| 自主性 | 5 行 × 直线/抛物双解法 + 铺盆顺序 = 组合空间 > L4 |
| 心流 | W1–W2 盆税观察窗 → W3 首峰（抛物教学）→ W4/W5 渐进 → W6 二幕 → W7/W8 彩排 → W9 峰值，约 5 分钟内完成两个完整紧张-释放循环 |

### 3.1 降维设计：花盆 = 睡莲垫的实体占位复用（已拍板为唯一语义）

用户已拍板「花盆 = 睡莲式实体占位物」路线（roof-process 附清单③），本 GDD **不再给两案**，直接锁定：

**种植规则矩阵（规格侧锁死，不可协商）**：

| 格状态 | 点旧 7 卡（6+睡莲）+投手 | 点花盆卡 |
|---|---|---|
| 陆地格 · 无盆 | ❌ 拒绝（toast「先放花盆」）| ✅ 放盆 |
| 陆地格 · 有盆 | ✅ 种在盆上 | ❌ 拒绝（已占用）|

> 屋顶**全 5 行都需盆**，无需行级区分——比泳池（WATER_ROWS=[1,3]）更简单，不存在"同一行里屋顶/非屋顶混排"。任何拒绝路径零副作用（不扣阳光、不进 CD、不消耗选择态），与泳池 E1/E2 同款。

**啃食/耐久语义（拍板锁甲案，与泳池睡莲同构）**：

| 项 | 花盆（屋顶）= 睡莲垫甲案复用 |
|---|---|
| 数据形态 | `type:'planter'` 真实实体，与上覆植物同格分层（plants 数组）|
| 耐久 | 有独立耐久（建议与普通植物同级，实现侧常量为准，规格不锁值）|
| 啃食顺序 | **自上而下**：先啃上覆植物，植物阵亡后盆保留；空盆被啃 = 盆销毁（复用 updateZombies 倒序遍历，对陆地格严格等价）|
| 上覆植物存续 | 盆在植物在；盆亡不连带（自上而下自然保证）|
| 铲子 | **作用于最上层实体**（与泳池 E4 同款）：铲上覆植物保留盆 / 空盆删除；返还按卡价一半向下取 25 倍数，花盆返 25 |
| 平衡影响 | 屋顶防线可被啃穿 → 盆税可能重复缴（压力真实，全场地比泳池更重）|

### 3.2 投手植物定案（卷心菜投手 cabbage-pult）

**选款理由（在「卷心菜投手」与「西瓜投手翻版」间权衡）**：
- 西瓜（melon）在本作已是一款**直线 + 溅射**强卡，若把屋顶投手做成"西瓜翻版"会造成 **抛物 + 溅射双强势主卡**：一方面挤掉直线豌豆经济位，另一方面"西瓜投手"与"西瓜"观感重复、新鲜度低。
- **卷心菜投手是原版屋顶象征性首卡**（最便宜、单目标、纯抛物线示范），作为屋顶**玩法教学载体**最合适：让玩家先学会"抛物线能单个居中调度"，未来版本（若 C 档）再补多目标玉米/溅射西瓜投手。
- 单目标、无溅射、纯抛物线 → 与现有西瓜（直线+溅射）、豌豆（直线单目标）**三足鼎立**，无主导策略。

**定案数值（可直接抄进实现）**：

| 属性 | 值 | 推导 |
|---|---|---|
| `type` | `'cabbage'` | 新弹道植物类型 |
| 费用 | **150 费** | 介于豌豆 100 与双发 200 之间；抛物优势的合理溢价 |
| CD | **2.0s** | 稳定单发间隔 |
| 单发伤害 | **30 dmg**（无溅射）| 单目标：dps = 30/2.0 = 15 |
| dps / sun | 15/150 = **0.10** | 低于豌豆（20/1.6s=12.5dps → 0.125/sun）但高于西瓜纯单发；抛物灵活性是 0.10 的补偿 |
| 射程 | 抛达同一行任意目标 | 复用 `hasZombieAhead` 目标选择 |
| 弹道 | 抛物线（见 §3.4）| 无视前排，砸后排 |

**定位一句话**：「比豌豆稍贵的、能越过前排砸后排的抛物线单目标补刀手」——屋顶的答案，不取代直线。

### 3.4 抛物弹道规格（给 engineering-lead 的可抄输入 · v1.1 预测提前量修订）

**核心需求**：抛物线能命中同一行**任意距离**的**移动中**目标（全行射程），投手不像直线那样受前排高度/阻挡影响，且**对移动僵尸应接近必中**——这是「抛物是答案」支柱的先决条件（下文命中手感声明）。

> **v1.1 修订依据**：初稿「按目标**当前** x 解算 vy0」被程基岩评估判定为 `PASS + 1 必改 CONCERN`（`docs/architecture/v1.3-roof-projectile.md` §2.3）。量化复算：弹道到第 8 列 `d=720、t≈2.77s`，期间 normal 左移 44px、fast 左移 125px，均超命中窗 ±42px——**按当前 x 解算，移动僵尸必 miss（fast 100%），投手形同虚设**。故本修订**采纳预测提前量修正**为唯一算法。

**规格（play 层意图，最终可实现性以程基岩评估背书）**：

- **弹道对象字段**：`{x, y, vx, vy, g, dmg, row, type:'cabbage'}`（在现有 projectiles 对象上新增 `vy, g` 两字段）。
- **发射**：目标 = 同行首个有僵尸的 x（新增辅助 `firstZombieX(p)`，返回 `z.row===p.row && z.x>pos.x-10` 的 `z.x`，兼读目标 `z.spd`），发射点 = 植物格右缘（x=pos.x+30，y≈pos.y）。
- **水平速度**：`vx = 260`（比豌豆 340 慢，抛物线有可见弧线；数值见 §3.5 微调说明）。
- **重力**：`g = 500`。
- **★ 垂向初速（预测提前量解算式，采纳程基岩 §2.3）**——把 `d` 从「目标当前 x」改为「**僵尸飞行后的预测位置**」：
  ```
  t0   = max(50, target.x - spawn.x) / vx      // 初估弹道时间
  lead = target.x - spd_row · t0                // 预测位置：减掉弹道时间内该行僵尸左移量
  d    = max(50, lead - spawn.x)                // 修正后距离
  t    = d / vx
  vy0  = (zy - spawn.y - 0.5·g·t·t) / t          // zy=本行基线（≈spawn.y 同行，差≈0）
  ```
  其中 `spd_row` = **该行首个目标僵尸的 `z.spd`**；若目标 `eating`（啃食中），`spd` 视为 0（本就静止，直接命中）。`zy=GRID_Y+row·CELL_H+CELL_H/2`（per-row 常数）。
- **每帧更新**：`pr.y += pr.vy*dt; pr.vy += g*dt; pr.x += pr.vx*dt`（仅 `type==='cabbage'` 生效，直线弹 y 恒定）。
- **命中判定**：复用现有双窗口 `Math.abs(zy-pr.y)<32 && Math.abs(z.x-pr.x)<42`（zy 随行定、天然可用）——**配合预测提前量，横向窗口在「下落段」对移动目标自然成立**。命中后 `pr.dead=true`，伤害与爆点同现有。
- **越界**：`pr.y > canvas.height + 40`（新增，兜下落）或 `pr.x > canvas.width+40`（既有，兜抛过头）→ `dead`；命中遍历已按 `pr.row` 过滤，不下穿误伤他行。
- **性能/手感**：单目标单发，无溅射，无额外粒子开销（复用现有 burst）；预测提前量为**每发射一次**计算（非每帧），开销可忽略。

> **命中手感定夺（策划决策）**：本关采用 **「抛物线打移动目标接近必中」** 手感。
> - 理由：与「抛物是答案，不是玩具」支柱绑定——若抛物线对移动目标保持"看得到打不到"的概率 miss，投手立即从"解法"降级为"玩具"，违背支柱 1；屋顶的差异化支点（弹道轴）就塌了。
> - 承载：预测提前量让命中窗对移动目标"几乎必中"（独立于目标选位的战术价值——投手的"贵但必中+越前排"，就是它值 150 费的溢价）；唯一 miss 残留 = 玩家选错目标行（无僵尸可打时 `hasZombieAhead` 已挡）。
> - 与直线弹的关系：不作为新窗口放宽污染直线弹——直线弹仍走自己的横向窗口逻辑，抛物线靠提前量命中，二者手感不互扰（程基岩 §2.3 已证仅放宽窗口救不了移动目标，且会污染直线弹窗口）。

> 规格版本备注 v1.1：初稿「按当前 x 解算 vy0」仅对**静止**（啃食中）僵尸精确命中，对移动僵尸 100% miss，已被程基岩评估驳回。修订后「预测提前量」为**唯一必选算法**；不再保留"接受只打静止目标"的降级选项（那与支柱 1 冲突）。工程侧实现以程基岩 `v1.3-roof-projectile.md` §2.3 为准。

### 3.5 预测提前量对投手数值的影响（DPS / 弹道速度取舍）

预测提前量修正改变了「有效 dps」——这是把投手从"废卡"救回"解法"的关键：

| 口径 | 初稿（按当前 x）| 修订后（预测提前量）|
|---|---|---|
| 对移动僵尸命中率 | normal 100% miss / fast 100% miss | **接近必中**（唯一 miss 残留 = 选错行，已被 hasZombieAhead 挡）|
| 有效 dps（名义 30/2.0s=15 × 命中率）| 实际 ≈0（投手废卡）| **≈15**（命中率→1，与名义持平）|
| 150 费性价比 dps/sun | 名义 0.10 / 实际 ≈0 → **白花钱** | 实际 ≈0.10（低于豌豆 0.125，抛物"必中+越前排"补齐溢价）|

**结论：预测提前量不推翻既有投手数值，反而让它们成立。**
- `150费 / 2.0s / 30dmg / vx260` **维持不变**——初调的数本就基于"抛物理应打得中"的假设，衡量的是"名义 dps"，前提修正后名义即实际，无需重调。
- **不做 DPS 升级**：若因"预测必中"把伤害抬到 40+ 或 CD 压到 1.5s，会与现有直线豌豆（20/1.6s/12.5dps）拉开过大单发价值，又回到「抛物+高伤害双强势主卡」主导策略（正是 §3.2 选款时规避的老路）。抛物 0.10/sun、比豌豆低但"必中+越前排"的定位**保持**。
- **弹道速度 vx260 维持**：预测提前量已补齐移动命中，无需以更快 vx 缩短飞行时间换命中（那会牺牲"可见弧线"的差异化手感）。若 Playtest 反馈远射弧线飞越 canvas 顶（程基岩 §6.4 CONCERN ② 对称弧峰过高手感），回退阀 = 调 `g`/`vx` 让弧更平缓（§9.4 同口径），**不动结构**——该 CONCERN 为美术手感非阻塞项，归 Playtest 校参。

### 3.6 屋顶斜坡地形规格（v1.3-M4 定稿 · C2 连续坡面几何）

> **本节的定性**：v1.3-M3 只改了屋顶**纹理层**（斜瓦带 / 斜缝 / 光渐变 / 城垛），**几何层仍是 9×5 水平矩形**（`gridToPos` 纯平面：x 只看 col、y 只看 row，L232），故玩家读作「平的」。v1.3-M4 把**几何层**改为 **C2 连续坡面**：屋顶轮廓从左往右**先斜升（斜坡段）、后水平（平台段）**，对齐 PvZ 原版屋顶。
> **用户 2026-09-19 拍板**：路线 = **C2（几何连续 · 平滑坡面）**；方向 = **左低右高**（确认没反）；**斜坡段由原 3 列扩到 5 列**；坡度取草图默认口径（总坡 **H=60px**）。**本功能为必做项（非可选优化）**。
> **可实现性依据**：工程侧 `production/v13-m4-slope-eng-assessment.md`（§C 完整 PvZ 化专项 / §D 5 列可行域）+ `docs/architecture/ADR-005-roof-5col-continuous-slope.md`（已落盘 · 参数以此为准）+ `production/v13-m4-c2-5col-impl-spec.md`（施工规格）。本节只锁**设计接口**，不锁实现命名。

#### 3.6.2 几何与绘制规则

1. **映射层（斜切 x 相关映射）**：`gridToPos` / `posToGrid` 改用**同一 `liftX`**；`posToGrid` 反解**必须先由 x 定 col、再减该点 x 的 `liftX(x)` 求 row**（顺序写反／漏减 → 斜坡列点击整体错行，破坏美术命门「看到的斜格 = 点中的格」）。
2. **底部锚定**：屋面底边**统一停 y=600**（恰与卡片栏顶 `CARD_Y` 重合）；抬升产生的**下方空档用檐板色 `#463b2b` 补成屋面厚度**（越靠右越厚，符合斜视屋顶读感）。
3. **顶部天空（无需补块）**：C2 为「**向上抬升**」模型——col0 基线锚定（顶边仍在 y=80），抬升量向平台递增，抬升后的屋面**仍落在全宽天空带 0–90 之内** ⇒ **天空带天然覆盖，无需额外补天空块**。（「斜坡列上方补一小块天空」是 B 档「向下偏移」模型的假设，C2 天然消解；工程已在评估 §D / ADR-005 纠正。）**验收目标「不裂缝、不遮 HUD」不变。**
4. **城垛随轮廓**：**9 座城垛**（约 45×14，每列居中），底边贴合屋脊轮廓 → **5 座沿斜坡段斜线（呈平行四边形）+ 4 座沿平台段水平**。
5. **格子形态**：斜坡段为**平行四边形**（左右竖边 + 沿坡斜顶/底），平台段为矩形；砖缝严格贴格边界 → **仍与格子对齐**（对齐是本作「几何色块」画风下落格直觉的命门）。
6. **瓦带 / 竖缝 / 城垛 / 檐口**：全部按 `liftX` 重写（M3 的 `ROOF_SLOPE=0.18` 旋转带口径在本档**弃用** —— 否则缝↔格错位）。
7. **roof gate**：`liftX` 内以 `level.roof` 前置（L1–L4 恒 0）⇒ **L1–L4 逐字节等价今日、零感知**（既有 gate 惯例：L716/1370/1431/1501/1520）。

### 4.3 预警与节奏机制（全部沿用零改动）

- 大波预警：`big:true` → 剩 ≤2 只先播 2s 预警横幅 + SirenLoop，清场后放出。
- 非大波推进：上一波清空 + 最小喘息（首波前 12s / 末两波 20s / 其余 16s）或 25s 兜底。

### 5.2 startSun=200 的专项推导

1. **盆税前置资金**：屋顶第一课=先放盆。W1 前需 2–3 盆（50–75）+ 首葵或首投手。200 起步 = 2 盆(50) + 首葵(50) + 首投手(150)的存量缓冲，保证首波前能完成「盆+植物」首次部署循环。
2. **隔离变量原则**（承 L4）：L5 新变量 = 全场地盆税 + 抛物。开局更宽 200 把注意力放在学习"先垫盆再种"这一课，而非双重经济压力。
3. **时长补偿**：本关 ≈5 分钟为系列最长，开局宽对后期压力影响小（后期主导项是葵产出与盆税）。
4. **关际手感差异**：L5 差异化已由盆税 + 抛物 + 投手承担，startSun 只做补偿。
5. **风险熔断**：开局过松 → `200→175`；过紧 → `200→225`。单字段，SMOKE-027 T4 独立断言。
6. **序列声明**：startSun 序列 150/150/100/150/**200** 非单调，**刻意的**（L3 下沉为经济考、L5 抬升为盆税补偿），需用户知悉。

### 5.3 盆税经济测算（全场地 vs 泳池水税占比）

| 项 | 泳池（L4）| 屋顶（L5）|
|---|---|---|
| 需垫行 | 2/5 行（水行）| **5/5 行（全部）** |
| 核心火力占用格 | ≈ 每水行 3 输出 × 2 = 6 格 + 陆地行不垫 | ≈ 8–10 个输出位全部需盆 |
| 垫/盆税 = 25 × 占用格 | 6–8 垫 × 25 = **150–200** | ≈ 10–13 盆 × 25 = **250–325** |
| 税占需求比 | ≈11–14% | **≈19–26%**（盆税更重）|
| 税占供给比 | ≈9–12% | ≈15–20% |

> 屋顶盆税占比（~19–26%）显著高于泳池——「屋顶=更重的税型最终关」的量化表达，支柱 2 的精确体现。**风险**：盆税过重让玩家"铺盆太贵不敢铺"。缓解 = startSun 200 + W1–W2 放软 + 盆 5s CD（铺盆不卡手）。§9.4 回退阀可降盆税。

### 5.4 总量 42 的专项推导（反向预算法 + 盆税专项）

- **经济反推（供给侧）**：起步 200 + 自然落阳（≈300s × 2.7/s ≈ 810）+ 向日葵产出（中后期 4–5 葵、需铺盆，按 L4 口径等比 ≈ +700）。总供给 ≈ **1700–1800**。
- **需求测算（火力）**：L4 口径系数 ≈0.124 sun/hp（950/7660），L5 总 hp 10480 → 火力需求 ≈ **1300–1400**。
- **需求测算（盆税专项）**：核心输出 + 经济占用 ≈ 10–13 盆 × 25 = **250–325**。
- **预算比**：≈ 1700–1800 / (1300–1400 + 250–325) ≈ **1700–1800 / 1550–1725 ≈ 1.04–1.16（中值 ≈1.1）**——**低于 L4 的 1.2**，盆税吃掉安全垫，被补偿链路（startSun 200 + 放软开局）部分抵销。**这是本关难度的真实来源：盆税把预算比压到 1.1，操作必须精准。**

> ⚠️ 预算比 1.1 偏紧，低于 L4 的 1.2。若 Playtest 反馈「不够流畅/盆税卡」，优先回退阀：**startSun 200→225 或盆 CD 5s→4s**（不降盆价，保持 25 倍数口径），见 §9.4。

- **历史锚点**：33→38 = +15.2%，38→42 = +10.5%，继续减速——L5 增量难度由盆税与抛物支付，数量只做温和爬升，远离 L2 削峰前红线。

### 5.5 interval 下限=6 的推导

- 承 L3/L4：L5 的难是"更长的作战 + 更重盆税"，不是"更密弹幕"。9 波 × 6 尾重摊薄下终波 8 只实际跨 ≈45–50s——单位时间压力低于 L2 终波，但持续更长、总量更大。
- 契约取 `minInterval ≥ 6`（SMOKE-027 T8）；疲劳回退阀保留终波 6→5 选项。
