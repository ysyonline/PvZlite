## 0. 摘要

- **现状**：12 个合成音效全部工作，但**无背景音乐、无分组总线、无主音量节点**。所有 oscillator 直接 `connect(c.destination)`，静音靠业务侧 `muted` 短路，缺乏统一的混音层。
- **本次补齐**：新增 **10 个音效**（Top3：种植落地强化、卡片冷却就绪、阳光叮声分层）、**1 个大波警报紧张 loop**、**1 条统一主总线结构**、**localStorage 静音持久化**。

> **⚙️ 口径更正（2026-09-16）** —— 本规格撰写于大波预警为 **4 秒**、静音尚未持久化之时。实现后有两处变化，**以下文出现处均以此为准**：
> 1. **大波预警时长 = `WARN_TOTAL = 2 秒`**（4→3→2，用户两次要求缩短）。§A.1 siren 行、§C、§H 等处原「4 秒」均已按 2 秒校正；涉及「4 秒 × N 轮」的 loop 节奏建议需按 2 秒重新推导。
> 2. **静音持久化已落地**（V11-04）：键名 **`pvz_muted`**（非原建议 `pvz.muted`），见 §D.4。
- **音乐方案**：推荐 **方案 C（仅警报紧张 loop）**，理由见 §C。
- **性能预算**：同发 Voice ≤ 12、单帧 AudioContext node 峰值 ≤ 30、音频内存 ≤ 2 MB（噪声 buffer 用完即弃）。
- **风险**：所有 oscillator 直连 `destination` → 一旦加 BGM 或分通道音量，必须重构（见 §D 总线图）。工程同学请注意这是**改造前唯一必须做的第一步**。

## A. 现有音频审计（Current Inventory）

**代码位置基准**：`plants-vs-zombies.html`
**通用工具**：
- `ac()`（L147）：懒初始化 AudioContext，`suspended` 时自动 `resume()`
- `tone(freq, dur, {type, vol, delay, to})`（L155）：单振荡器 + ADSR-lite envelope（attack 12ms、exp decay、无 sustain/release）
- `noise(dur, {vol, delay, lp, hp})`（L170）：白噪 → 可选高通 → 低通 → gain，一次性 buffer
- `gate(key, sec)`（L191）：基于游戏时钟 `gt` 的节流门，防止密集事件糊成噪音
- 顶层异常兜底（L220-223）：所有 `SFX.*` 都用 try/catch 包住，自动播放策略或设备错误不会炸主循环 ✅

### A.2 关键审计发现

**已做对的地方**（值得保留）：
- 用 `gate(key, sec)` 节流高频战斗音效（shoot/hit/death/chomp），避免"糊成一团"；这是 WebAudio 合成音效最容易翻车的点 ✅
- 音效异常被 try/catch 全局兜底（L220-223），自动播放策略失败不会让游戏静默死亡 ✅
- 大波预警 `siren` 采用双音上下交替 3 遍 + 低音尾音，情感传达清晰 ✅
- `noise()` 每次生成新 buffer，用完后 GC，没有 buffer 复用错乱问题 ✅

**发现的问题**（按严重度）：
1. **无主总线**：所有 `g.connect(c.destination)` 直连，无法做分组音量/主音量/BGM 淡入淡出。这是补 BGM 前必须先做的重构。
2. **静音不持久化**：`muted` 是模块级变量，刷新页面丢失。README 待办第 3 条已列。
3. **`SFX.sun` 语义混杂**：既是"阳光叮"又是"菜单点击"。信息不清晰，且被过度使用（每次点关卡、点难度都响），听觉上会被玩家钝化。
4. **`SFX.wave` 与 `SFX.siren` 情感断层**：普通波只有一个低音下沉，大波却有三遍警报——中间的"紧张递增"完全没有过渡。
5. **无 BGM**：长时间对局听觉完全空白，玩家 2-3 分钟后开始"听觉疲劳 → 忽略音效"。
6. **`SFX.deny` 与 `SFX.plant` 太接近**：`plant` 上滑 300→560，`deny` 只有 155——玩家很难靠耳朵分辨"这次种成功了还是失败了"。

## B. 音频缺口清单（Missing，按优先级）

### B.1 P0（强烈建议补，直接影响可玩性）

#### B1 · 种植落地强化 —— `SFX.plant.settle`
- **现状**：只有一个 140 ms 上滑音，缺乏"落地感"。
- **触发**：`SFX.plant` 调用后立即跟一个短噪声。
- **设计意图**：给玩家"种下去了"的物理反馈，让"选卡→点格"两个动作在听觉上完成闭环。
- **音色建议**：
  - 主音：保留原 `SFX.plant`（300→560 sine, 140 ms, vol 0.16）
  - **新增叠层**：`noise(0.06, {vol:0.09, lp:600, hp:100, delay:0.05})` —— 落地"噗"
  - **复用**：✅ 复用 `noise()`
- **实现成本**：一行改动（在 `SFX.plant` 内加一句 `noise(...)`）

#### B2 · 卡片冷却就绪 —— `SFX.cardReady`
- **现状**：卡片从灰白恢复彩色时**完全没有声音**，玩家经常错过冷却就绪。
- **触发**：`cardCD[type]` 从 `>0` 降到 `<=0` 的当帧。
- **设计意图**：**纯信息型**，告诉玩家"这卡又能用了"，不喧宾夺主。
- **音色建议**：
  - `tone(880, 0.09, {type:'triangle', vol:0.10, to:1180})` —— 短促"叮"
  - 高频、短促、音量低（0.10）—— 避免和战斗音效打架
  - **复用**：✅ 复用 `tone()`
- **节流**：每张卡各自 gate（不同 key），冷却就绪不会互相干扰

#### B3 · 阳光叮声分层 —— 拆分"掉落" vs "收集"
- **现状**：`SFX.sun` 一个音色包打天下。
- **触发**：
  - **掉落**（新增）：`effects.push({kind:'sun'...})` 时（L701）
  - **收集**：L330 点击收集时（沿用现音色但**弱化**）
- **设计意图**：让玩家"注意到阳光下落"（掉落叮）而不是"错过阳光就消失"；收集则是爽感的短促叮。
- **音色建议**：
  - **掉落** `SFX.sunDrop`：`tone(1567, 0.08, {type:'sine', vol:0.06, to:2093})` —— 极轻柔、不干扰
  - **收集** `SFX.sun`（改）：保留 880→1350 + 1320 双音，但**总 vol 略降**到 0.10 + 0.07，加 `gate('sunCollect',0.08)` 节流
  - **复用**：✅ 复用 `tone()`

## C. 音乐基调建议

### 三方案对比

| 方案 | 优点 | 缺点 | 实现成本 |
|---|---|---|---|
| **A · 完全无音乐** | 零成本；无音频预算压力；玩家专注音效 | 长时间对局听觉疲劳；无情绪铺垫 | 0 |
| **B · 4 小节 loop 背景** | 完整听觉体验；有情绪曲线 | 合成 BGM 容易听感廉价（尤其无和声编排时）；可能喧宾夺主 | 60-100 行 |
| **C · 仅警报紧张 loop** | 精准打击情绪高点；不动常态音频；玩家"平时安静，警报时震撼" | 常态下依旧无 BGM；只覆盖预警期（**2 秒**） | 20-30 行 |

### 推荐：**方案 C**（仅警报紧张 loop）

**理由**：

1. **PvZ Lite 定位**：零依赖、零外部资源、单文件。方案 B 的 4 小节合成 BGM 很容易做出"电子合成器玩具感"，反而拉低品质感。
2. **听觉心理学**：常态安静 → 警报突然紧张，**对比度更高**，比持续 BGM 更能激活玩家的"警觉反应"。
3. **契合原作品哲学**：PvZ 原版的紧张感也主要靠**音效密度递增**（普通波稀疏、大波密集），而非 BGM 转调。方案 C 延续了这一策略。
4. **不侵入主循环**：只在 `warn.active === true` 期间启动，`warn.active === false` 时立即淡出，对性能几乎无影响。

### C.1 紧张 loop 代码骨架（示意，供工程参考）

```js
// 在 SFX 对象内新增
sirenLoopStart(){
  if(muted) return;
  const c = ac(); if(!c) return;
  // 复用现 siren() 逻辑但改为预警期循环（预警 = WARN_TOTAL = 2 秒）
  // 建议用 setInterval 触发预警期内的多轮警报 + 一次低频尾音
  // 停止条件：warn.active === false 时 clearInterval
}
```

**实现思路**（推荐给程基岩）：
- 复用现 `SFX.siren()` 的 3 遍警报逻辑，但把 `for(let i=0;i<3;i++)` 改成**按固定间隔触发一轮**的 `setInterval`。
- ⚠️ **口径（2026-09-16）**：预警期现为 **2 秒**（`WARN_TOTAL=2`，原规格 4 秒）。原「4 秒 = 3 轮警报」的节奏**需按 2 秒重新推导**（2 秒约 1–2 轮 + 收束），与 §B7 的 `SFX.bigWaveImpact` 衔接。
- **必须**：`warn.active=false` 时 `clearInterval` 并加 200 ms 淡出，避免预警结束瞬间"音频断裂"。
- **必须**：如果玩家按暂停键，也要暂停 loop（`clearInterval` 后恢复时从头播）。

### C.2 为什么不选方案 B

方案 B 的 4 小节 loop 在合成器上做出来很容易听成"电子琴"或"游戏机开机音"。除非能加：
- **和声编排**（I–vi–IV–V 进行）
- **音色分层**（低音方波 + 主旋律三角波 + 噪声打击乐）
- **动态混音**（大波时 BGM 音量自动降到 50%）

…才能达到可接受的品质。这些都在 P6 打磨阶段成本不划算，留到 Phase 7 再考虑。

## D. 层级与混音策略

### D.1 总线结构（**改造前必看**）

现状（**所有音效直连 destination，无总线**）：
```
osc → gain → destination
noise → filter → gain → destination
```

**建议改造为**（**这是所有后续音频迭代的地基**）：

```
                ┌── masterGain ─── destination
                │
osc → gain ─────┤
noise → filter →┤
gain ───────────┤
                │
BGM osc ─── gain ┤ (方案 C 未使用，预留)
```

**关键 node**：
- `masterGain`：主音量总闸（默认 1.0，可后续接音量滑块）
- `uiGain`：UI 音效总线（默认 0.8）
- `battleGain`：战斗音效总线（默认 1.0）
- `eventGain`：事件音效总线（默认 0.9）
- `envGain`：环境/BGM 总线（默认 0.6，方案 C 时几乎不响）

所有 `SFX.*` 的 gain node 应 `connect` 到**所属分组**，而不是直连 destination：
```js
// 之前
g.connect(c.destination);
// 之后
g.connect(battleGain); // 或 uiGain / eventGain
```

**工程同学注意**：改造这一层是**幂等操作**，不影响现有效果，但**是所有 B 类补齐的前置条件**。建议单独作为一个 PR 先落地。

### D.2 音效分组

| 分组 | 音效 | 最大并发 | 音量优先级 |
|---|---|---|---|
| **战斗**（battle） | shoot, hit, chomp, death.*, boom, melonThrow | **6** | 1.0 |
| **事件**（event） | wave, siren, sirenLoop, bigWaveImpact, win, lose | **4** | 0.9 |
| **UI**（ui） | plant.settle, sunDrop, sun, cardReady, uiClick, shovelArm, shovel, deny | **2** | 0.6 |
| **环境**（env） | 未来 BGM 通道（方案 C 不用） | 1 | 0.5 |

**优先级规则**：同帧多音效并发时，按 **战斗 > 事件 > UI > 环境** 决定保留谁。当前项目通过 `gate()` 节流已隐式实现，未来如做主动"抢占式"混音，按此规则丢弃低优先级。

### D.3 音量矩阵（推荐默认值）

```
masterGain    = 1.00
  ├─ battleGain  = 1.00  ← 战斗音永不衰减
  ├─ eventGain   = 0.90  ← 警报、波次
  ├─ uiGain      = 0.60  ← UI 反馈永远低一档
  └─ envGain     = 0.50  ← 未来 BGM
```

**特殊规则**：
- `muted = true` 时，直接**将 masterGain.gain 设为 0**（而不是业务层短路）。这样 BGM/未来音频通道也能被一键静音。
- 大波预警期间，`battleGain.gain` 可临时降至 0.7（让警报更突出），预警结束后恢复。

### D.4 静音持久化（README 待办第 3 条）· ✅ **已落地**（V11-04）

**键名更正（2026-09-16）**：实际实现用 **`pvz_muted`**（下划线风格，与既有 `pvz_unlocked` / `pvz_highscore` 对齐）。**本节原建议的 `pvz.muted` 已作废**，请勿再按旧键名实现。

**当前实现**（`plants-vs-zombies.html` L175 / L512）：
```js
// 启动即恢复（L175）
let audioCtx=null, muted=storageGet('pvz_muted')==='1';

// 切换静音处即落盘（L512）
storageSet('pvz_muted', muted ? '1' : '0');
```
- `storageGet(key)` / `storageSet(key,val)`（L103/L106）是统一封装，**内部已包 try/catch 静默降级**（写失败不影响对局）。
- 同批落地的还有最高分持久化：键 **`pvz_highscore`**（L123 读 / L136 写，仅刷新纪录时写以减少 IO）。
- 覆盖用例：`tests/harness/cases/SMOKE-020.js`（静音偏好 + 最高分「写入 → 重载 → 读回」全路径）。

**注意**：`localStorage` 在 file:// 协议下**多数浏览器可用**，但 Safari 隐私模式下可能抛错——上述封装已按此处理。

### D.5 频率带宽分区（避免频带打架）

| 频段 | 用途 | 现存/建议音色 |
|---|---|---|
| **低 < 200 Hz** | 警报、失败、爆炸、大波警告 | boom, lose, siren, bigWaveImpact |
| **中 200–800 Hz** | 战斗反馈、种植、啃食 | plant, chomp, shoot, hit, death |
| **高 800–2000 Hz** | UI 反馈、阳光、卡片就绪 | sun, cardReady, uiClick, sunDrop |
| **超高频 > 2000 Hz** | 金属/玻璃碎裂（铁桶） | death.bucket 叠层 |

**原则**：同一时段不要同时密集触发同一频段的多个音效。当前 `gate()` 已隐式满足。
