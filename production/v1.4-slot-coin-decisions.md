## §2 逐条详情

### D-1 ⬜ 初始 5 槽怎么装

- **提案**：玩家自选——进关前新增选卡界面（state=deck），从 9 卡中选**恰好 5 张**；提供「推荐默认卡组」一键采纳（向日葵/豌豆/坚果/双发/西瓜）。备选固定组合被否（丧失构筑深度）。
- **评审**：机制无异议；提醒选卡界面需配套最低合法性校验（→D-8）与键位行为（→D-12）。
- **拍板选项**：A 自选＋默认卡组（推荐）｜ B 固定 5 张无选卡界面
- **你的拍板**：＿＿＿＿

### D-2 ⬜ 第 6-9 槽解锁方式与入口

- **提案**：槽位按 6→7→8→9 **固定顺序**金币解锁（买的是容量）；新槽装哪张卡玩家自选；入口 = 主菜单「卡槽」面板（主）＋ 胜利结算页「解锁第 N 槽」快捷按钮（次），共用同一购买逻辑。
- **评审**：无异议。
- **拍板选项**：A 顺序固定＋双入口（推荐）｜ B 仅菜单入口 ｜ C 仅结算页入口
- **你的拍板**：＿＿＿＿

### D-3 ⬜ 槽价曲线

- **提案**：600 / 1100 / 1900 / 3400（≈1.8× 等比，总 7000）；锚定阳光经济 3×–17× 单株价位；回退阀整体 ×0.7（4900）或 ×1.3（9100）。
- **评审**：复算确认 5 轮毕业稳健（含首杀砍半敏感性），价格不需动。
- **拍板选项**：A 采纳原曲线（推荐）｜ B 自定义数值
- **你的拍板**：＿＿＿＿

### D-4 ⬜ 热键方案

- **提案**：热键绑**槽位**——按 `i` 选中第 i 槽当前装载的卡；未解锁槽的数字键静默无效；与 X/空格/F/M/Esc 零冲突。原案「1-9 直选 CARDS[i]」因卡随槽变而失效。
- **评审**：无异议。
- **拍板选项**：A 绑槽位（推荐）｜ B 其他映射（请说明）
- **你的拍板**：＿＿＿＿

### D-5 ⬜⭐ 首杀判定重构 ＋ 存量玩家初始化（全清单最要紧项，O-2 合并裁决）

- **问题（主理人已实证源码）**：原案首杀币「复用 pvz_unlocked 递增事件」，但写档逻辑被 `if(levelNo+1<=5)` 包裹（L1344）→ **①通关 L5 永不触发，新玩家 500 首杀币静默丢失；②存量玩家（已解锁全关）重玩零首杀**。评审 R-1 判定必须重构。
- **评审修法**：新增持久化字段 `pvz_cleared`（位掩码或数组），胜利时 `!clearedHas(levelNo)` 才发首杀币（关×100）。
- **连带裁决——存量玩家初始化方式**（合并原 O-2）：
  - **A 干净版**：`pvz_cleared` 初始化 = 已通关卡（无任何补发；原提案「不补偿」口径）
  - **B 软着陆**：`pvz_cleared` 留空 → 存量玩家重玩各关首次通关照拿首杀币（全 5 关隐性可得 1500，比原案 B 的 200×关数更平滑）
  - **C 显性欢迎币**：一次性发 200×解锁数（原提案备选，双方均不推荐）
- **评审对 O-2 的分析**：存量玩家可直刷 L5（432/次），farming 效率不低于新玩家，不发币也公平（R-11 确认）。
- **拍板选项**：重构本身 A 采纳（双方一致，建议必选）；初始化 A / B / C 三选一
- **你的拍板**：重构 ＿＿＿ ｜ 初始化 ＿＿＿

### D-6 ⬜ 失败是否作废（原 O-3）

- **提案**：A 胜利提交·失败作废（增赌注、批量低频写 localStorage）｜ B 收集即落盘（零挫败、写频高）。
- **评审**：倾向 A，但**必须补「胜利瞬间 sweep 场上未捡金币自动入袋」（R-2）**——否则通关判定触发时最后掉的金币直接丢失，「刚赢就丢币」与胜利语义矛盾。选 B 则此条自动消解。
- **拍板选项**：A 作废制＋胜利全收（推荐）｜ B 收集即落盘
- **你的拍板**：＿＿＿＿

### D-7 ⬜ 金币掉落不套特效容量守卫（R-3，必须项）

- **问题（主理人已实证源码）**：源码 4 处 effects 500 上限守卫（L1047/1138/1251/1264）。若工程侧照「死亡特效」范式给金币加同样守卫，**大波僵尸群体死亡时（恰是金币最密集时）会静默吞币**，掉了但捡不了。
- **评审修法**：金币生成不设守卫，与自然阳光掉落同待遇，直接 push 进 effects。
- **拍板选项**：A 采纳（推荐，双方技术一致）｜ B 改「击杀即记账、掉落物仅动画」（偏离点击收集立意，备选）
- **你的拍板**：＿＿＿＿

### D-8 ⬜ 选卡合法性校验（原 O-1 ＋ R-5 合并）

- **提案（O-1）**：A 选卡界面硬校验（进 L4 须装载睡莲、进 L5 须装载花盆，否则阻挡并提示）｜ B 放开（无载具必败、玩家自担）｜ C 载具免费预载不占槽。
- **评审（R-5）**：O-1 只管载具不够——「5 张全攻击无向日葵」「全辅助无攻击」也是必败卡组，且在作废制（D-6=A）下白丢一局金币挫败叠加。建议载具保持硬锁，**经济/攻击加软提醒**（弹确认框二次确认放行，不做硬锁以免限制构筑）。
- **拍板选项**：载具：A 硬校验（推荐）｜ B 放开 ｜ C 免费预载；经济/攻击软提醒：要（推荐）/ 不要
- **你的拍板**：载具 ＿＿＿ ｜ 软提醒 ＿＿＿

### D-9 ⬜ 首杀档位（原 O-4）

- **提案**：A 维持关×100（理由：首轮 2615 刚好覆盖载具双槽 1700，进度自洽的关键）｜ B 降为关×60。
- **评审**：复算显示**即使砍半（首轮 1865）毕业仍 5 轮、仍 ≥1700 覆盖载具槽**——降档不致死，但维持 A 不冒险。前提 = D-5 修复（否则首轮实际只有 2115，名义档位失真）。
- **拍板选项**：A 维持关×100（推荐）｜ B 降关×60 ｜ C 其他
- **你的拍板**：＿＿＿＿

### D-10 ⬜ 难度与金币联动（R-4，提案缺项）

- **背景（主理人已实证源码）**：DIFFS 三档（普通 1.0 / 困难 1.35 / 地狱 1.80）只乘僵尸 HP 与速度，不影响金币产出——高难玩家单位时间收益反而更低。
- **评审方案甲（推荐）**：显式声明「金币产出与难度无关」写入设计铁律，防止实现者自行乘系数破坏 §2.3 数值闭环；上线后再议。
- **评审方案乙**：击杀币 ×1.2（困难）/ ×1.5（地狱）（首杀/重复不变），毕业加速、需联动回退阀重算。
- **拍板选项**：A 甲·声明无关（推荐）｜ B 乙·难度系数
- **你的拍板**：＿＿＿＿

### D-11 ⬜ 金币/阳光同点拾取（R-6）

- **问题**：金币与阳光共用 effects 与点击收集范式，同落点重叠时点击可能「只收阳光、金币要再点一下」。
- **评审修法**：点击收集金币**优先于阳光**（金币更稀缺）；金币生成坐标加 ±12px 随机偏移防完全重叠。
- **拍板选项**：A 采纳（推荐）｜ B 不处理
- **你的拍板**：＿＿＿＿

### D-12 ⬜ 选卡界面 Esc / R 键行为（R-7）

- **问题（主理人已实证）**：源码 R 键在任意态触发退出请求——穿透到选卡界面会**直接退出游戏**而非回菜单，违反直觉；Esc 在 deck 态无分支（无取消路径）。
- **评审修法**：deck 态 Esc = 回菜单、R = 回菜单（不触发游戏退出）；play 态语义不变。
- **拍板选项**：A 采纳（推荐）｜ B 其他行为（请说明）
- **你的拍板**：＿＿＿＿

### D-13 ⬜ 金币 HUD 位置（R-8）

- **问题**：现有 stat 栏已接近满高，runCoins（本局）与 pvz_coins（总量）需区分显示，提案未指定位置。
- **评审修法**：金色币标「🪙 本局 +X ｜ 总 Y」（#ffd54a 区别于阳光/分数）；play 态显本局、menu/end 显总量；坐标右上 x≈990 或顶部居中 (500, 8)。
- **拍板选项**：A 右上（推荐）｜ B 顶部居中 ｜ C 其他
- **你的拍板**：＿＿＿＿

### D-14 ⬜ 奖励结算时机（R-13）

- **问题**：首杀币/重复币是战斗内即时显示还是胜利时结算，原案未明确，HUD 数字跳动来源会不清。
- **评审修法**：通关分支统一结算：sweep 场上金币（D-6）→ 首杀（D-5 判定）→ 重复（关×20）→ `pvz_coins` 落盘；HUD 本局币只显点击收集部分，结算页展示含奖励的合计。
- **拍板选项**：A 采纳（推荐）｜ B 其他
