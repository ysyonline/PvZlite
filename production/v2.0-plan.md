## §1 版本定位与范围

### §1.1 版本性质

**结构升级版**。v1.x 系列以「玩法数值 + 测量收口」为主轴，v2.0.0 首次动游戏的**骨架**：关卡组织方式、导航结构、奖励发放模型。三条主线：

1. **菜单模块**：平铺选关列表拆为「主菜单 → 选关界面」两级导航（现状：`state='menu'` 即选关列表，无独立主菜单，L355/L992/L3146）。
2. **关卡结构**：数字关号 `levelNo` 1..5 → `'世界-关号'`（`'1-1'`～`'4-10'`）40 关；4 世界主题（草地/泳池/墓地/房屋）。昼夜结构（已拍板 2026-09-23）：草/墓/房 = 前 5 昼后 5 夜（待最终确认）；**泳池 = 特殊三段**：2-1～2-2 白天、2-3～2-5 黑夜、2-6～2-10 **浓雾黑夜**（白色浓雾遮罩战场，仅可见最左列前半列 + 最右列半列，原版雾关视野效果）。昼夜均为**纯视觉变体**（Q-6 已拍板）。
3. **奖励改版**：每通过 1 关奖励 1 个植物（替代现有 5 关发卡序列）；每个世界 10 关全通另有额外金币。

**本期落地口径（用户原话约束）**：菜单模块做通 + 跑通 1-1；1-2 做占位（点击无响应，反馈形式待拍板 Q-3）；**解锁功能暂不做**；世界 2/3/4 关卡全部占位。数据层、存档迁移、奖励框架本期就位（1-1 的发卡链路真实生效；世界全通金币逻辑落地但本期不可触发——世界 1 未开放全 10 关可玩）。

## §2 玩家流程设计（文字线框级）

### §2.1 全流程

```
打开游戏
  └→ [A 主菜单] --点击「进入游戏」--> [B 选关界面] --点击 1-1--> [C 对局]
                                                        |--失败--> 结算(失败) --返回--> [B]
                                                        └--通关--> [D 结算屏] --「返回选关」--> [B]
                                                                            └--「下一关」--> 占位提示或 [B]
[B 选关界面] --点击「返回主菜单」--> [A]
```

状态机改造：`state` 枚举 `'menu'|'play'|'end'` → **`'menu'`（主菜单）+ 新增 `'select'`（选关）**，仍走 `setState` 统一切换（L361），审计钩子零破坏。备选方案（menu 内加子页 flag）不推荐：绕过 setState 审计面。

### §2.2 [A] 主菜单

| 元素 | 规格 |
|---|---|
| 游戏标题 | Canvas 直绘大字标题 + 副标语（具体视觉待拍板 Q-1） |
| 「进入游戏」按钮 | 共享几何常量（如 `MENU_BTN`），绘制与命中同源；hover 高亮 + `SFX.uiClick()` |
| 版本角标 | 右下角 `v2.0.0`（复用 L52 VERSION 常量） |
| 测试模式提示 | `?test=1` 行为不变（守卫逻辑零改动，L210-213） |

交互：仅一个出口（进入游戏 → select）。本屏不出现关卡数据。

### §2.3 [B] 选关界面

| 元素 | 规格 |
|---|---|
| 「返回主菜单」按钮 | 左上角 |
| 世界区块 ×4 | 世界 1 草地 / 2 泳池 / 3 墓地 / 4 房屋；标注各世界「昼 1-5 · 夜 6-10」（形态待拍板 Q-8：页签 vs 地图） |
| 关卡格子 ×40 | 键名 `1-1`…`4-10`；三态样式——可玩（亮色）/ 占位（灰字 + 「敬请期待」或锁形，待拍板 Q-10）/ 当前 |
| 关卡名 | 世界内显示「第 N 关 · 主题·昼夜」（如「1-3 草地 · 白天」） |

交互：点击 1-1 → `setState('play')` 载入新键位关卡；点击占位格 → 无响应或 toast（待拍板 Q-3）；点击返回 → menu。

### §2.4 [C] 对局

HUD 与玩法逻辑零改动；仅两处：①关卡名展示改 `'w-l'` 格式；②`level` 对象来源改为 `LEVELS['w-l']`（字段名兼容，见 §3）。种植规则、水行逻辑（L849-857/L1665/L2108/L2605 读 `level.water`）、屋顶花盆税全部按字段驱动，不感知键位变化。

### §2.5 [D] 结算屏

- 沿用 v1.9 修复后的 `END_BTN` 共享几何（L48-50 教训：新界面先抽常量再写绘制/命中）。
- 「返回」按钮目标从 menu 列表 → **select 选关界面**。
- 「进入第 N 关」按钮 → 语义改为「下一关 `w-(l+1)`」：本期 1-1 通关后指向 1-2（占位），点击给占位反馈；世界末关（如 1-10）隐藏或改「返回选关」。

### §2.6 URL 直跳（测试基建，保持可用）

- `?level=N`（N 为 1..5 数字）：兼容 shim 映射到 `'1-N'`（映射规则与废弃策略见 §3.5、风险 R-3）。
- `?level=w-l`：新格式原生支持（如 `?level=2-6`）。
- `?test=1` 沙盒行为零改动（不写存档守卫保持）。

## §3 数据模型改造方案

### §3.1 键位与 LEVELS 结构

```js
// 世界主题表（新增，数据注册式，沿 POINT_CONFIG L54-56 工程约束：只加数据不改逻辑）
// 昼夜结构（Q-6 拍板 2026-09-23）：草/墓/房=前5昼后5夜；泳池=2-1~2-2昼、2-3~2-5夜、2-6~2-10浓雾夜
// time 值域：'day'|'night'|'fog'（fog=浓雾黑夜：白色浓雾遮罩，仅见最左列前半列+最右列半列）
const WORLD_THEMES={
  1:{key:'grass',name:'神秘草地',terrain:'lawn',
     dayLawn:['#88c250','#77b042'],   nightLawn:['#6f9f5e','#628f52']}, // 昼色板取自旧 L1、夜色板取自旧 L3
  2:{key:'pool', name:'昏暗泳池',terrain:'water',
     dayLawn:['#5a9e6b','#4f8f5f'],   nightLawn:['#4a7f5a','#3f6f4d']},
  3:{key:'grave',name:'雾夜墓地',terrain:'grave',           // Q-7 拍板：墓碑机制随世界3开放实装，本期字段预留+视觉装饰
     dayLawn:['#7a8f6a','#6b7f5c'],   nightLawn:['#5a6a50','#4d5c45']},
  4:{key:'house',name:'最后一屋',terrain:'roof',            // 复用 v1.3 斜坡/花盆（Q-7 房屋侧沿用推荐）
     dayLawn:['#8a7a5a','#6e5f45'],   nightLawn:['#6a5c44','#564a37']}
};
// 关卡表：键 'w-l'；world/time 可由键推导，显式存一份用于校验与绘制直读
const LEVELS={
  '1-1':{name:'1-1 草地 · 白天',world:1,time:'day',
         startSun:150,armTime:8,totalWaves:5,waves:[/* 旧 L1 波次原样迁入 */]},
  // '1-2' ～ '4-10'：占位项只占键位与元数据，不配 waves（本期不可玩）
};
const LEVEL_INDEX=['1-1','1-2',…,'4-10'];   // 有序列表，绘制/迭代/下一关推算统一走它
```

运行期主键从 `levelNo:number` 换为 `levelKey:string`（`let level=LEVELS[levelKey]` 写法不变）。现有 6 处数字键读写点全部随 M1 改造：菜单点击 L992、URL 参数 L203-207、卡池推导 L291、发卡 L1894、解锁推进 L1917、菜单绘制 L3146。

### §3.2 40 关配置组织（防 40 份重复配置）

三层结构，手写量收敛到「锚点 + 模板 + 覆盖」：

1. **锚点关（5 个，手写波次原样保留）**：旧 5 关的 `waves` 数组是 v1.x 平衡资产，逐字迁移不做数值改动（映射见 §3.3）。
2. **波次模板（每世界 1 套 × 昼/夜微调参数）**：`WAVE_TEMPLATES[world]` 描述该世界的出怪骨架（怪种组合、大波节奏）；`time` 变体通过 `spawnMult/intervalMult` 两参数微调。**夜 vs 昼本期纯视觉（Q-6），模板参数默认昼夜同值**，字段预留以便未来夜玩法定参。
3. **启动期展开**：`materializeLevels()` 在 boot 时对无显式 `waves` 的键做**确定性展开**生成完整配置——同输入同输出、可被脚本整体快照校验。未来 v2.x 补真实关卡时只需把手写 `waves` 填回对应键，展开函数自动让位。

行数账（估算）：主题表 ~25 行 + 模板 ~80 行 + 40 键位元数据 ~80 行 + 展开函数 ~40 行 ≈ **+225 行**，对比 40 份全量手写（~900 行）省约 3/4。

### §3.4 存档迁移与兼容读法

- **新存档**：`localStorage['pvz_progress_v2']` = JSON `{v:2, cleared:['1-1',…], unlocked:'1-N', cardSeen:[…]}`。`cleared` 用集合表达（40 关稀疏通关，替代隐含的数字递增），为「每关 1 植物、重复通关不重复发」（现 T-12 规则，L1893）提供天然判据。
- **迁移规则（单向、幂等）**：读档时若 v2 键不存在且 `pvz_unlocked` 存在 → 旧 `unlockedLevel=N`（N=已解锁最大关号，即 1..N-1 已通关）映射为 `cleared=['1-1'..'1-(N-1)']`、`unlocked='1-N'`，写 v2 键。**旧键保留不删**（回滚 v1.9 旧版后进度无损）。
- **兼容读法（永远向后兼容）**：读档顺序 = v2 键 → 缺失则旧键迁移 → 均无则全新档。`?level=` URL 会话内提升 `unlocked`（现 L205 语义），不落盘，与迁移正交。
- **守卫沿用**：`testMode` 不写任何存档键（L211 现状保持）；无痕模式 try/catch 静默降级保持。
- **本期不做解锁门禁**（X-3）：`unlocked` 字段照常维护，但选关界面不据此置灰（显示样式按 Q-10 口径），为未来解锁功能留好接口。

### §3.5 数字键兼容 shim

`legacyKey(n)= '1-'+n`（n∈1..5）仅用于两处：`?level=N` URL 兼容、迁移函数。其余代码路径一律 `'w-l'`，避免双键真相。旧数字键长期保留还是本版后废弃 → 随 Q-2 一并拍板（建议本版保留、v2.1 再评估废弃）。

## §4 奖励系统改造

### §4.1 每关 1 植物 vs 现有 CARD_AWARD

**推荐：改造 `SLOT_CONFIG.CARD_AWARD`（L91），不新增并行表。**

- 理由：CARD_AWARD 语义就是「按关号通关发卡」，与需求完全同构；差异仅在键位格式（`1`→`'1-1'`）与序列长度（5→40）。新增第三张表会与 CARD_AWARD / DIFF_AWARD（L94）形成三头对照，违反项目「两处真相禁令」（L66 注释既定约束）。
- 改造内容：键位 `'w-l'` 化；序列扩至 40 项；`derivePool`（L287-292，现按 `1..unlockedLevel-1` 遍历）改为按 `cleared` 集合遍历取奖。
- DIFF_AWARD（难度门槛重通发卡）本期**冻结不动**：其键 `'hard:3'` 是旧数字关号，语义在 40 关结构下待未来重定义，登记进 v2.1 备查。

### §4.2 世界全通金币 vs 现有 CLEAR_REWARD per10

**推荐：改造 `POINT_CONFIG.CLEAR_REWARD`（L77-81），`mode:'per10'` → `mode:'worldClear'`，`per10Amount:300` 语义平移为 `worldClearAmount:300`。**

- 理由：per10（累计通关逢 10 发 300）与新需求「世界 10 关全通发金币」触发点几乎重合，改造比双轨并行干净——双轨会在「第 10 关通关」时刻同时命中两条规则，玩家收到两笔来源不明的金币，体验混乱。
- `computeClearReward`（L304-308）改为按「该世界 cleared 数 == 10 且此前 <10」判定；判据直接取 §3.4 的 `cleared` 集合。
- 本期落地状态：逻辑与配置就位，世界 1 无全 10 关可玩 ⇒ 不可触发，M4 用纯函数级测试验证判定正确性。
- 经济影响预估：全游戏金币总增量 4×300=1200，与现 per10 全量口径等额，槽位总价 6400（L88）经济面零冲击。
