### 1.1 bot 策略（专业判断①）
**严格优先级 + 等待**的通用混合防线（每 0.25s 决策一次，至多一次种植）：

1. **受威胁行优先补豌豆**（近端僵尸所在行、且该行无豌豆 → 在 `col1` 起首个空豌豆列种豌豆）；
2. 经济不足则补**向日葵**（`col0`，上限 4 株）；
3. 逐格铺**豌豆**（`col1..4`）；
4. 补**坚果**（`col6`，每行 1）；
5. 水行先铺**睡莲**再种主体。

**为什么代表「普通玩家」**：向日葵铺前排、豌豆做主力输出、坚果当前排阻挡 —— 正是通用新手/中级玩家的防线范式；且受真实约束（`canSelect`/扣费/`cardCD` 全局卡冷 5s、种植走 `selectCard→clickGrid` 真实路径）。

**关键工程决策（严格有序，非「首个可负担」）**：初版 bot 采用「按优先级找第一个能种的就种」，**全军覆没**——因为贪婪会不断被更便宜的单位「偷走」预算（睡莲 25、向日葵 50），豌豆（100）永远建不起来，实测 80 局全败、仅建 7~13 株。改为**严格优先级 + 买不起/冷却中就等**后，防线正常建成（见 §5 证据链）。这是本任务最大的口径实现要点。

### 1.2 阳光不锁的理由（专业判断②）
用户要的是「普通玩家眼中的难度」，而**普通玩家必须自己赚阳光**。更关键的是：世界 2 的核心难度特征正是**经济/地形维度**——逐关 `startSun` 差异（100/150/175）与**睡莲税**（每个水行种植位需先花 25 阳光铺睡莲、且多占一次卡冷）。若锁阳光（`test=1`）会把这两者**一并抹掉**，只剩「波次 vs 防线强度」。故本轮取**真实经济**。（对照证据：锁阳光下 bot 会瞬间铺满整张防线、80 局全胜、曲线恒平，无判别力——见 §6 备注。）

### 1.3 泳池关适配（专业判断③）
世界 2（`2-x`）`level.water=true`、`WATER_ROWS=[1,3]`（0-indexed）。bot 对水行的处理：**目标格若为水行且无睡莲 → 先种睡莲（`req='lilypad'`），睡莲在位后再种主体**。水行单位因此实际消耗「睡莲(25)+主体」两次种植 + 两次卡冷，被如实计入曲线（这正是睡莲税）。1-x 无此路径（`water=false`），零影响。

### 1.4 难度档（专业判断④）
用**默认档 `normal`**，全程未调用 `setDiff`。

### 1.5 指标定义
- **内容分（静态，客观）**：`zCount`=总出怪数；`threat`=Σ(出怪数 × 血量/180)（血量归一权重 normal=1 / cone=1.89 / fast=0.78 / bucket=3.11）。
- **通关率 winRate**：4 种子中通关局数 / 4。
- **耗时 gameT**：单局游戏内秒数（`gt`）；取 4 种子中位数。`每波耗时`=中位耗时/波数。
- **渗透 minZX**：全局限僵尸最小 `x`（越小=越靠近屋）。**median**=4 种子中位；**worst**=4 种子最深（含失守）。`x ≤ GRID_X(55)` 记「进入进屋带」（`updateZombies` 失败阈值 `x<15`）。
- **泄漏 leak**：进入危险区（`x ≤ 150`）的僵尸数（跨局合计）。
- **首败波次**：失守局首次进屋时的波号。

## 4 离群关判定与结论

### 4.1 阈值口径（专业判断⑤，可判定）
1. **过难（行为）**：`winRate ≤ 0.25`（≤1/4 种子存活）。
2. **偏难（行为）**：`0.25 < winRate ≤ 0.75`。
3. **失守（行为）**：存在局有僵尸抵达进屋带（`minZX ≤ GRID_X=55`）—— 全胜亦提示临界压力。
4. **过易（内容）**：`threat < 0.70 × 该世界线性期望` 且 `winRate = 1.0`。
5. **超载（内容）**：`threat > 1.40 × 线性期望`。

> **为什么是这些阈值**：行为阈值直接锚定「能否守住」（0.25=仅 1/4 存活即近不可过；0.75=临界）。内容阈值用**世界内线性递进基线**（首关威胁 → 末关威胁线性插值）度量「该关内容量是否匹配其位序」；±30%/±40% 是在「波次手写、逐关本应递增」这一设计前提下，能容忍设计性喘息波（如注释标注的「软喘息」）又足以抓出**成段塌陷**（1-3~1-5 的 0.35~0.51，远超噪声）的经验门限。

### 4.2 判定结果

| 类别 | 关卡 | 依据 |
|---|---|---|
| **过易（内容欠填）** | **1-3、1-4、1-5** | ramp = 0.51 / 0.41 / 0.35（远低于 0.70）；waves 数组与 `1-1` **逐字节相同** |
| 偏难 / 失守（行为） | 1-7、1-9、2-4 | 各 1/4 种子失守；首败波次 W4 / W2 / **W1** |
| 过难 | 无 | — |
| 内容超载 | 无 | — |
| 轻微回落（非离群） | 2-2（0.78）、2-6（0.81） | 与设计注释（2-2 平移、2-6 雾段首关）一致 |

### 4.3 结论（T-301 首轮记录 · 已被 T-301b 修订，最新见 §7）
- **1-3 / 1-4 / 1-5 = 模板占位关，是本轮唯一「明显离群」**。它们**不是手写数据**：`materializeLevels()` 对无显式 `waves` 的键用 `WAVE_TEMPLATES[1]`（= `1-1` 的 waves）深拷贝补齐，`_ANCHORS` 仅含 `1-1/1-2/1-6/2-1/4-1` 五个锚点。因此 1-3/1-4/1-5 的 waves 与 `1-1` 完全相同；又因**出怪串行门只对 `'1-1'/'1-2'` 生效**（`processSpawnQueue` 的 `levelKey` 门），这三关**没有那道教学减速门**，实测比 `1-1` 还快（150~156s vs 165.5s）—— 难度**低于**其位序应有的水平，更低于 1-2。
- **1-7 / 1-9 / 2-4 的失守发生在早期波次（W1~W4）**，机制是**开局经济/布防的随机性**（该种子前期阳光掉落稀疏或威胁行分布不利，防线未建成即被突破），**不是后期内容超载**（渗透中位仍为 225 = 防线正常）。故判定为**种子级方差**，不直接标记为「过难」，但建议定向加密复核（见 §6）。
- 结合内容分与实测：**20 关不存在对熟练基准防线构成系统性压垮的关卡**；发布前的内容质量风险集中在 1-3~1-5 的占位塌陷。

## 6 已知风险与后续建议

**A. 1-3 / 1-4 / 1-5（模板占位）——建议后续刀处理（本轮不改源码）**
- 现状：waves 与 `1-1` 完全相同、且无教学串行门，是**世界 1 曲线唯一塌陷**。
- 建议方向（择一）：
  1. **补写**这三关的手写 waves，使其内容分落在 `1-2`(4760) 与 `1-6`(7660) 之间并递增（例如 1-3≈5500 / 1-4≈6200 / 1-5≈6900 量级），保持「逐关递进」；
  2. 或**显式标注为占位**（选关页/文档），避免被当作已定稿内容发布。
- 注：这不是「过难」，而是**过易 + 内容缺口**；在 M3 定版前应明确取舍。

**B. 1-7 / 1-9 / 2-4（各 1/4 早期失守）——建议定向加密复核**
- 现象：单一子失守且均在早期波次（W4/W2/W1），渗透中位正常——判为**开局方差**。
- 建议：对这 3 关**定向加密到 8 种子**复核：
  - 若失守率收敛到 ~0 → 判为种子噪声，**无需改数值**；
  - 若失守率稳定 ≥1/8 → 属**开局节奏偏紧**（前 1~2 波布防窗口不足），可考虑给这 3 关**轻微抬高 `startSun` 或放软首波**（对齐 1-6 系列「前两波放软补偿」惯例）。
- 不要在拿到加密结果前擅自回调 waves（避免过拟合 4 种子）。
