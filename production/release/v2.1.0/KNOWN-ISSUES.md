## 方法论沉淀（本版新增）

1. **锚点缺键 = 静默内容缺口，须靠「逐关对比」暴露** —— `materializeLevels` 的让位原则（`_ANCHORS[k] || metaFor(k)`）对**缺键不报错**，且占位关仍可玩。**检测口径**：① 内容分/威胁值逐关对比（塌陷即缺键）；② 克隆组检测（多关 waves 数组逐字节相同 → 疑模板）；③ 关卡注册表字段契约（只保形状不保内容，需另加克隆断言）。本期 1-3~1-5 由 T-301 画像首次暴露。
2. **难度曲线画像须先校准 bot，再读曲线** —— 真实经济 bot 若用「首个可负担」贪婪策略，会被廉价单位（睡莲 25 / 向日葵 50）**偷走预算**，致豌豆（100）永远建不起来 → 80 局全败（假阴性）。**改用「严格优先级 + 等待」（头项买不起就等，不跳去种更便宜的）**后防线正常建成、曲线可用。**教训：读数异常先怀疑 bot 校准，再怀疑关卡难度**。
3. **真实经济 vs 锁阳光的取舍要写进口径** —— 锁阳光（`?test=1`）会瞬时铺满整张防线 → 曲线恒平无判别力；真实经济才反映睡莲税与逐关 `startSun` 差异。本轮取真实经济，并在报告中披露「熟练基准」局限。
4. **冻结副本三重校验 + git 对象导出** —— 必走 `git show <commit>:file` 重定向字节直通（**勿经工作区拷贝**，CRLF 污染历史踩过）；校验 = LF SHA-256 / 字节数 / 行数 / CR 计数 = 0 / `cmp` git 对象一致。
5. **spawnSync EBUSY 判定流程** —— 子进程启动恒 EBUSY 且复跑无效时，先切异步 spawn 验证（正常 ⇒ 会话级环境问题）；**不要反复重试同步调用**；门控直跑清单以 `run-gates.js` 源码内部列表为准逐门等效。
