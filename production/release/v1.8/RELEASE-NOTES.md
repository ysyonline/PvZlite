## 二、本版变更（相对 v1.7）

### 2.1 溅射同格锁（用户设计规则 · 本版唯一玩法级变更）

需求来源：**用户 2026-09-22 17:18 裁诀原话**——

> 「R8 砍，明确玉米和卷心菜只能溅射到同一格的怪，上下的和前后格的怪，无法溅射」

| 项 | v1.7（旧规则） | **v1.8（同格锁）** |
|---|---|---|
| cabbage / corn 溅射判定 | 同排 30px 带状（`\|z2.x−pr.x\| < 30`，可波及**同排相邻格**） | **落点同一格**（`colOf(z2.x) === colOf(pr.x)`，行隔离沿用） |
| 同格内溅射伤害 | 8（cabbage 20×0.40）/ 6（corn 15×0.40） | **不变**（8 / 6） |
| melon / icemelon | 同排 55px 跨格带，溅射 35.75 | **维持现状**（用户明示：西瓜/冰瓜照旧） |
| 溅射定身 | 不施加（仅黄油直中定身） | **不变** |

- **分级设计**：小投手（卷心菜/玉米）窄溅射 = 仅同格；大投手（西瓜/冰瓜）宽溅射 = 跨格 — 用户要求的「小 / 大两级」由本版正式确立为**设计规则**。
- **实现口径**：`fireArcProjectile` 透传 `splashGrid` 字段（**字段存在性语义**，与既有 `chill` / `butter` 同款）；`updateProjectiles` 溅射判定双分支——`splashGrid` 弹走 `colOf` 同格判定（`colOf = Math.floor((x − GRID_X) / CELL_W)`，锚点 = `pr.x` 结算当刻），字段缺失的老弹体走旧带状（向后兼容）。**禁欧氏距离**（`CELL_H=104` 使行间距远大于同排列距，与设计语义不符）。
- **源码增量**：18 行（`fireArcProjectile` 透传 1 行 + cabbage / corn 调用点各 1 行 + 判定双分支 + 注释），`updatePlant` 数值（cost/dmg/cd）、`fireArcProjectile` 弹道解算、`updateProjectiles` 直中链**零改动**。
- **命名纪律**：字段名用 `splashGrid`，**禁用 `sameCell`**（与既有「土豆雷」概念撞名）。判定为「同列（`colOf` 相等）且同排」，非欧氏距离。

## 三、测量结论（本版核心产出）

### 3.1 R7 · 同格锁下溅射堆叠分布

锚点假设「大范围稳定吃 1 副目标」在**字面语义下 REFUTE、堆叠条件语义下 CONFIRM**（口径显式落档）：

| 类型 | P(≥1)（无条件） | **P(≥1 \| 落点格堆叠 n≥2)** |
|---|---|---|
| cabbage | 0.5741（部分） | **1.0000（CONFIRM）** |
| corn | 0.5351（部分） | **1.0000（CONFIRM）** |
| melon | 0.8920（CONFIRM） | 0.9538（CONFIRM） |
| 混编 | 0.7033（部分） | 0.9876（CONFIRM） |

- **同格锁的几何推论**：落点格内**必溅**（无距离判定）⇒ 条件概率为 **100% 确定性**；无条件档偏低是因为分母含大量「弹着点落在簇外格、无同格受害者」的弹。
- **浪费率全类型「低（≤10%）」**（仅真实行程臂上报，溢杀率拆直中 / 溅射两栏）：cabbage 0.0% · corn 0.4% · melon 0.0% · 混编 0.0%。**画像预警**：同格锁下溅射受害者与直中主目标同批将死，溢杀口径**系统性低估战略浪费**——三档全低应读作「无返工级问题」，**不读作「溅射伤害都用在刀刃上」**。
- **判别力自证**（v1.7 旧源 `c379872` 同种子配对复跑）：cabbage 跨格溅射受害者 **22 → 0**、melon 分布**逐字节不变**（victims=371 / P(≥1)=0.8451）⇒ 读数差异归因于同格锁规则而非管线伪影。
- **附带设计洞察**：旧 30px 带对 +16px 紧堆叠簇**基本够不着**（弹着点在直中框前缘提前触发，副目标距离 ≈32px > 30px，旧源 n2 条件 P(≥1) 仅 **0.11**）；同格锁把「同格内必溅」变为确定性规则后，紧堆叠场景的溅射价值**从 0.11 升到 1.0**——同格锁对堆叠玩法**不是单纯削弱**。
- 完整报告：`production/v18-r7-report.md`；脚本与数据：`tests/playtests/v18-splash-distribution.{js,json}`（固定种子逐字节可复现）。

### 3.2 R9-b · 平衡投影公式标定（两域分界）

| 候选式 | 全域 maxAbs 残差 | χ²(df=4) / R² | 判定 |
|---|---|---|---|
| **F-A** 泊松 `1−(1−p)^(nT/cd)` | **3.0pp**（T>cd 域系统性高估 +2.6~3.0pp） | 17.5 / 0.973 | ✗ 未通过 |
| **F-B** 连续更新回报 `npT/(cd+npT)` | **15.1pp**（全域大幅低估） | 276.8 / 0.602 | ✗ **淘汰，禁入任何投影场景** |
| **F-C** M6 式 `1−exp(−n·p·T/cd)` | **4.1pp**（系统性低估） | 21.3 / 0.969 | ✗ 未通过 |
| **GRID** 网格修正式（参考，不作判定） | 2.1pp（仅 A2 微超 0.1pp） | **8.05 / 0.9875** | （建议采纳，见下） |

- **标定判定维持「无一候选式通过」**（判据：全锚点 |残差| ≤ ±2pp，**禁凑数放宽**）。
- **两域分界 = 硬边界**：`T ≤ cd`（v1.6 域）刷新事件**数学上不可能** ⇒ 线性式 `n·p·T/cd` 解析精确（A1 全 48 种子 refresh=0）；`T > cd`（v1.7+ 域）刷新必然发生 ⇒ 一切「窗口×概率」式系统性高估。根因教训：**代数投影携带参数域前提，前提崩塌时口径静默失效**（v1.6→v1.7 调参翻车直接死因）。
- **修正公式建议（分段式，超差如实标注，悬置待用户拍板）**：T>cd 域推荐机制驱动的 **GRID 网格修正式**（零拟合参数、χ²/R² 全表最优、maxAbs 2.1pp）；心算可用 `F-A − 3pp` 保守修正。GRID 与源码机制一一对应（黄油掷定在确定性 cd 网格上，非泊松过程），T≤cd 时**严格退化为线性式**（一式覆盖两域）。
- **终判纪律**：复测 SEM ≈ 1.2–1.4pp + 口径效应 ±1~2pp 与公式残差同量级 ⇒ **公式只作设计初筛，终判必须跑复测脚本**（`v18-r9b-calibration.js` 同款 48 种子）。
- 完整报告：`design/butter-balance-calibration-v18.md`；数据：`tests/playtests/v18-r9b-calibration-results.json`。

> ⚠️ **悬置决策（不阻塞发布）**：GRID 投影式是否采纳进正式口径（v1.8-decisions 未涵盖此项）。技术侧建议**采纳**（全表最优 + 零拟合参数 + 两域退化自洽），待用户在后续版本拍板。
