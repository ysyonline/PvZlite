## §1 配置表结构设计（示意）

> 全部收进**一个配置表族**（`POINT_CONFIG` 管积分、`SLOT_CONFIG` 管卡槽）。逻辑只读配置，未来新增地图/积分渠道 → 只往表里加数据，不动逻辑。
> `DIFF_MULT` 不重复定义，直接引用既有 `DIFFS[DIFF].mult`（L52–54）。

```js
// ============ v1.4 配置表（仅示意，落点：基础配置区 L35 之后） ============
const POINT_CONFIG = {
  // ① 阶位定义（铜/银/金三阶，掉落物与 HUD 共用）
  TIER: {
    bronze: { value: 1, color: '#b87333', label: '铜' },
    silver: { value: 2, color: '#c0c0c0', label: '银' },
    gold:   { value: 3, color: '#ffd54a', label: '金' },
  },
  // ② 怪 → 阶 映射（普通=铜 / 快速=银 / 路障=银 / 铁桶=金）
  ZOMBIE_TIER_MAP: {
    normal: 'bronze',
    fast:   'silver',
    cone:   'silver',
    bucket: 'gold',
  },
  // ③ 难度系数：逻辑只读 DIFFS[DIFF].mult（此处不存，避免两处真相）
  //    DIFFS = { normal:{mult:1.0}, hard:{mult:1.35}, expert:{mult:1.80} }  // 既有 L51–55
  // ④ 掉落物坐标随机偏移半径（px，防同点重叠）
  DROP_OFFSET: 12,
  // ⑤ 通关积分奖励（★双读法可切，等用户定案零改动切换）
  CLEAR_REWARD: {
    mode: 'per10',     // 'per10' = 读法①（每累计通关 10 关发一次固定奖）
                      // 'flat'  = 读法②（每关都发固定值）
    per10Amount: 300,  // 读法①：满 10 关发一次的固定奖励
    flatAmount: 30,    // 读法②：每关固定发放
  },
};

const SLOT_CONFIG = {
  initialSlots: 6,                                  // 初始 6 槽
  maxSlots: 10,                                     // 最大 10 槽
  initialPool: ['sunflower','nut','pea','mine'],    // 初始卡池 4 张
  // 第 7–10 槽单价（合计 6400）；key = 目标槽序号
  SLOT_PRICE: { 7: 600, 8: 1200, 9: 1900, 10: 2700 },
  CARD_W: 88,                                       // 卡栏卡片宽度（v1.4：98 → 88）
  // 通关发卡序列：key = 已通关的关卡号 → 发放卡 type（载具卡严格先于对应关）
  CARD_AWARD: { 1: 'double', 2: 'cabbage', 3: 'lilypad', 4: 'planter', 5: 'melon' },
};
```

**双读法切换契约**：`computeClearReward()`（T-08）只读 `CLEAR_REWARD.mode`——
- 用户拍板读法①：`mode:'per10'`，发奖条件 `clears>0 && clears%10===0`；
- 用户拍板读法②：仅改 `mode:'flat'`，每关 `return flatAmount`。
两种读法**改配置即可切换，逻辑零改动**。

## §2 逐任务详情

### T-01　配置表落地（POINT_CONFIG + SLOT_CONFIG）
- **目标**：在基础配置区（L35 之后、CARDS 之前或之后）新增两个配置常量，承接全部「硬编码禁令」项（阶位、怪→阶、难度系数引用、槽价、发卡序列、通关奖励规则）。
- **新增/修改**：新增 `const POINT_CONFIG = {...}`、`const SLOT_CONFIG = {...}`（结构见 §1）。无函数新增；后续任务逻辑一律 `POINT_CONFIG.X` / `SLOT_CONFIG.X` 取值。
- **验收标准**：两个对象存在且字段齐全；用 `node -e` 或 harness 探针断言 `POINT_CONFIG.TIER.gold.value===3`、`SLOT_CONFIG.SLOT_PRICE[10]===2700`、`SLOT_CONFIG.CARD_AWARD[5]==='melon'`。
- **门控影响**：无新增用例（纯数据）；但**所有后续任务门控都依赖此表存在**，属地基任务。

### T-02　新存档键读写 + 存量迁移
- **目标**：新增 4 存档键 `pvz_points`/`pvz_slots`/`pvz_cards`/`pvz_deck`（另加跨轮计数 `pvz_clears` 支撑读法①），并通过 `storageGet/Set`（L172–177）读写；存量用户按 `pvz_unlocked`（L153）推导卡池初始化。
- **涉及源码行号**：L172–177、L193–196（状态声明）。
- **新增函数签名**：
  - `function loadMeta()` —— 读 5 键；缺省时按 `SLOT_CONFIG.initialSlots/initialPool` 推导 `slots`/`ownedCards`，`deck` 取卡池前 `min(slots, 4)`（4/6 即合法默认）；`points`/`clears` 默认 0。
  - `function saveMeta()` —— 写 5 键（复用 `storageSet`，静默降级不变）。
  - 新增状态变量：`let points=0, slots=SLOT_CONFIG.initialSlots, ownedCards=[], deck=[], clears=0;`（并入 L194 状态声明行，避免并行 Edit 冲突）。
- **验收标准**：无存档首启 → `slots===6`、`ownedCards` 含 4 张初始卡、`deck.length===4`；二次 `loadMeta` 回读一致；`pvz_unlocked` 存在但无新键时迁移不报错；`localStorage` 受限（无头桩）不抛。
- **门控影响**：复用 SMOKE-020 存档范式新增 `REG-META-01`（首启迁移）/`REG-META-02`（写入→重载→回读全路径）。回归 +2，总线不变。

### T-03　runPoints 局内计数 + startGame 重置
- **目标**：新增局内积分计数 `runPoints`，随对局开始清零。
- **涉及源码行号**：L194（加 `let runPoints=0;`）、L888（`runPoints=0;` 并入 startGame 重置串）。
- **新增函数签名**：可选 `function addRunPoints(v){ runPoints+=v; }`（逻辑简单，可内联）。
- **验收标准**：`startGame()` 后 `runPoints===0`；点击收集掉落物后 `runPoints` 增对应 tier 值（T-05 联验）。
- **门控影响**：无独立用例（由 T-04/T-05/T-13 覆盖）；注意 `startGame` L888 重置串被 T-06 也改，须协定同一行顺序。

### T-04　击杀掉落生成（tier/坐标偏移/绕守卫）+ 掉落物视觉
- **目标**：僵尸死亡时按 `ZOMBIE_TIER_MAP` 生成对应阶掉落物，坐标 `±12px` 随机偏移防重叠；**掉落物不受 effects 500 上限守卫丢弃**；三色视觉（铜银金）。
- **涉及源码行号**：killZombie L1277–1284（L1279 加分后挂靠）、5 处 effects 守卫 L1047/1138/1143/1251/1264（**绕开**）、渲染区 L1382+。
- **设计决策（绕守卫）**：掉落物**独立数组 `let pointDrops=[]`**（不进 `effects`），从根上不触发任一 500 守卫，生命周期独立（无尸体清理耦合）。备选方案是 push 进 `effects` 但选非守卫代码路径——本任务采用独立数组（最稳）。
- **新增函数签名**：
  - `function spawnPointDrop(x,y,tier)` —— 取 `POINT_CONFIG.TIER[tier]`，`x+=R(-DROP_OFFSET,DROP_OFFSET)` 同法 y，推入 `pointDrops`：`{x,y,value,color,life,t}`，无数量守卫。
  - `function resolveTier(zType){ return POINT_CONFIG.ZOMBIE_TIER_MAP[zType]; }`（可内联）。
  - `function drawPointDrops()` —— 按 `color` 画铜/银/金圆点（落入渲染 L1382+ 的 effects 绘制之后）。
- **hook**：killZombie L1279 后加 `const t=resolveTier(z.type); if(t) spawnPointDrop(z.x, y, t);`（y 取 L1280 同式）。
- **验收标准**：击杀 4 类型僵尸各生成正确 tier（value 1/2/2/3）；`pointDrops` 在 `effects.length>500` 时仍正常生成（故意灌爆 effects 后击杀验证）；坐标偏移在 ±12 内；三色渲染不抛。
- **门控影响**：新增 `REG-POINT-01`（tier 映射正确）+ 守卫绕开断言（灌爆 effects）。回归 +1，总线不变。

### T-05　点击收集（阳光优先分支）
- **目标**：点击收集时**阳光优先于积分**（同点重叠先收阳光），再收积分掉落物。
- **涉及源码行号**：onClick 阳光循环 L745–754（其后追加 pointDrops 收集）。
- **新增函数签名**：内联即可；收集逻辑 `for(let i=pointDrops.length-1;i>=0;i--){ const d=pointDrops[i]; if(dx²+dy²<R²){ runPoints+=d.value; d.dead=true; SFX.coin?; } }`（半径建议 30px，同阳光手感）。
- **验收标准**：同点同时有阳光与掉落物时，点击先收阳光（sun 增、return）；无阳光时收掉落物（runPoints 增）；二者不冲突。
- **门控影响**：新增 `REG-POINT-02`（阳光优先 + 独立收集）。回归 +1。

### T-06　结算逻辑：胜利 sweep + 失败部分结算
- **目标**：胜利→sweep 场上未捡掉落物 + 计入通关奖励，全收；失败→只结算已点击收集部分（不清零总积分）。
- **涉及源码行号**：checkWave 通关判定 L1342–1348（胜利分支）、僵尸进屋失败分支（`updateZombies` 内 `z.x<GRID_X-40` → setState('end') 处，won=false）。
- **新增函数签名**：
  - `function settleRun(won)` —— 胜利：`for(d of pointDrops) runPoints+=d.value; pointDrops=[];` 失败：不 sweep（只已收集）。调用 `computeClearReward()`（T-08）与乘算（T-07）得 `total`，`points+=total; saveMeta();` 后 `runPoints=0;`。
- **hook**：L1342 块内先 `won=true; settleRun(true);` 再 `setState('end','通关')`；失败分支 `setState('end',...)` 前 `settleRun(false)`。
- **验收标准**：胜利时场上未捡掉落物计入 + 奖励计入（REG-POINT-04）；失败时 `points` 仅增已收集部分、不清零（REG-POINT-05）；`points` 持久化。
- **门控影响**：新增 `REG-POINT-04`（胜利全收 sweep+奖励）、`REG-POINT-05`（失败部分结算）。回归 +2。

### T-07　难度乘算（局合计取整口径）
- **目标**：单局积分 = (击杀合计 + 通关奖励) × `DIFFS[DIFF].mult`，**局合计取整，不做 per-drop 取整**。
- **涉及源码行号**：结算内部（随 T-06 `settleRun` 同函数，约 2–4 行）。
- **新增函数签名**：内联于 `settleRun`：`const raw = runPoints + clearReward; const total = Math.round(raw * DIFFS[DIFF].mult);`
- **验收标准**：`normal` 乘 1.0、`hard` 1.35、`expert` 1.80；取整在合计后（非每 drop）；与 T-06 同次提交。
- **门控影响**：新增 `REG-POINT-03`（三种难度乘算 + 取整位置）。回归 +1。

### T-08　通关奖励结算（配置驱动双读法）
- **目标**：按 `CLEAR_REWARD.mode` 结算通关奖励，两种读法可切。
- **涉及源码行号**：结算内部 + 配置 §1。
- **新增函数签名**：
  - `function computeClearReward()` —— `const c=POINT_CONFIG.CLEAR_REWARD; if(c.mode==='per10') return (clears>0 && clears%10===0)? c.per10Amount:0; if(c.mode==='flat') return c.flatAmount; return 0;`
  - 另：`clears` 自增放在胜利结算（`settleRun(true)` 内 `clears++` 后 `saveMeta`）。
- **验收标准**：`mode:'per10'` 时仅 `clears%10===0` 发 `per10Amount`；`mode:'flat'` 每关发 `flatAmount`；**仅改配置 `mode` 即可切换，逻辑零改动**（REG-CLEAR-01 同时断言两读法由 `mode` 切换）。
- **门控影响**：新增 `REG-CLEAR-01`（双读法切换，配置驱动）。回归 +1。

### T-09　卡池/卡组状态 + 默认卡组（可不选满）
- **目标**：确立 `ownedCards`（卡池）/ `deck`（已选卡组，长度 ≤ slots）状态；**卡组可不选满开局（4/6 合法）**——解除「恰好选满」约束。
- **涉及源码行号**：状态 L193–196（并入 T-02 变量）、迁移（T-02 `loadMeta`）。
- **新增函数签名**：
  - `function defaultDeck(){ return ownedCards.slice(0, Math.min(slots, SLOT_CONFIG.initialPool.length)); }`（4 张即默认合法）。
  - `function inDeck(type){ return deck.includes(type); }`（选卡界面用）。
- **验收标准**：默认 `deck.length===4` 且 `deck.length<=slots`；`deck` 未选满时仍可 `startGame`（T-10 联验）；`deck` 越界（>slots）被钳制。
- **门控影响**：新增 `REG-SLOT-01`（初始 6 槽 + 卡组不必选满即合法）。回归 +1。

### T-10　选卡界面（新 state，允许不满开局）

  - `function onClickDeck(x,y)` —— 点卡 toggle 入/出 `deck`（受 slots 上限）；点开始 → `startGame`。
- **验收标准**：state `'deck'` 进界面不抛；勾选 ≤slots 生效；**deck=4（<6）时开始按钮可用且能进 play**（REG-SLOT-04）；超出 slots 拒绝。

### T-12　通关发卡
