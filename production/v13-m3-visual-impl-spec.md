## 0. 结论速览（TL;DR）

1. **方案成立**：美术侧 4 手段在 Canvas 2D 现有原语下**全部可实现、零新增外部依赖**；本轮工程复核**确认可行性**，同时**新发现 2 个落地风险**（见 §0.3），需用户知悉。
2. **工作量**：核心施工（手段①②③④a + 1 常量）**净增 ≈ +35 行**；含可选项（④b 檐口剪影 / 檐沟改色）**净增 ≈ +49 行**；加注释与留白，落地 **≈ 45–65 行**（美术侧估 50–90，工程实测估偏低，见 §附录 A）。
3. **两个定夺**（§5）：
   - 斜缝实现 → **手动端点剪切**（非 `ctx.transform`）：性能等同、可读性/可调试性更优、与现有「不启用 transform 组合」工程惯例一致。
   - 白云 → **静态默认**（缓漂为单常量 opt-in）。
4. **测试影响**：**零既有用例会被破坏**（harness ctx 为吞调用 Proxy 桩，**无任何绘制断言**；改动全部落在 `if(level.roof)` 分支内，L1–L4 渲染路径零触碰）。门控基线（烟雾 27 · 回归 60 · 总线 56）**预期全绿不变**。
5. **bench 影响**：仅场景 E（L5）新增 **≈ +26 draw calls/帧（+1.2%）**，p50/p95 增量 **< +0.03ms**，判级 PASS 不变。
6. **回退**：改动**全部隔离**在 1 个新插入块 + roof 分支 + 1 常量，**一键回退 = 还原 3 处 diff**（§9），零连带。
7. **建议分批**：**先①②（天空+城垛）单独真机验收**，再③④a（斜缝+光渐变）。理由见 §10。

## 2. 施工总原则

### 2.1 三条红线

1. **gridToPos 平面假设不动**：格填充仍是轴对齐 `fillRect`；倾斜只作用于**装饰层**（天空/城垛/斜缝/檐口/光渐变）。 **〔⚠️ 已推翻（V13-M4-ENG-01/02，2026-09-19）：C2 拍板 ⇒ `gridToPos/posToGrid` 改为 x 相关斜切映射，格填充改平行四边形。见文件顶部勘误 + `docs/architecture/ADR-005-roof-5col-continuous-slope.md`。红线②③ 仍有效。/ 程基岩〕**
2. **隔离在 `if(level.roof)` 之内**：所有新绘制必须被 `level.roof` 圈住（天空块用 `if(level.roof)` 前置）。**L1–L4 渲染路径零触碰** ⇒ 老回归天然免疫。
3. **不遮挡实体与 UI**：屋顶皮肤绘制早于植物/僵尸（L1480+）与 HUD（`drawStatus`）⇒ 天然被覆盖，**不需额外 z 排序**；城垛 y∈[68,80] 与 HUD y∈[4,48] 不重叠、与 row0 植物顶部（≈y≥90）不重叠。

### 2.2 编排方式

- 全部改动落在 **3 个位置**：① `drawGameWorld` **顶部新插一段**（天空块）；② **roof 分支**（L1400–1428）内部重排；③ **基础配置常量区**加 1 常量。**无一处需要新增/改动顶层函数签名**（`drawCloud` 若需则内联，避免 code-map 表面积扩大）。

- **改法（伪代码）**：

```js
if(level.roof){
  // —— 天空带（覆盖顶部裸露 CSS 绿底 #7fbf4a；名义 0–90，实际可见 0–80）——
  const SKY_H=90;
```

### 手段 ③ 斜向砖缝（★核心）

- **落点**：**改写** L1408–L1420（现有竖缝循环）。
- **层级**：roof 分支内、横缝（L1401–07）之后，对角光渐变之前。
- **改法（伪代码）**：

```js
// 斜向砖缝（核心：端点水平剪切 → 平行四边形砖；全局一致斜率、跨行连续对齐）
ctx.save();
ctx.beginPath();ctx.rect(GRID_X,GRID_Y,COLS*CELL_W,ROWS*CELL_H);ctx.clip();  // 裁到屋面，防斜缝外溢
ctx.strokeStyle='rgba(0,0,0,0.10)';
for(let r=0;r<ROWS;r++){
  const off=(r%2)*(CELL_W/2);                       // 保留奇数行半砖错缝
  const yT=GRID_Y+r*CELL_H, yB=GRID_Y+(r+1)*CELL_H;
  for(let c=0;c<COLS;c++){
    const xNom=GRID_X+c*CELL_W+off;                 // 名义(未剪切)竖缝 x
    if(xNom>=GRID_X+COLS*CELL_W)break;
    const xT=xNom-ROOF_SLOPE*(yT-GRID_Y);           // 上端点
    const xB=xNom-ROOF_SLOPE*(yB-GRID_Y);           // 下端点（比上端点更左 → "右倾"）
    ctx.beginPath();
    ctx.moveTo(xT,yT);
    ctx.lineTo(xB,yB);
    ctx.stroke();
  }
}
ctx.restore();
```

- **数学口径（关键，供复核）**：全局剪切 `x(y) = xNom − ROOF_SLOPE·(y − GRID_Y)`。
  - `ROOF_SLOPE>0` ⇒ y 越小（越靠上）x 越大 ⇒ **上端点偏右 = "右倾"（形如 `/`）**，与用户拍板方向一致。
  - 单行内端点水平错位 = `ROOF_SLOPE·CELL_H ≈ 15.6px`；整个网格底行相对顶行累计错位 = `ROOF_SLOPE·ROWS·CELL_H ≈ 78px`（≈ 8.5° 剪角）——**这正是"读成斜面"的来源**。
  - **横缝不动**：x 向剪切不改变 y，故水平砖缝（L1401–07）保持水平 ⇒ 砖块成为「上下水平、左右倾斜」的**平行四边形**（符合美术口径）。
  - **符号即方向**：`ROOF_SLOPE` 取负号即镜像为「左倾」。**最终符号须对已通过的 v2 效果图肉眼校对**（我无法读图，见 §11 待确认）。
- **clip 的必要性**：78px 剪切会让边缘缝外溢。若不加 clip，外溢部分仅在 x<55（房子区）/x>865（道路区）——而这两处**恰在其后被 L1455/L1447 覆盖**，故**不加 clip 也能被前景盖住**。**仍建议加 clip**：语义明确、且不受未来绘制顺序调整影响；成本仅 1 组 `save/rect/clip/restore`。
- **预计增删行**：**+18 / −13**（净 +5，含 clip 包装）。

### 手段 ④a 对角光渐变（受光统一）

- **落点**：roof 分支内，③ 之后、② 城垛之前。
- **改法（伪代码）**：

```js
// 方向光渐变（远/上亮 → 近/下暗，强化"面朝上受光"）
const lg=ctx.createLinearGradient(GRID_X,GRID_Y,GRID_X+COLS*CELL_W,GRID_Y+ROWS*CELL_H);
lg.addColorStop(0,'rgba(255,240,210,0.10)');
```

- **层级理由**：置于砖缝**之上**（薄 tint 统一砖面+缝的明暗），置于檐口/城垛**之下**（城垛须保持纯剪影、不被压暗）。
- **预计增删行**：**+7 / −0**。 **性能**：1 gradient + 1 fillRect。

## 5. 遗留项定夺

### 5.1 斜缝实现：手动端点剪切 vs `ctx.transform(1,0,slope,1,0,0)`

| 维度 | 手动端点剪切（**选定**） | `ctx.transform` 整体斜切 |
|---|---|---|
| 行数 | +18/−13（净 +5，含 clip） | 少 2–3 行（省去每缝两端点算术） |
| 性能 | 每缝 2 次乘加（≈90 缝 → 180 次算术/帧，**μs 级、可忽略**） | 1 次矩阵装配/帧 |
| 桩影响 | 无（纯算术） | **无**（harness/bench Proxy 对未知键返回 no-op，`ctx.transform(...)` 安全吞掉） |
| 可读性/调试 | **就地、自洽、无隐式状态** | 需推理 CTM 与既有 shake-`translate` 的嵌套组合 |
| 描边畸变 | 无 | 剪切矩阵会让斜线**描边宽度轻微非均匀**（0.10 alpha/2px 下不可见，但存在） |
| 工程惯例 | 与「perf-profile §5.7：不启用 transform 组合」一致；现有代码即内联坐标算术 | 与既有惯例相悖 |

**定夺：手动端点剪切。** 性能同等、可读性与一致性更优，且规避 CTM 隐式状态与描边畸变。`ctx.transform` 作为"若行数成为硬约束"的**备案**（注释保留一句即可）。

> 说明：`perf-profile §5.7` 禁用的是 `setTransform` 组合（**绕过栈**），而 `ctx.transform` 是栈安全的矩阵后乘；即便如此，本项目一贯偏好"显式坐标"，故仍选手动。

### 5.2 白云：静态 vs 缓漂

| 维度 | 静态（**选定**） | 缓漂 |
|---|---|---|
| 一致性 | 与 v2 静态扁平风一致 | 引入运动，可能"抢戏" |
| 复杂度/风险 | 零 `gt` 耦合、零动画状态、可预测 | 需读 `gt`（暂停自动冻结，语义正确），多 1 组 x 偏移算术 |
| bench | 最低 | 略高（3 次 x 计算/云/帧，仍可忽略） |
| 可逆 | — | 单常量 opt-in（加 `CLOUD_DRIFT`，`x=(base+gt*spd)%(W+80)−40`） |

**定夺：静态默认。** 理由见上；保留「缓漂」为单常量升级项（若用户要"活气"，一行加法落地）。

## 6. 天空带规格（口径澄清 · 必读）

用户拍板「天空 ≈13%（0–90px）」＋「不侵占网格」。二者存在 **10px 张力**，工程侧口径如下（**默认按此落地，列 §11 待确认**）：

| 项 | 值 | 说明 |
|---|---|---|
| **名义天空带** | `SKY_H = 90`（y∈[0,90]，= 680 的 **13.2%**） | gradient 定义域、`fillRect` 高度 |
| **可见纯天空** | y∈[0,**80**]（80px，11.8%） | 棋盘自 `GRID_Y=80` 起，`fillRect` 覆盖 y∈[80,90] |
| **"天际线带"读感** | y∈[0,80]（含城垛剪影 68–80） | 屋脊城垛在此带内，视觉上补足"天空-屋脊"层高 |

- **覆盖 CSS 绿底的方式**：天空 `fillRect(0,0,canvas.width,90)` **全宽覆盖**顶部（含左房子上方 x0–55、右道路上方 x865–955 的裸露绿底），一次画满。
- **为什么可见上限只有 80px**：网格从 `y=80` 起（`GRID_Y`），任何"可见天空 = 90px"都要求把 `GRID_Y` 下移 10px → **动布局常量 = 动 `gridToPos` 语义 = 破红线**，**否决**。故名义 90、可见 80。 **〔⚠️ 勘误（2026-09-19）：C2 仍**不动布局常量**（此句的「否决」**依然成立**）；但「`gridToPos` 语义 = 红线」的前提已被 C2 推翻——C2 是**在 roof-gate 内新增 `liftX`**（不动 `GRID_Y`）。故本条结论（名义 90 / 可见 80）不变，仅措辞口径更新。/ 程基岩〕**
- **若要更多天空**：只能把「屋脊+城垛」**下压进网格顶部若干像素**（城垛盖住 row0 顶缘，纯视觉可，零逻辑影响）——**本轮不做**，留作用户可选升级项（§11）。
- **左/右上方也一并覆盖**：天空全宽，故房子/道路上方不再露绿。

### 7.2 对基线的波及核对（结论：**零破坏**）

1. **harness ctx 是吞调用 Proxy 桩**（`tests/harness/index.js` L274–285）：任意未知键返回 no-op 函数；`createLinearGradient/createRadialGradient` 返回带 `addColorStop` 的哑对象；`measureText→{width:0}`、`getLineDash→[]`。**无任何断言读取绘制产物**（无像素/截图/draw-call 断言）⇒ **绘制层改动从原理上不可能使既有用例 FAIL**，除非**抛异常**。
2. **抛异常是唯一失败模式**，而 L5 真帧渲染**确有覆盖**：`SMOKE-027` 末尾（L50–59）用 `__stepFrame` 在 **L5** 跑真 loop 帧（update+render 全链路）+ `console.error` 监视网。**故本规格的绘制代码必须"桩下不抛"**：
   - 只用 Proxy 桩已支持的调用：`createLinearGradient / fillRect / ellipse / beginPath / rect / clip / save / restore / moveTo / lineTo / stroke / fill`（**逐条已核验**，§1.3 可行性质检）。
   - **禁止**读取 `ctx.canvas.width`（桩里 `ctx.canvas` 返回**函数**而非对象 ⇒ `.width` 为 `undefined`）；天空宽度一律用 DOM 变量 `canvas.width`（现状既有写法）。
   - `ctx.transform` 若采用（本规格未采用）也是 no-op ⇒ 安全。
3. **L1–L4 用例不受影响**：新绘制全部在 `if(level.roof)` 内；L1–L4 的 `SMOKE-024/025`（L3/L4 真帧）、`REG-END-02`（结算帧）、`SMOKE-010/021`（暂停/菜单帧）**不进 roof 分支** ⇒ 渲染输出路径与今日一致。
4. **静态断言类用例（SMOKE-011/013/022/023/024/025/027 等）**：不涉绘制，完全无感。

**一句话**：**预期 27/60/56 全绿不变**，唯一新增义务是"L5 真帧不抛"（SMOKE-027 已为守门）。

### 7.3 是否新增视觉/绘制用例（**只列规格，不实现**）

- **不推荐**新增"像素/绘制"自动化用例：harness 无栅格化能力，任何基于 ctx 调用计数的断言都会**锁死实现细节**（例如"必须调用 N 次 createLinearGradient"），与"轻视觉、可调参"定位冲突，且改动 `ROOF_SLOPE`/云数即误报。 **〔⚠️ 措辞过时（V13-M4-ENG-01/02，2026-09-19）：C2 拍板后本关**不再**走「轻视觉（仅装饰层）」定位——已改「几何连续坡面」（破 `gridToPos` 平面假设）。本条**结论仍成立**（不推荐像素/绘制类自动化用例），但「轻视觉定位」这一限定词已废弃；锁死实现细节/误报的理由不变。/ 程基岩〕**
